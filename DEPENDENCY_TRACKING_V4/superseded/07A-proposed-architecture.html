07A: Proposed Architecture (Revised)

Supersedes 07. Incorporates Luca's feedback, Adam's big-bang decision, composable primitives deep dive, and concrete chart analysis.

Design Principles

1. Don't encode defaults, encode decisions. Primitives and capabilities encode operational knowledge. Charts express intent, not K8s boilerplate.
2. Registries are the API; pipes are the syntax. Cross-cutting concerns use capability registries (NixOS-style option merging). Pipes (|>) are ergonomic sugar that desugar into registry declarations.
3. config.manifests is terminal. No module reads from it. All cross-module communication flows through typed options (capabilities, registry, exports).
4. Capabilities have levels. Monitoring, network policy, TLS = cluster-level (capability interfaces). Autoscaling, PDB, sidecars = application-level (resource group combinators).
5. Zero coupling between charts and implementations. Charts declare abstract intent. Implementations decide how to act. Swap Prometheus for Datadog: zero chart changes.

Capability Interface Design

Monitoring (cluster-level capability)

# modules/capabilities/monitoring.nix
options.monitoring = {
  enabled = lib.mkOption { type = types.bool; default = false; };
  provider = lib.mkOption { type = types.enum [ "prometheus" "datadog" "none" ]; };
  defaultInterval = lib.mkOption { type = types.str; default = "30s"; };
};

options.capabilities.monitoring = lib.mkOption {
  type = types.attrsOf (types.submodule {
    options = {
      # Input (charts write):
      port = lib.mkOption { type = types.int; };
      path = lib.mkOption { type = types.str; default = "/metrics"; };
      namespace = lib.mkOption { type = types.str; };
      serviceName = lib.mkOption { type = types.str; };

      # Output (implementation writes back):
      labels = lib.mkOption { type = types.attrsOf types.str; default = {}; };
      annotations = lib.mkOption { type = types.attrsOf types.str; default = {}; };
    };
  });
};

Prometheus — "find metric endpoints, not find coredns"

# modules/implementations/monitoring-prometheus.nix
config = lib.mkIf (cfg.enabled && cfg.provider == "prometheus") {
  # Write BACK: generic discovery label for ALL monitored services
  capabilities.monitoring = lib.mapAttrs (_: _target: {
    labels."kix.monitoring/scrape" = "true";
    annotations = {
      "kix.monitoring/port" = toString _target.port;
      "kix.monitoring/path" = _target.path;
    };
  }) targets;

  # Create ServiceMonitors matching the generic label
  manifests = lib.mapAttrs' (name: target:
    lib.nameValuePair "monitoring-${name}-servicemonitor"
      (mkServiceMonitor { selector.matchLabels."kix.monitoring/scrape" = "true"; })
  ) targets;
};

Datadog drop-in — zero chart changes

# modules/implementations/monitoring-datadog.nix
config = lib.mkIf (cfg.enabled && cfg.provider == "datadog") {
  capabilities.monitoring = lib.mapAttrs (_name: target: {
    labels = {};  # Datadog doesn't use label selectors
    annotations = {
      "ad.datadoghq.com/check_names" = builtins.toJSON [ "openmetrics" ];
      "ad.datadoghq.com/instances" = builtins.toJSON [{
        prometheus_url = "http://%%host%%:${toString target.port}${target.path}";
      }];
    };
  }) targets;
  # No CRDs needed — Datadog Agent discovers via pod annotations
};

Resource Group Combinators

Combinators operate on resource groups and return modified groups. They accumulate capability declarations in _extraConfig — this is how pipes desugar to registry declarations.

Usage — Luca's vision realized

# In pkgs/coredns/resources.nix
workloadGroup =
  { inherit deployment; }
  |> kixlib.combinators.mkGroup
  |> kixlib.combinators.withRole {
       rules = [
         { apiGroups = [""]; resources = ["endpoints" "services" "pods"];
           verbs = ["list" "watch"]; }
       ];
     }
  |> kixlib.combinators.optionalPipe cfg.hpa.enabled
       (kixlib.combinators.withAutoscaler "coredns" {
         inherit (cfg.hpa) minReplicas maxReplicas;
       })
  |> kixlib.combinators.optionalPipe pdbEnabled
       (kixlib.combinators.withPDB {
         inherit (cfg.podDisruptionBudget) minAvailable;
       });

Practical Limits of Composable Primitives

Analysis of the three existing charts shows that only 20–30% of chart code is standard deployment boilerplate:

ChartStandard PatternRBACApp-SpecificCross-Cutting
CoreDNS (423 lines)13%5%59%12%
Valkey (894 lines)18%0%65%7%
cert-manager (593 lines)30%34%20%8%

The value isn't in reducing line count — it's in:

  • Zero coupling between charts and cross-cutting implementations
  • Composability via pipes for the parts that ARE standard
  • Introspection via capability registries (kix status, kix graph)
  • Swappability of implementations (Prometheus → Datadog, HPA → KEDA)

Big-Bang Migration Plan

Adam chose big bang. All changes happen together in one coordinated effort.

0 Snapshot baseline — Build all 17 variants + 3 clusters, save YAML output. Ground truth for verifying non-monitoring resources are byte-identical after migration.
1 Create capability interfaces — modules/capabilities/monitoring.nix (abstract interface with input/output fields) + modules/capabilities/autoscaling.nix
2 Create implementation modules — modules/implementations/monitoring-prometheus.nix (logic from current monitoring.nix + generic label writeback) + autoscaling-hpa.nix
3 Update infrastructure — modules/default.nix new imports. Delete modules/monitoring.nix.
4 Update all charts — monitoring.targets.* → capabilities.monitoring.* in coredns, valkey, cert-manager. Merge capability labels into metrics Services.
5 Add combinators to kixlib — mkGroup, withAutoscaler, withPDB, withRole, optionalPipe, groupToManifestList
6 Update cluster configs — monitoring.* → cluster-level monitoring config in clusters/example.nix
7 Update tests — Rewrite all monitoring assertions in flake.nix to use capabilities.monitoring.*. Add capability writeback assertions.
8 Regenerate golden files — ./scripts/update-golden.sh. Only ServiceMonitor resources and metrics Services should change.
9 Verify — Diff all variants against Step 0 baseline. nix flake check. Manual inspection of representative ServiceMonitor.

What This Gets Us

  1. Zero coupling — Swap Prometheus for Datadog without touching chart code.
  2. Terminal manifests — config.manifests is write-only. All communication through typed capability options.
  3. Pipe composition — |> withAutoscaler |> withPDB |> withRole for charts. Desugars to capability registry declarations.
  4. Generic monitoring — "Find metric endpoints", not "find coredns". One discovery label for all monitored services.
  5. Introspection — Capability registries enable kix status, kix graph, kix validate.
  6. Dependency DAG — Capability declarations + structural inference give Luca his DAG across all 5 use cases.
  7. RFC 189 compatible — Capability interfaces are structurally compatible with NixOS Contracts.
