# Kix documentation

Astro Starlight site for Kix. Built as a true sibling Nix subflake.

Deployed at **<https://kixops.dev/docs/>** (current tree) with pinned
version snapshots at `kixops.dev/docs/v0.1/`, etc. GitHub Pages serves
the merged `homepage/` + `docs/` artifact — see
`.github/workflows/pages.yml`.

## Build

```bash
nix build ./docs#site
```

The static site is written to `result/`. Serve it with any static file server, e.g.:

```bash
python3 -m http.server -d result 8000
```

## Dev server (live reload)

One command — run from the kixpkgs repo root:

```bash
nix run ./docs#dev
```

This builds the snippet + reference pipelines, syncs their output into
`docs/src/`, installs npm deps if missing, and starts the Astro dev
server with HMR. Open the URL it prints (usually <http://localhost:4321>).

> **Nix features.** This flake requires `nix-command` + `flakes` (standard on
> nix-darwin / NixOS) and declares `pipe-operators` via `nixConfig`. Accept the
> nix prompt on first use, or set `accept-flake-config = true` in your
> `~/.config/nix/nix.conf`.

Re-run after editing source `.nix` files (packages, kix-examples snippet
files) to re-sync the generated content. Pure prose edits inside `docs/`
hot-reload without restarting.

### Manual dev path (rarely needed)

If `nix run ./docs#dev` isn't an option, do it by hand:

```bash
nix build ./docs#snippets          --no-link --print-out-paths   # → /nix/store/...
nix build ./docs#reference         --no-link --print-out-paths   # → /nix/store/...
# Copy each output into the docs/src tree (see flake.nix preBuild for paths)
nix develop ./docs
cd docs && npm install && npm run dev
```

## Layout

- `src/content/docs/` — MDX content, organized by [Diátaxis](https://diataxis.fr/) quadrant:
  - `tutorials/` — learning-oriented walkthroughs
  - `how-to/` — task-oriented recipes
  - `reference/` — information-oriented API/option docs
  - `explanation/` — understanding-oriented background
- `astro.config.mjs` — site config, sidebar, plugins
- `src/content.config.ts` — Starlight content collection schema

Pages under `reference/package-catalog/` are auto-generated by
`docs/nix/reference.nix` — it runs `nixosOptionsDoc` over each Kix package's
`options` attrset and emits one MDX file per package. Do not edit them
by hand; changes will be overwritten on the next build.

On a clean checkout these paths show placeholder content from Phase 2A.
The `reference` derivation only runs when you build `nix build ./docs#site`
(which drops it into the content tree via `preBuild`) or directly via
`nix build ./docs#reference`. Currently only `echo-server`, `cert-manager`,
and `cilium` are wired up; the remaining 58 packages will be added in a
later pass.

## Snippets

The snippet pipeline auto-discovers `.nix` files containing `# region:NAME`
markers under `kix-examples/` and drops each region into
`src/snippets/<relative-path-without-.nix>/<region>.nix` as raw Nix
code (no frontmatter, no fence). No registration step.

**Add a new snippet:**

1. In any `.nix` file under `kix-examples/`, wrap the code you
   want to expose:

   ```nix
   # region:isProxy
   isProxy =
     inst:
     builtins.elem "reverse-proxy" (inst._meta.packageMeta.provides or [ ]);
   # endregion:isProxy
   ```

   Rules: markers on their own line; one region per name per file;
   region name matches `[a-zA-Z][a-zA-Z0-9-]*`; end markers must name
   the region they close. Nested regions are allowed.

2. Rebuild. The output path mirrors the source path. For example
   `examples/19-scorecards/scorecard.nix` with a `# region:isProxy`
   marker emits `src/snippets/examples/19-scorecards/scorecard/isProxy.nix`.

That's it — no edits to `docs/flake.nix`.

**Use a snippet in a docs page** (page must be `.mdx`, not `.md`):

```mdx
---
title: "Scorecards explained"
description: ...
---

import Snippet from '/src/components/Snippet.astro';
import isProxy from '/src/snippets/examples/19-scorecards/scorecard/isProxy.json';

Scorecard rules identify reverse-proxy packages with this helper:

<Snippet {...isProxy} />
```

`<Snippet>` (from `docs/src/components/Snippet.astro`) renders the code
through Starlight's `<Code>` component (syntax highlighting, copy-to-clipboard,
title showing the line range) and adds a "View source on GitHub" link
pointing at the exact line range in the kix-examples repo at the locked
commit. The URL is computed by the snippet pipeline from `sourceUrlBase`
in `docs/flake.nix`, which pins to `kix-examples.rev` from `flake.lock` —
links never rot under `main`.

Nested regions can be elided by the calling MDX page. This keeps the source
file free of docs-only presentation hints:

```mdx
<Snippet
  {...clusterFrame}
  elide={{ helloWorldInstance: '        # package instances go here' }}
/>
```

**Raw code only (no link, no component):** the pipeline also emits a
`.nix` sidecar with just the region body. Use this if you want to render
the snippet your own way:

```mdx
import { Code } from '@astrojs/starlight/components';
import isProxyCode from '/src/snippets/examples/19-scorecards/scorecard/isProxy.nix?raw';

<Code code={isProxyCode} lang="nix" />
```

## Plugins

- [`starlight-llms-txt`](https://github.com/delucis/starlight-llms-txt) — emits `llms.txt` and per-page `.md` for LLM ingestion.
- [`starlight-versions`](https://github.com/HiDeoo/starlight-versions) — multi-version routing. The `versions` array in `astro.config.mjs` is empty until v0.1 is cut.
