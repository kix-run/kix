`kix doctor` inspects the bundled runtime directory that `kix` uses to run Nix, Helm, `kubectl`, and `sops`. It reports how the runtime directory was located, confirms that every bundled program matches the version compiled into the `kix` binary, and checks the SHA-256 hash of every file and symlink target in `manifest.json`.

This page is hand-maintained from `cli/kix-cli/src/cli.rs`, `cli/kix-cli/src/commands/doctor.rs`, `cli/kix/src/runtime.rs`, and `cli/runtime/programs.json`. When flag definitions or runtime behavior change in the Rust source, update this page in the same change.

## Synopsis

<Command commands={["kix doctor"]} />

`kix doctor` takes no command-specific flags and ignores `-o` / `--output`.

## How Kix locates its runtime

When `kix` starts, it resolves its runtime directory (`libexec/kix`) using the first match in this order:

1. **`KIX_RUNTIME_DIR`**, if set in the environment. If `KIX_RUNTIME_DIR` is set to an empty string or points to a path that is not a directory, `kix` exits with an error instead of falling back.
2. **`../libexec/kix` relative to the `kix` executable**, which is the layout inside the pre-built release archive (`bin/kix` alongside `libexec/kix/`).
3. **The compiled-in Nix store path** (`KIX_BUILTIN_RUNTIME_DIR`), used when `kix` is built and installed through Nix (`nix run` or `nix profile install`).

On normal commands (`kix check`, `kix diff`, `kix deploy`), `kix` reads `<runtime>/manifest.json` and verifies that the program set and version strings match what the binary expects. `kix doctor` goes further and hashes every file and symlink target listed in `manifest.json` to detect corrupted or incomplete installations.

## Bundled programs

Each `kix` binary is compiled against the exact tool versions in `cli/runtime/programs.json`:

| Program | Bundled version(s) | Used by Kix for |
| --- | --- | --- |
| `nix` | `2.35.4` | Evaluating cluster flakes and storing rendered manifests in Kix's local store (`$XDG_CACHE_HOME/kix/store` or `~/.cache/kix/store`, overridden by `KIX_STORE_ROOT`). |
| `helm` | `4.3.1` (default), `3.19.1` | Fetching Helm chart tarballs (`fetchHelmChart`) and rendering templates (`importChart`). |
| `kubectl` | `1.37.2` | Streaming workload logs (`kix logs`) and forwarding local ports (`kix pf`). |
| `sops` | `3.12.1` | Decrypting SOPS-encrypted secrets (`kix.mkSopsSecret`) during `kix deploy` and `kix apply`. |

### Version update policy

- **`nix`, `kubectl`, and `sops`** track recent upstream stable releases and are updated across Kix releases after passing the test suite.
- **`helm` versions are pinned for reproducibility.** Because `helm template` output feeds directly into Kix resource hashes (`kix.run/hash`), changing a Helm binary version can change rendered manifests. Kix ships both Helm 4 (`4.3.1`, the default) and Helm 3 (`3.19.1`, upstream security fixes until 10 February 2027), and checks at evaluation time that your `kixpkgs` library lockfile expects the same Helm versions as the running `kix` binary. See [`kix lib update`](/docs/reference/cli/lib/) and [Helm and imports](/docs/reference/helm-and-imports/#helm-versions).

## Third-party licenses and LGPL components

The release archive ships `libexec/kix/THIRD_PARTY_LICENSES` alongside the bundled binaries, and each GitHub release publishes a companion `kix-<version>-third-party-sources.tar.zst` archive containing the exact upstream source tarballs and Nix patches for the LGPL/GPL runtime libraries (`glibc`, `gcc` runtime libraries, `libidn2`, `libunistring`, `attr`, `acl`, and `util-linux` libraries).

If you ever need to run `kix` against a modified build of one of those shared libraries:

1. Copy `libexec/kix/` to a writable directory and replace the shared library file inside `lib/`.
2. Point `KIX_RUNTIME_DIR` at your modified directory.

Normal `kix` commands check only the program names and versions in `manifest.json`, so your modified library will run as expected. `kix doctor` will report the modified file's SHA-256 mismatch because its hash check compares against the original `manifest.json`.

## Examples

Verify a healthy installation:

<Command commands={["kix doctor"]} />

```text
Runtime directory: /home/alice/.local/libexec/kix (next to executable)
  nix: 2.35.4
  helm: 3.19.1, 4.3.1
  kubectl: 1.37.2
  sops: 3.12.1
  files: 48 verified (sha256)
Runtime OK.
```

## Exit status

- `0` when the runtime directory exists, all program versions match the compiled-in manifest, and every file and symlink matches its recorded SHA-256 hash.
- `1` when the runtime directory cannot be found, `manifest.json` is missing or mismatched, or any file is missing, unexpected, or fails its SHA-256 check.
