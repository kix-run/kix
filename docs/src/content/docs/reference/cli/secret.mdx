`kix secret` works with the SOPS files that Secrets are made from. Its `hash` subcommand prints the value to set as `hash` beside `source`, on a `packages.secret` instance or in `scope.mkSecret`.

:::note
This page is hand-maintained from `cli/kix-cli/src/cli.rs`, `cli/kix-cli/src/commands/secret.rs`, and `cli/kix/src/cluster/secrets.rs`. When flag definitions or behavior change in the Rust source, update this page in the same change.
:::

## Synopsis

```text
kix secret hash <FILE>
```

## What `kix secret hash` prints

`kix secret hash` decrypts `FILE` with the `sops` in the Kix runtime, as `kix deploy` does, and prints `sha256-<base64>`: the SHA-256 of the decrypted keys, written as `<key>=<value>` lines in key order, each ending in a newline. It prints only the hash and never prints the secret values.

Decrypting needs the same key that `kix deploy` uses, such as the age key in `SOPS_AGE_KEY_FILE`.

`kix deploy` stops when a SOPS file's values do not match its `hash`, and it does not print the new hash, because deploy output often goes to shared logs. After you change a SOPS file on purpose, run `kix secret hash` on it and put the result in `hash` where the file is declared.

Global flags `-v` / `--verbose`, `-q` / `--quiet`, and `--no-color` also apply. `-o` / `--output` accepts only `text`.

## Example

<Command commands={["kix secret hash secrets/app-db.sops.yaml"]} />

```text
sha256-0DPxd8CHMQF98J0Ly5ea++hp1OCONIrWMz5Yb7eXmdY=
```

Set the result on the instance whose `source` is that file:

```nix title="cluster.nix"
instances.data.app-db-password = {
  package = packages.secret;
  config = {
    source = ./secrets/app-db.sops.yaml;
    hash = "sha256-0DPxd8CHMQF98J0Ly5ea++hp1OCONIrWMz5Yb7eXmdY=";
    keys = [ "password" ];
  };
};
```

## Exit status

- `0` when Kix decrypted the file and printed its hash.
- `1` when the file does not exist, `sops` cannot decrypt it, or its decrypted content is not a mapping of keys to values.
