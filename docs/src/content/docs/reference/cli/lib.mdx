`kix lib` manages the `kixpkgs` library input locked in your project's `flake.lock`. Its `update` subcommand moves your locked `kixpkgs` revision to match the version of the `kix` binary you are running.

:::note
This page is hand-maintained from `cli/kix-cli/src/cli.rs`, `cli/kix-cli/src/commands/library.rs`, and `cli/kix/src/library.rs`. When flag definitions or behavior change in the Rust source, update this page in the same change.
:::

## Synopsis

<Command commands={["kix lib update [--dry-run] [--flake <FLAKE>]"]} />

## Why the CLI and `kixpkgs` versions stay aligned

When a cluster uses Helm charts (`kix.helmChart`, `scope.helm.importChart`, or `scope.helm.importChartCrds`), both `kixpkgs` and the `kix` CLI record the exact Helm 3 and Helm 4 versions used to render templates (`kix/lib/helm-versions.json` in `kixpkgs`, and `cli/runtime/programs.json` in the CLI). Keeping those versions identical guarantees that `helm template` produces the same resource hashes on every machine.

If you upgrade the `kix` binary (or update `flake.lock`) and the two sides disagree on a Helm version, Kix stops before rendering the chart and prints a mismatch error telling you how to align them:

- If your `kix` binary is newer than the `kixpkgs` revision in `flake.lock`, run `kix lib update` to move `flake.lock` to `v<kix-version>`.
- If your `flake.lock` is already ahead of your installed `kix` binary, upgrade `kix` to match the version reported in the error.

## Flags (`kix lib update`)

| Flag | Default | Description |
| --- | --- | --- |
| `--dry-run` | `false` | Resolve `github:kix-run/kixpkgs/v<version>` and print the lockfile change that would occur without writing `flake.lock`. |
| `--flake <FLAKE>` | `.` | Path to the flake directory containing `flake.nix` and `flake.lock` (also read from `KIX_FLAKE`). |

Global flags `-v` / `--verbose`, `-q` / `--quiet`, and `--no-color` also apply. `-o` / `--output` is ignored.

## How `kix lib update` updates `flake.lock`

`kix lib update` inspects your flake's input graph via `nix flake metadata --json`, locates the `kixpkgs` input (including transitive inputs when `kixpkgs` is reached through a shared platform flake via `inputs.kixpkgs.follows`), and runs:

```text
nix flake lock --override-input <input-path> github:kix-run/kixpkgs/v<version>
```

It modifies **only `flake.lock`** and never edits `flake.nix`.

For this automatic lockfile update to work cleanly on future `nix flake update` runs as well, your `flake.nix` should declare `kixpkgs` as an unpinned GitHub input:

```nix
{
  inputs.kixpkgs.url = "github:kix-run/kixpkgs";
}
```

### When `kix lib update` asks you to edit `flake.nix` instead

`kix lib update` refuses to overwrite inputs that are intentionally pinned or non-standard in `flake.nix`, and prints exact instructions instead:

- **Pinned tag, branch, or commit in `flake.nix`** (for example, `github:kix-run/kixpkgs/v0.8.0`): `kix lib update` will not silently override a ref written in `flake.nix`. Update the URL in `flake.nix` to `github:kix-run/kixpkgs/v<version>` (or remove the `/v...` suffix so `kix lib update` can manage the version in `flake.lock` directly) and run `kix lib update` again.
- **Custom fork or Git URL**: Update your fork or branch to include `v<version>` and refresh `flake.lock` with `nix flake update`.
- **Local `path:` input**: Check out the matching revision in that local directory.

## Examples

Preview the lockfile change without writing `flake.lock`:

<Command commands={["kix lib update --dry-run"]} />

```text
Would update flake.lock input 'kixpkgs':
  0123456789ab -> 89abcdef0123 (github:kix-run/kixpkgs/v0.1.0)
```

Update `flake.lock` in the current directory:

<Command commands={["kix lib update"]} />

```text
Updated flake.lock input 'kixpkgs':
  0123456789ab -> 89abcdef0123 (github:kix-run/kixpkgs/v0.1.0)
```

## Exit status

- `0` when `flake.lock` is updated (or already at the target revision, or `--dry-run` succeeds).
- `1` when the flake has no `kixpkgs` input, when `flake.nix` pins a ref/fork/path that must be edited by hand, or when `nix flake lock` cannot fetch the target tag.
