`kix drift` checks whether the fields Kix applied to each resource still hold
the values it applied. Every apply writes a `kix.run/applied-hash` annotation;
the check recomputes that hash from the live object and compares. It also
reports each object that the cluster's current Activation record lists and
that is gone from the cluster, such as one someone removed with
`kubectl delete`. It needs only a kubeconfig: it evaluates no flake and builds
nothing.

This page is hand-maintained. Check `cli/kix-cli/src/cli.rs` and
`cli/kix-cli/src/commands/drift.rs` when in doubt.

## Synopsis

```text
kix drift [--cluster <CLUSTER>] [--context <CONTEXT>] [-o text|json] [-q]
```

| Flag | Meaning |
| --- | --- |
| `--cluster <CLUSTER>` | Check only this Kix cluster's resources. Kix finds them through the cluster's Activation records, so no flake is needed. Fails when the cluster has no records while other Kix clusters do. |
| `--context <CONTEXT>` | Kubeconfig context to check. Defaults to the current context. |
| `-o`, `--output` | `text` (default) or `json`. Other values print text. |
| `-q`, `--quiet` | Omit the connection and count lines. |

`--flake` and `--no-cache` have no effect. See
[Global flags](/docs/reference/cli/global-flags/).

## Scope

Without `--cluster`, the check covers every resource carrying the Kix
managed-by label in the Kubernetes context, whichever Kix cluster deployed it.
Each report names the Kix clusters the resource belongs to, read from the
Activation records its `kix.run/activations` annotation names. Text output
shows them in brackets after the resource when the check found more than one
Kix cluster. With `--cluster`, the check covers that cluster's resources,
including ones it shares with another cluster.

Only fields Kix owns through server-side apply are hashed. A field Kix never
set, such as one a controller adds, is not drift. A change made through the
`/scale` subresource, such as `kubectl scale` or an autoscaler, is drift when
Kix set the replica count.

## Verdicts

| Verdict | Text | JSON `verdict` | Meaning |
| --- | --- | --- | --- |
| In sync | `in sync` | `in-sync` | The applied fields match the stamp |
| Drifted | `DRIFTED` | `drifted` | The applied fields changed |
| Unstamped | `not checked (no kix.run/applied-hash annotation; ...)` | `unstamped` | No `kix.run/applied-hash`; the resource was applied before stamping existed, and the next deploy adds it. Not counted as drift. |
| Unreadable | `not checked (no Kubernetes field ownership entry for Kix)` | `no-fieldset` | The object has no field ownership data, so the check cannot run |
| Missing | `MISSING` | `missing` | The current Activation record lists the object, and the cluster does not have it. Counted as drift. |

Kix finds missing objects through the list of deployed objects that each
deploy writes on its Activation record. The list holds identity hashes, so Kix
names a missing object from its manifest in Kix's local store. On a machine
that does not have the deployed build, a missing object shows as
`Unknown/(hash: ...)`. A record without the list, such as one written by an
older version of Kix, gets no check for missing objects. When an
older version of a missing object is on the cluster under another identity
hash, Kix does not report it as missing.

Text output lists only the resources that are not in sync, then a summary line
with the counts. Add `-v` to list the resources in sync as well. JSON output
always lists every resource.

For a drifted resource, text output names each changed field with the field
manager, operation, and time Kubernetes recorded, in the form
`<field> owned by <manager> (<operation>, <time>)`. When no other manager
is recorded, Kix says so. When anything drifted, the output ends with a
`Next:` line that names `kix plan` and `kix deploy --reconcile`. When an
object is missing, the `Next:` line names `kix deploy --reconcile`, which
creates it again. A deploy without `--reconcile` skips objects whose build did
not change, so it does not create a missing object.

JSON output has a `resources` array (`kind`, `namespace`, `name`, `verdict`,
`clusters`, `foreignOwners`) and a `summary` object with `inSync`, `drifted`, `unstamped`,
`noFieldset`, and `missing` counts. A missing resource also has
`identityHash`. Programs that read the output must skip verdicts they do not
know.

  "kix drift --context prod",

## Exit status

| Code | Meaning |
| --- | --- |
| `0` | No resource drifted and none is missing |
| `1` | At least one resource drifted or is missing, or the cluster could not be reached |

:::tip[Use it in a task]
See [Check live resources for drift](/docs/how-to/operate-a-cluster/check-live-resources-for-drift/),
then [Reconcile drift](/docs/how-to/operate-a-cluster/reconcile-drift/) to put
the values back.
:::

See [Server-side apply, field ownership, and drift](/docs/explanation/server-side-apply-and-drift/)

:::
