`kix gc` removes what a cluster's build no longer contains. It has three
modes: the default compares the last deployed build with a fresh one,
`--full-scan` scans every Kix-managed resource of the named cluster, and `--operator`
deletes Activation records and lets the Kix operator clean up after them.
Every mode also retires old Superseded Activation records.

This page is hand-maintained. Check `cli/kix-cli/src/cli.rs` and
`cli/kix-cli/src/commands/gc/{mod,plan,render}.rs` when in doubt.

## Synopsis

```text
kix gc <CLUSTER> [-y] [--dry-run] [--full-scan [--include unstamped,unattributed,copies]] [--operator]
       [--keep <N>] [--keep-max <N>] [--keep-for <DURATION>]
       [--flake <FLAKE>] [--context <CONTEXT>]
```

| Argument or flag | Meaning |
| --- | --- |
| `<CLUSTER>` | Cluster name to build from the flake. |
| `-y`, `--yes` | Skip the confirmation prompt. Required when stdin is not a terminal. |
| `--dry-run` | Print what gc would delete, both resources and Activation records, and delete nothing. |
| `--full-scan` | Scan the named cluster's resources carrying the Kix managed-by label and delete those whose identity hash is not in the fresh build. |
| `--include <KINDS>` | With `--full-scan` (required), also judge the kinds of resource a full scan only lists by default. A comma-separated list of the values below. |

| `--include` value | Resources it adds |
| --- | --- |
| `unstamped` | Resources that carry the label but no `kix.run/identity-hash`. Kix never applied these, so by default they are only listed. |
| `unattributed` | Resources that name no Activation record on the cluster. When another Kix cluster has records on the same Kubernetes cluster, Kix cannot tell whose these are, so by default they are only listed. |
| `copies` | Copies. A copy carries Kix's labels and annotations, but Kix never wrote it: an operator copied them from an object Kix made, such as the data volumes it makes for a database. By default copies are only listed. |
| `--operator` | Delete the retired Activation records only; the operator's finalizer removes their resources. |
| `--keep <N>` | Always keep at least the `N` newest Superseded records, whatever their age. Default `10`. `0` keeps none. |
| `--keep-max <N>` | Never keep more than `N` Superseded records. Default `50`. A value below `--keep` is raised to it. |
| `--keep-for <DURATION>` | Beyond `--keep`, retire records older than this: `30d`, `12h`, `45m`, `30s`, or a bare number of days. `0` or `off` disables the age rule. Default `30d`. |
| `--flake`, `--context` | See [Global flags](/docs/reference/cli/global-flags/). `-o` has no effect. |

## Modes

| Mode | Old side | What is deleted |
| --- | --- | --- |
| Default | The build the cluster's Active record names, from this machine's cache of the last `kix deploy` or `kix rollback` when that is the same build, else from Kix's local store; and the builds the Active record lists under `status.orphansKeptFrom` | Resources whose kind, namespace, and name are absent from the fresh build. Exits with a message if the cluster has no Active record or its build is not on this machine. A cached build of another context's cluster of the same name is set aside with a warning. |
| `--full-scan` | Every Kix-managed resource of the named cluster | Resources whose identity hash is not in the fresh build |
| `--operator` | Activation records | Retired records; the operator deletes their resources |

Both the default mode and `--full-scan` judge only objects carrying the label `app.kubernetes.io/managed-by=kix`, and the Kix operator reads only objects with that label. `kix gc` never lists or deletes an object applied without that label, such as a resource applied with `kubectl`. See [Objects Kix did not apply](/docs/reference/cli/diff/#objects-kix-did-not-apply).

:::caution[The default mode can omit cluster-level garbage from its plan]
The default mode currently deletes stale resources that belong to no package,
but its confirmation plan does not list them. Use `--full-scan` when you need
the plan to inventory those resources before deletion.
:::

`--full-scan` judges the resources of the cluster you name. Each resource Kix
deploys lists, in its `kix.run/activations` annotation, the Activation records
whose builds contain it, and each record carries a `kix.run/cluster` label.
When one Kubernetes cluster hosts several Kix clusters, a full scan reads those
records to decide whose each resource is:

- A resource that names only another cluster's records is skipped, and the
  run prints how many it skipped per cluster.
- A resource that another cluster's current build also contains is kept and
  listed as `kept ..., still deployed by Kix cluster <name>`.
- A resource that names no record on the cluster (its records were retired,
  or it predates the annotation) is listed under "No deployment record on this cluster" and kept
  unless you pass `--include unattributed`. With only one Kix cluster on the
  Kubernetes cluster, such a resource is judged like any other.

The default mode, `kix deploy --prune`, and `kix rollback --prune` apply the same rule to
a resource both clusters deploy: when the named cluster's build drops it and
another cluster's current build still contains it, the plan lists it as kept.

Every delete checks again just before it happens: gc reads the resource, then
the Activation records, and deletes it only if no other cluster's current
record names it and it has not changed since that read. A resource left for
either reason is printed as `= prune: kept ...` and is not a failure.

Resources are deleted dependents first. Namespaces and
CustomResourceDefinitions are skipped. A resource that is already gone when
gc deletes it is reported, not counted as a failure.

A deploy without `--prune` keeps its orphans and lists the builds they came
from on the new Activation, under `status.orphansKeptFrom`. The default
mode deletes those orphans too, listed under "Orphans kept by earlier
deploys". When gc deletes without failures in either mode and the fresh build
is the one the Active record describes, it removes the list. The default mode
leaves the list if this machine could not read one of the builds, and a full
scan leaves it if it was forbidden to list some kinds. Deploying with
`--prune` every time keeps the list empty, so the default mode has no kept
orphans to find; see [`deploy`](/docs/reference/cli/deploy/).

Retiring a record removes it as a rollback target. Each record kept adds one
entry to the `kix.run/activations` annotation on every managed resource, which
is why the count is capped. A record is deleted only if it has not changed
since it was listed.

## Exit status

| Code | Meaning |
| --- | --- |
| `0` | Nothing to collect, everything planned was deleted, `--dry-run` printed the plan, or the prompt was declined |
| `1` | A deletion failed; confirmation was needed on a non-interactive terminal; or a build or cluster error |

:::tip[Use it in a task]
See [Garbage-collect stale resources](/docs/how-to/operate-a-cluster/garbage-collect-stale-resources/)
for choosing a mode, and
[Configure activation retention](/docs/how-to/operate-a-cluster/configure-activation-retention/)
for the retention flags.
:::
