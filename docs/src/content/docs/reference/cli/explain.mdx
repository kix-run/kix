When a change in Kix or the Kix library makes an existing definition fail, the
error starts with the change's id in brackets, such as `[K0001]`. `kix explain`
prints the change record behind that id: what changed, the release it shipped
in, and what to change in your definition.

Kix carries every change record up to its own version. The command reads no
project and contacts no cluster.

:::note
This page is hand-maintained from `cli/kix-cli/src/cli.rs` and
`cli/kix-cli/src/commands/explain.rs`. When the command changes, update this
page in the same change.
:::

## Synopsis

```text
kix explain <ID> [-o json]
```

| Argument | Meaning |
| --- | --- |
| `<ID>` | `K` and four digits, such as `K0001`. Kix also accepts the id in brackets or in lower case, so you can paste `[k0001]` from an error. |

`-o json` prints the record as JSON. See
[global flags](/docs/reference/cli/global-flags/).

## After an error

When an error names an id that Kix knows, Kix prints one more line after the
error:

```text
Run `kix explain K0001` for what changed and how to update.
```

`kix check` prints the same line after a failed check.

## Output

The first line names the id and the kind of change, such as
`Breaking (shows an error)`. The next line names the release that shipped it.
Lines for the packages, library symbols, or commands the change touches follow,
then the record's text.

<Command commands={["kix explain K0001"]} />

```text
K0001: Breaking (shows an error)
Released in Kix 0.10.0
Packages: echo-server, dns-exporter

`echo-server` and `dns-exporter` rename `replicaCount` to `replicas`. Set
`replicas` instead.
```

## Exit status

- `0` when Kix knows the id.
- `1` when the argument is not an id, or when Kix has no record with that
  id. A newer Kix may know the id.
