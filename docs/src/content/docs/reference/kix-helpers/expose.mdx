---
title: "`expose`, `ingress`, and `httpRoute`"
description: "Expose a Service or path backends through an Ingress or Gateway API HTTPRoute, or build route definitions directly."
---

Kix provides two layers for HTTP exposure:

- `kix.expose` is a build-entry function that inspects the resolved router
  dependency (`gateway` or `ingressNginx`) and creates either a Gateway API
  `HTTPRoute` or a Kubernetes `Ingress` (plus network policy edges when a
  network policy enforcer is active).
- `kix.ingress.fromService`, `kix.httpRoute.fromService`, and
  `kix.httpRoute.fromPaths` are lower-level helpers that return unsealed
  `Ingress` or `HTTPRoute` definitions for `scope.mkResource` or `scope.mkCR`.

## `kix.expose`

`kix.expose` returns a build-entry function for a package's `build` list:

```nix
build = [
  ({ scope, config, self, kix, ... }: {
    deployment = /* ... */;
    service = self.deployment |> kix.service.fromWorkload { port = 8080; } |> scope.mkResource;
  })
  (kix.expose { service = "service"; })
];
```

Pair `kix.expose` with `kix.options.ingress` in the package's `options` so
instances can configure `ingress.host` and `ingress.annotations`.

### Arguments

| Argument | Default | Meaning |
| --- | --- | --- |
| `service` | `null` | Name of the Service part on `self` (for example, `"service"`). Mutually exclusive with `paths`. |
| `paths` | `null` | List of `{ path; service; port ? null; pathType ? "Prefix"; }` records naming Service parts on `self`. Mutually exclusive with `service`. |
| `partName` | `"route"` | Part name created on `self` for the rendered `Ingress` or `HTTPRoute` (or `null` when unexposed). |
| `exposurePart` | `"exposure"` | Part name created on `self` for the route metadata record (`{ via; host; scheme; url; urlOrNull; }`). |
| `defaultAnnotations` | `{ }` | Default annotations merged under `config.ingress.annotations` in Ingress mode. |
| `port` | `null` | Explicit backend Service port when `service` is used. Defaults to `self.<service>.out.port`. |
| `timeouts` | `null` | Gateway API rule timeouts (such as `{ request = "0s"; }`) in Gateway mode. Ignored in Ingress mode. |
| `deriveHost` | `true` | When `true`, falls back to `<instanceName>.<cluster.domain>` when `config.ingress.host` is unset. When `false`, requires an explicit `config.ingress.host`. |

If a package calls `kix.expose` more than once, set distinct `partName` and
`exposurePart` names on the second call so its parts do not collide with the
first.

### Dependencies and parts produced

The build function returned by `kix.expose` takes optional `gateway ? null`,
`ingressNginx ? null`, and `clusterIssuer ? null` dependencies:

- When neither `gateway` nor `ingressNginx` is resolved (or no host is set),
  `self.<partName>` is `null` and `self.<exposurePart>.via` is `null`.
- When `gateway` is resolved, `kix.expose` validates that the Gateway publishes
  a matching HTTP or HTTPS listener for the route's host and namespace, creates
  `self.<partName>Crd` (`scope.mkCRDRef` for `HTTPRoute`), and builds
  `self.<partName>` with `scope.mkCR`.
- When `ingressNginx` is resolved, `kix.expose` builds a `networking.k8s.io/v1`
  `Ingress` with `scope.mkResource`, applying `clusterIssuer.out.withCert` when
  `clusterIssuer` is present.
- When both `gateway` and `ingressNginx` are resolved at once, evaluation fails
  and asks the cluster definition to wire one of them via `deps`.
- When a `network-policy-enforcer` is present and the router publishes
  `out.podSelector`, `kix.expose` also emits `<partName>-netpol-<servicePart>`
  allowing ingress traffic from the router's pods to the backend Service ports.

### Reading the public URL (`self.exposure`)

`self.<exposurePart>` (`self.exposure` by default) is a record with:

| Field | Value |
| --- | --- |
| `via` | `"gateway"`, `"ingress"`, or `null` |
| `host` | Resolved hostname string without Nix string context, or `null` |
| `scheme` | `"http"`, `"https"`, or `null` |
| `urlOrNull` | `"<scheme>://<host>[:<port>]"` when exposed, or `null` when unexposed |
| `url` | Same as `urlOrNull`, but fails evaluation with an actionable message if the instance is not exposed |

## `kix.ingress.fromService`

`kix.ingress.fromService` takes route settings and a Service resource, and
returns an unsealed `networking.k8s.io/v1` `Ingress` definition for
`scope.mkResource`:

```nix
ingress =
  self.service
  |> kix.ingress.fromService {
    name = scope.instanceName;
    host = "app.example.com";
    className = ingressNginx.out.ingressClassName;
  }
  |> scope.mkResource;
```

| Argument | Default | Meaning |
| --- | --- | --- |
| `name` | required | `Ingress` name. |
| `host` | required | Hostname for the single rule. |
| `path` | `"/"` | HTTP path match value. |
| `pathType` | `"Prefix"` | Kubernetes Ingress path match type (`"Prefix"` or `"Exact"`). |
| `port` | the Service's `out.port` | Numeric backend Service port. Required when the Service exports no `out.port`. |
| `className` | `null` | Written to `spec.ingressClassName` when non-null. |
| `tls` | `[ ]` | Written to `spec.tls` when non-empty. |

Any additional attributes on the first argument (such as `annotations` or
`labels`) are passed through to the returned resource definition.

## `kix.httpRoute.fromService`

`kix.httpRoute.fromService` takes route settings and a Service resource, and
returns an unsealed Gateway API `HTTPRoute` definition with one rule. Build it
with `scope.mkCR` from a CRD reference for HTTPRoute, which adds the instance
namespace, labels, validation, and dependency metadata. The HTTPRoute CRD
comes with the Gateway API implementation, so the package declares it with
`scope.mkCRDRef`; without that dependency the cluster build refuses the route
(cross-resource check 21).

```nix
routeCrd = scope.mkCRDRef {
  group = "gateway.networking.k8s.io";
  kind = "HTTPRoute";
  plural = "httproutes";
  version = "v1";
};

route =
  self.service
  |> kix.httpRoute.fromService {
    name = scope.instanceName;
    host = "app.example.com";
    parentRef = gateway.out.gatewayRef;
  }
  |> scope.mkCR self.routeCrd;
```

### Arguments

The first argument is a record; the second is the backend Service resource.

| Argument | Default | Meaning |
| --- | --- | --- |
| `name` | required | HTTPRoute name. |
| `host` | required | The single entry written to `spec.hostnames`. |
| `parentRef` | required | Gateway reference with `name` and optional `namespace`. |
| `path` | `"/"` | HTTP path value of the rule's match. |
| `pathType` | `"PathPrefix"` | Gateway API path match type, written as given. |
| `port` | the Service's `out.port` | Numeric backend Service port. Required when the Service exports no `out.port`. |
| `timeouts` | `null` | Gateway API rule timeouts, such as `{ request = "0s"; }` for a long-lived streaming backend. Omitted when `null`. |

Any other key is copied to the top level of the returned definition, so
`labels` or `annotations` reach `scope.mkCR`.

`kix.expose { service = ...; }` uses this helper when the package receives a
Gateway provider, and adds the CRD reference as the part `<partName>Crd`
(`routeCrd` by default). Use the helper directly when a package needs an
HTTPRoute outside the standard exposure interface. For several paths to
different Services, see [`kix.httpRoute.fromPaths`](#kixhttproutefrompaths).

## `kix.httpRoute.fromPaths`

`kix.httpRoute.fromPaths` returns an unsealed Gateway API `HTTPRoute`
definition. Build it with `scope.mkCR` from a CRD reference for HTTPRoute,
which adds the instance namespace, labels, validation, and dependency
metadata. The HTTPRoute CRD comes with the Gateway API implementation, so the
package declares it with `scope.mkCRDRef`; without that dependency the
cluster build refuses the route (cross-resource check 21).

```nix
routeCrd = scope.mkCRDRef {
  group = "gateway.networking.k8s.io";
  kind = "HTTPRoute";
  plural = "httproutes";
  version = "v1";
};

route = scope.mkCR self.routeCrd (kix.httpRoute.fromPaths {
  name = scope.instanceName;
  host = "app.example.com";
  parentRef = gateway.out.gatewayRef;
  paths = [
    {
      path = "/api";
      svc = self.apiService;
      port = 8080;
    }
    {
      path = "/";
      pathType = "Exact";
      svc = self.frontendService;
    }
  ];
});
```

### Arguments

| Argument | Default | Meaning |
| --- | --- | --- |
| `name` | required | HTTPRoute name. |
| `host` | required | The single entry written to `spec.hostnames`. |
| `parentRef` | required | Gateway reference with `name` and optional `namespace`. |
| `paths` | required | List of backend path records described below. |
| `timeouts` | `null` | Gateway API rule timeouts, copied to every generated rule. |

Each `paths` entry accepts:

| Field | Default | Meaning |
| --- | --- | --- |
| `path` | required | HTTP path value. |
| `svc` | required | Kix Service resource used for the backend name and dependency. |
| `port` | `svc.out.port` | Numeric backend Service port. Required when the Service exports no `out.port`. |
| `pathType` | `"Prefix"` | `Prefix` or `PathPrefix` becomes Gateway API `PathPrefix`; `Exact` remains `Exact`. Other values are evaluation errors. |

The helper writes one HTTPRoute rule per path. Gateway API determines rule
precedence, so list order does not control which matching rule wins.

`kix.expose { paths = ...; }` uses this helper when the package receives a
Gateway provider, and adds the CRD reference as the part `<partName>Crd`
(`routeCrd` by default). Use the helper directly when a package needs an
HTTPRoute outside the standard exposure interface.
