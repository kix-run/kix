Writing raw Kubernetes manifests often means repeating the same boilerplate in multiple places, such as declaring a volume and its mount path separately or copying container ports into a matching Service. The `kix.*` composition helpers let you write each concern once: some transform container and workload specs directly, while others drop into a package's `build` list to wire ingress routes, Prometheus scraping, and post-deploy health checks.

:::note[Helpful background]
- [07. Package anatomy and safe resource composition](/docs/tutorials/07-package-anatomy-and-safe-resource-composition/): see how `kix.withMounts`, `kix.mkEnvVars`, and `kix.service.fromWorkload` work together in a package.
- [Package anatomy](/docs/reference/package-anatomy/): review how entries in a package's `build` list are evaluated and merged.
- [Resources and `out`](/docs/reference/resources-and-out/): see how the resources returned by these helpers expose `.out` attributes.
- [Service (Kubernetes docs)](https://kubernetes.io/docs/concepts/services-networking/service/): review how Kubernetes Services select pods and route traffic to container ports.
:::

## Env helpers

Kubernetes expects a container's `env` field to be a list of `{ name, value }` or `{ name, valueFrom }` objects. `kix.mkEnvVars` and `kix.mkEnv` let you write concise attribute sets while supporting secret and downward-API `valueFrom` references and conditional `null` entries.

### `kix.mkEnvVars` and `kix.mkEnv`

| Function | Signature | Description |
| --- | --- | --- |
| `kix.mkEnvVars` | `attrs -> list` | Converts an attribute set `{ KEY = value; ... }` into a sorted list of Kubernetes `env` entries, dropping any key whose value is `null`. |
| `kix.mkEnv` | `attrs -> list -> list` | Equivalent to `(kix.mkEnvVars attrs) ++ rawList`. Combines an attribute set of env vars with an explicit list of `{ name; ... }` objects. |

Each value in `attrs` passed to `kix.mkEnvVars` or `kix.mkEnv` can be:
- **A string**: becomes `{ name = KEY; value = "..."; }`.
- **An attribute set containing `valueFrom`** (such as `self.secret.out.keyRef "password"`): becomes `{ name = KEY; valueFrom = value.valueFrom; }`. Any attribute set without `valueFrom` throws an evaluation error.
- **`null`**: omitted from the returned list.

```nix
env = kix.mkEnv {
  PORT = "8080";
  LOG_LEVEL = config.logLevel;
  DB_PASSWORD = self.dbSecret.out.keyRef "password";
  OPTIONAL_FEATURE = if config.enableFeature then "true" else null;
} [
  {
    name = "POD_IP";
    valueFrom.fieldRef.fieldPath = "status.podIP";
  }
];
```

When merging user-supplied environment variables from `kix.options.env` (`config.env`), use [`kix.mergeEnv`](/docs/reference/package-anatomy/#escape-hatches-and-guard-helpers) so operators cannot overwrite environment variables owned by typed package options.

## Mount helpers

In raw Kubernetes specs, mounting a volume requires updating two separate places: `spec.template.spec.volumes` and `spec.template.spec.containers[*].volumeMounts`. Kix's `kix.mount.*` constructors and `kix.withMounts` / `kix.withMountsOn` keep each volume and its mount path together in one declaration.

```nix
deployment = scope.mkDeployment (
  kix.withMounts [
    (kix.mount.configMap self.configMap {
      mountPath = "/etc/myapp";
      readOnly = true;
    })
    (kix.mount.secret self.tlsSecret {
      mountPath = "/etc/tls";
    })
    (kix.mount.emptyDir {
      name = "cache";
      mountPath = "/var/cache/myapp";
      sizeLimit = "512Mi";
    })
  ] {
    name = "myapp";
    spec = {
      replicas = 2;
      selector.matchLabels = scope.selectorLabels;
      template.spec.containers = [
        {
          name = "myapp";
          image = kix.image.ref config.image;
          resources = config.resources;
        }
      ];
    };
  }
);
```

### `kix.mount.*` constructors

All resource-backed mount constructors (`kix.mount.pvc`, `kix.mount.configMap`, and `kix.mount.secret`) return `null` when their first argument (`resource`) is `null`, so optional mounts work without extra `lib.optional` wrappers. They also derive the volume name from `resource.out.name` by default (propagating the resource's Nix string context so the workload automatically depends on the mounted `ConfigMap`, `Secret`, or `PersistentVolumeClaim`) and record the resource's namespace for `checkNamespacedRefs`.

| Constructor | Signature | Options in final attrset |
| --- | --- | --- |
| `kix.mount.pvc` | `pvc -> { mountPath, name ? pvc.out.name, readOnly ? false, subPath ? null }` | Mounts a `PersistentVolumeClaim` (`persistentVolumeClaim.claimName = pvc.out.name`). |
| `kix.mount.configMap` | `cm -> { mountPath, name ? cm.out.name, readOnly ? false, subPath ? null, defaultMode ? null, items ? null }` | Mounts a `ConfigMap` (`configMap.name = cm.out.name`). |
| `kix.mount.secret` | `sec -> { mountPath, name ? sec.out.name, readOnly ? false, subPath ? null, defaultMode ? null, items ? null }` | Mounts a `Secret` (`secret.secretName = sec.out.name`). |
| `kix.mount.emptyDir` | `{ name, mountPath, medium ? null, sizeLimit ? null, readOnly ? false, subPath ? null }` | Mounts a scratch `emptyDir` volume named `name`. |
| `kix.mount.hostPath` | `{ name, mountPath, hostPath, type ? "DirectoryOrCreate", readOnly ? false, subPath ? null }` | Mounts the node path `hostPath` as a volume named `name`. |

`readOnly = true` sets `readOnly` on the container's `volumeMounts` entry. Set it on each mount record separately: a mount record carries one `readOnly` value, so a container that writes a volume and one that only reads it take two records of the same volume, which `kix.withMountsOn` declares once.

### `kix.withMounts` and `kix.withMountsOn`

| Function | Signature | Behavior |
| --- | --- | --- |
| `kix.withMounts` | `mounts -> workloadAttrs -> workloadAttrs` | Attaches all non-null `mounts` to the one container in the pod template's `containers`. Init containers do not count. Fails the build when the pod template has more than one container. |
| `kix.withMountsOn` | `containerName -> mounts -> workloadAttrs -> workloadAttrs`, or `[ containerName ... ] -> mounts -> workloadAttrs -> workloadAttrs` | Attaches all non-null `mounts` to each named container, searching `containers` and `initContainers`. Fails the build when a name matches no container. |

The pod template is `spec.jobTemplate.spec.template.spec` when the workload has a `jobTemplate` (a `CronJob`), and `spec.template.spec` otherwise.

Both functions add each volume to the pod template's `volumes` once. A volume that is already there with the same name and the same source (the same claim, ConfigMap, Secret, or emptyDir settings) is not added again, so the same volume can be mounted into several containers, or at several paths, with separate calls or separate mount records. Two volumes with the same name and different sources fail the build. The error names both sources; give one of them another name with `name = "..."`.

```nix
# The init container writes the token; the main containers read it.
{ name = "worker"; spec = { ... }; }
|> kix.withMountsOn "write-token" [ (tokenMount false) ]
|> kix.withMountsOn [ "app" "sidecar" ] [ (tokenMount true) ]
|> scope.mkDeployment
```

Each call appends to the named containers' `volumeMounts`, so the order of the calls is the order of the mounts in each container.

## service.fromWorkload

`kix.service.fromWorkload` derives a `v1/Service` definition from a workload resource, wiring the workload's label selector and resolving container ports automatically. Pass its result to `scope.mkResource`.

```nix
service = scope.mkResource (
  kix.service.fromWorkload {
    name = "echo";
  } self.deployment
);
```

### `kix.service.fromWorkload` arguments

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | string | Required | `metadata.name` of the `Service`. |
| `type` | string | `"ClusterIP"` | Kubernetes Service type (`"ClusterIP"`, `"NodePort"`, `"LoadBalancer"`). |
| `ports` | list of `{ name; port; targetPort?; protocol?; }` or `null` | `null` | Explicit Service ports. When `null`, Kix extracts all ports declared across the workload's containers (`port = containerPort`, `targetPort = name`). Any string `targetPort` is verified against the workload's named container ports and resolved to its numeric port number. |
| `outputs` | attrset | `{ }` | Extra fields merged onto the Service's `.out` surface (`outputs.port` defaults to the first Service port number). |
| `...` | any | None | Any additional `scope.mkResource` arguments (`labels`, `annotations`, `requires`, `extra`, or extra `spec` fields) are forwarded to `scope.mkResource`. |

### Related port helpers

- **`kix.port name containerPort`**: Shorthand returning `{ name = name; containerPort = containerPort; protocol = "TCP"; }` for container `ports` lists.
- **`kix.service.extractPorts workload`**: Returns the list of `{ name, port, targetPort, protocol }` objects extracted from `workload`'s container specs.

## expose

`kix.expose` is a composable `build` list entry that exposes a package `Service` outside the cluster using whichever ingress provider the cluster has deployed (`gateway` for Gateway API `HTTPRoute` + `Certificate`, or `ingressNginx` for `networking.k8s.io/v1` `Ingress`). It pairs with `ingress = kix.options.ingress "<default-subdomain>";` in `options`.

```nix
options = {
  ingress = kix.options.ingress "grafana";
};

build = [
  (
    { self, config }:
    {
      deployment = ...;
      service = ...;
      root = self.service;
    }
  )
  (kix.expose { service = "service"; })
];
```

### `kix.expose` arguments

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `service` | string or `(self: resource)` | `"service"` | Part name in `self` (or selector function `self: self.myService`) identifying the target `Service`. |
| `paths` | list or `({ self, config, service }: list)` or `null` | `null` | Custom path routing table (`[ { path; pathType ? "Prefix"; service; port?; } ]`). Overrides `config.ingress.paths` when set. |
| `port` | int, string, or `null` | `null` | Explicit Service port name or number (defaults to `service.out.port` or the sole port on `service`). |
| `partName` | string | `"route"` | Part name for the generated `HTTPRoute` or `Ingress` resource (certificate is placed at `"${partName}Crd"` when Gateway API TLS is active). |
| `exposurePart` | string | `"exposure"` | Attribute name in `self` where resolved exposure metadata (`self.exposure`) is published. |
| `defaultAnnotations` | attrset or `({ config }: attrset)` | `{ }` | Default annotations merged under `config.ingress.annotations` when generating an `Ingress`. |
| `timeouts` | `{ request?; backendRequest?; }` or `null` | `null` | Optional Gateway API `HTTPRoute` rule timeouts (for example, `{ request = "60s"; }`). |
| `deriveHost` | `{ config, clusterConfig }: string` | `config.ingress.host` or `"${config.ingress.subdomain}.${clusterConfig.domain}"` | Custom hostname derivation function. |

### `self.exposure` metadata

Even before the route resource is built, `kix.expose` populates `self.${exposurePart}` (default `self.exposure`) so sibling resources in `build` can read the external URL without creating a circular dependency:

| `self.exposure` field | Type | Description |
| --- | --- | --- |
| `via` | `"gateway"` \| `"ingress"` \| `"none"` | Active exposure mechanism based on `config.ingress.enable` and bound cluster providers (`gateway` takes precedence over `ingressNginx`). |
| `host` | string | Resolved external hostname (for example, `"grafana.example.com"`). |
| `scheme` | `"https"` \| `"http"` | `"https"` when `config.ingress.tls` is true, otherwise `"http"`. |
| `url` | string | Full external URL (`"${scheme}://${host}"`), always populated from `config` and `clusterConfig`. |
| `urlOrNull` | string or `null` | Full external URL when `via != "none"`, or `null` when ingress is disabled or no provider is bound. |

### Lower-level route helpers

When a package needs custom routing outside `kix.expose`, use the lower-level builders directly with `scope.mkResource`:
- `kix.ingress.fromService { host, tls ? true, clusterIssuer ? null, annotations ? { }, paths ? null, port ? null, name ? null } service`
- `kix.httpRoute.fromService { host, gateway, tls ? true, clusterIssuer ? null, scope, paths ? null, port ? null, timeouts ? null, name ? null } service` (returns `{ route, cert }`)
- `kix.httpRoute.fromPaths { name, host, gateway, tls ? true, clusterIssuer ? null, scope, paths, timeouts ? null }` (returns `{ route, cert }`)

## monitor

`kix.monitor` is a composable `build` list entry that creates a `monitoring.coreos.com/v1` `ServiceMonitor` (and an optional `PrometheusRule` for alerts) whenever a `prometheus` provider is bound in the cluster. It pairs with `monitor = kix.options.monitor { };` (and optionally `alerts = kix.options.alerts { };`) in `options`.

```nix
options = {
  monitor = kix.options.monitor { interval = "15s"; };
  alerts = kix.options.alerts { };
};

build = [
  (
    { self, config }:
    {
      deployment = ...;
      service = ...;
      root = self.service;
    }
  )
  (kix.monitor {
    service = "service";
    port = "metrics";
    alerts = {
      EchoHighErrorRate = {
        expr = ''rate(http_requests_total{status=~"5.."}[5m]) > 0.05'';
        "for" = "5m";
        severity = "warning";
        summary = "High HTTP 5xx error rate on echo";
        description = "More than 5% of requests have failed over the last 5 minutes.";
      };
    };
  })
];
```

### `kix.monitor` arguments

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `service` | string or `(self: resource)` | `"service"` | Target `Service` part name in `self` (or selector function). If the target resolves to `null`, monitoring resources are skipped. |
| `port` | string | `"metrics"` | Named port on the target `Service` to scrape. Verified at build time against `service.out.ports`. |
| `path` | string | `"/metrics"` | HTTP scrape path. |
| `scheme` | string or `null` | `null` | Scrape scheme (`"http"` or `"https"`). |
| `tlsConfig` | attrset or `null` | `null` | Prometheus endpoint `tlsConfig` block. |
| `params` | attrset of `listOf str` or `null` | `null` | URL query parameters added to scrape requests. |
| `honorLabels` | bool or `null` | `null` | Whether Prometheus preserves labels exported by the scraped target. |
| `extraEndpoints` | list of attrsets | `[ ]` | Additional endpoint definitions appended to `spec.endpoints` on the `ServiceMonitor`. |
| `alerts` | attrset or `({ self, config }: attrset)` | `{ }` | Map of `<AlertName> = { expr; "for"?; keep_firing_for?; severity?; summary?; description; runbook_url?; labels?; annotations?; }`. |
| `extraLabels` | attrset | `{ }` | Extra `metadata.labels` merged onto generated monitoring resources. |
| `name` | string or `null` | `service.out.name` | Override `metadata.name` of the generated `ServiceMonitor` and `PrometheusRule`. |
| `monitorPart` | string | `"serviceMonitor"` | Part name for the `ServiceMonitor` in the returned parts attrset. |
| `rulesPart` | string | `"prometheusRule"` | Part name for the `PrometheusRule` in the returned parts attrset. |

### Standalone alert rules (`kix.alerts`)

For packages that define `PrometheusRule` alerts without a `ServiceMonitor` (for example, rules evaluated over kube-state-metrics or node-exporter series), use `kix.alerts`:

```nix
(kix.alerts {
  alerts = {
    NamespacePodRestartLoop = {
      expr = ''increase(kube_pod_container_status_restarts_total{namespace="${scope.namespaceName}"}[15m]) > 5'';
      "for" = "5m";
      severity = "warning";
      description = "Pod in ${scope.namespaceName} is restarting repeatedly.";
    };
  };
})
```

`kix.alerts` accepts `alerts`, `name` (defaults to `scope.instanceName`), `extraLabels`, and `rulesPart` (defaults to `"prometheusRule"`).

## healthCheck

`kix.healthCheck` is a composable `build` list entry that creates a post-deployment `batch/v1` `Job` and registers it in `root.postHooks`. Kix runs the Job after `root.resource` and `root.requires` are ready, and re-runs it automatically whenever the package changes (`kix.run/rerun: on-change`). It pairs with `healthCheck = kix.options.healthCheck { };` in `options`.

```nix
options = {
  healthCheck = kix.options.healthCheck { };
};

build = [
  (
    { self, config }:
    {
      deployment = ...;
      service = ...;
      root = self.service;
    }
  )
  (kix.healthCheck {
    script = ''
      import os, urllib.request
      url = f"http://{os.environ['SERVICE_HOST']}:{os.environ['SERVICE_PORT']}/healthz"
      with urllib.request.urlopen(url, timeout=5) as resp:
          assert resp.status == 200
    '';
    env = { self, ... }: {
      SERVICE_HOST = self.service.out.fqdn;
      SERVICE_PORT = toString self.service.out.port;
    };
  })
];
```

### `kix.healthCheck` arguments

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `script` | string or `({ self, config, deps }: string)` | Required | Verification script executed inside the probe container. |
| `env` | attrset or `({ self, config, deps }: attrset)` | `{ }` | Environment variables passed to `kix.mkEnvVars` (supports strings and Secret `keyRef` values) and merged with `RETRY_FOR = toString retryFor`. |
| `when` | bool or `({ self, config, deps }: bool)` | `true` | Additional condition combined with `config.healthCheck.enable`. |
| `retryFor` | positive int | `60` | Retry budget in seconds exposed to the script as `$RETRY_FOR`. Must not exceed `90` seconds (`kix.healthCheck.roundBudget`). |
| `requires` | list or `({ self, config, deps }: list)` | `[ ]` | Extra resources the health-check Job must wait for (in addition to `self.root.resource`, which is wired automatically). |
| `partName` | string | `"healthCheck"` | Part name for the `Job` in `self` (must be unique if a package defines multiple `kix.healthCheck` entries). |
| `runtime` | `{ image, command }` | `kix.healthCheck.runtimes.python` | Probe execution runtime. Built-in runtimes: `kix.healthCheck.runtimes.python` (`python:3.13-alpine`, `["python3" "-u" "-c"]`) and `kix.healthCheck.runtimes.shell` (`busybox:1.37.0`, `["/bin/sh" "-e" "-c"]`). |
| `activeDeadlineSeconds` | positive int | `retryFor + 30` | Kubernetes `Job` `spec.activeDeadlineSeconds` (`<= 120s`). |

Like every Job Kix builds, the finished Job stays on the cluster until a later build no longer contains it, and Kix deletes it then.

## availability

Kix models cluster availability across four ordered levels: `"none"` < `"pod"` < `"node"` < `"zone"`. Inside a package, the `availability` argument reflects the effective availability level for the current instance (clamped to `meta.availability.max`). The top-level `kix.availability` namespace provides the underlying functions when you need to pass an explicit level.

| Helper | Signature | Description |
| --- | --- | --- |
| `availability.level` | string | Effective availability level for the current instance (`"none"`, `"pod"`, `"node"`, or `"zone"`). |
| `availability.pick` | `{ none, pod?, node?, zone? } -> value` | Picks the value for `availability.level`, falling back to the nearest lower defined key (only `none` is required). |
| `availability.atLeast` | `threshold -> bool` | Returns `true` when `availability.level >= threshold` (for example, `availability.atLeast "node"`). |
| `kix.availability.levels` | list of strings | `[ "none" "pod" "node" "zone" ]`. |
| `kix.availability.rank` | `level -> int` | Maps `"none" -> 0`, `"pod" -> 1`, `"node" -> 2`, `"zone" -> 3`. |
| `kix.availability.pick` | `level -> { none, ... } -> value` | Same as `availability.pick` with an explicit `level` argument. |
| `kix.availability.atLeast` | `threshold -> level -> bool` | Returns `true` when `level >= threshold`. |
| `kix.availability.spreadConstraints` | `{ level, selector, topology ? null } -> list` | Synthesizes `topologySpreadConstraints` for operator custom resources (such as CloudNativePG `Cluster` or Valkey) that manage their own pods outside `scope.mkDeployment`. Returns `[]` for `"none"` or `"pod"`, a hostname spread constraint for `"node"`, and both zone and hostname spread constraints for `"zone"`. |

## Image and pin helpers

### `kix.image.ref` and `kix.image.isPinned`

Pair `kix.options.image` in `options` with `kix.image.ref` in container specs:

```nix
image = kix.image.ref config.image;
imagePullPolicy = config.image.pullPolicy;
```

| Function | Signature | Behavior |
| --- | --- | --- |
| `kix.image.ref` | `{ repository, tag ? "", digest ? "", ... } -> string` | Formats a container image reference: `"${repository}:${tag}@${digest}"` when both `tag` and `digest` are non-empty, `"${repository}@${digest}"` when `tag` is empty, or `"${repository}:${tag}"` when `digest` is empty. Also records image provenance for `kix-image-sources.json`. |
| `kix.image.isPinned` | `string -> bool` | Returns `true` if the image string contains a valid `@sha256:<64-hex-chars>` digest. |

### `kix.pins` (`pins.json`)

Kix stores upstream container image digests in `kix/pins.json` (`version = 2`), exposed at `kix.pins`:

| Helper | Signature | Description |
| --- | --- | --- |
| `kix.pins.get` | `key -> { repository, tag, digest, ... }` | Looks up an image pin entry by key from `pins.json`, throwing a descriptive error if the key does not exist. |
| `kix.pins.ref` | `key -> string` | Equivalent to `kix.image.ref (kix.pins.get key)`. |
| `kix.pins.keys` | list of strings | Sorted list of all top-level image pin keys. |
| `kix.pins.all` | attrset | Full attribute set of top-level image pins. |
| `kix.pins.instances` | attrset | Map of `<instanceName>.<optionPath>` image overrides recorded by `kix pin` for specific cluster instances. |

### Image provenance (`kix-image-sources.json`)

Every built cluster output includes `kix-image-sources.json`, which maps each container image string in the cluster to its `origin`:
- `"pin"`: Loaded from `kix/pins.json` (or matched to a pinned digest).
- `"package_default"`: Declared in `kix.options.image` default values inside the package.
- `"injected"`: Overridden by cluster or instance configuration (`instances.<name>.config`).
- `"nix_built"`: Built directly from a Nix derivation (`image.fromDerivation`).
- `"code"`: Constructed inline in Nix expressions without `kix.options.image` or `kix.pins`.

## Facts and untrackedRef

### `kix.facts`

When Kix inspects a resource manifest, it classifies every `.out` reference to determine how the reference affects network policy derivation and secret tracking:

- **Default (ambient reference)**: Counts as a deployment dependency, a network traffic path (when pointing to a `Service` or workload), and a secret reference.
- **`kix.facts.refOnly value`**: Marks `value` (typically a `Service` or workload `.out.name`) as a **structural or configuration-only reference** that does **not** carry network traffic. The deployment dependency (`kix.run/depends-on`) is preserved, but no `CiliumNetworkPolicy` ingress/egress rule is generated for this reference.
- **`kix.facts.connect { target = service; ports = [ 5432 ]; } value`**: Attaches an explicit network connection fact to `value` restricted to the listed `ports`.
- **`kix.facts.structural value`**: Marks a Secret reference (`secret.out.name`) as structural metadata (for example, passing a Secret name to an operator flag that watches it via the Kubernetes API) so Kix does not flag it as an unmounted application credential.

```nix
# Referencing a Service name in an operator CLI flag without opening pod-to-service data traffic
args = [
  "--webhook-service-name=${kix.facts.refOnly self.webhookService.out.name}"
];
```

### `kix.untrackedRef`

Kix validates that every cross-resource reference in a manifest (`serviceAccountName`, volume `claimName`, `secretName`, `configMap.name`, ingress backend, etc.) points to a Kix-managed resource via `.out`. When a field intentionally references a resource created outside Kix or dynamically at runtime by the package's own controller, wrap the reference in `kix.untrackedRef`:

```nix
# Referencing a Secret created dynamically at runtime by this package's own controller
volumes = [
  {
    name = "webhook-cert";
    secret.secretName = kix.untrackedRef {
      name = "my-operator-webhook-cert";
      kind = "Secret";
      by = "self";
    };
  }
];

# Referencing a resource managed by another package dependency
env = kix.mkEnvVars {
  DYNAMIC_CONFIG = kix.untrackedRef {
    name = "operator-generated-cm";
    kind = "ConfigMap";
    by = deps.myOperator;
  };
};
```

`kix.untrackedRef` accepts either a plain string (`kix.untrackedRef "external-name"`) or an attribute set:

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | string | Required | Name of the untracked Kubernetes resource. |
| `kind` | string or `null` | `null` | Kubernetes kind (such as `"Secret"` or `"ConfigMap"`). When `kind` is set and `by != "self"`, Kix records `<apiVersion>/<kind>/<namespace>/<name>` in `metadata.annotations."kix.run/expects"` for pre-deploy cluster checks. |
| `apiVersion` | string | `"v1"` | API version paired with `kind` in `kix.run/expects`. |
| `by` | resource, `"self"`, or `null` | `null` | Who creates the resource at runtime. Passing a dependency (`by = deps.operator`) attaches its store context so the dependency deploys first. Passing `by = "self"` declares that the current package creates the resource itself (suppressing `kix.run/expects` and recording a self-managed expectation). Leaving `by = null` emits a scorecard finding under `architecture.untrackedReferences`. |
