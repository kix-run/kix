---
title: "`instances`"
description: "Declare package instances and imports per namespace, along with their configuration, dependency bindings, availability overrides, and label settings."
---

```nix
instances.apps.web = {
  package = packages.web;
  config = {
    replicas = 3;
    ingress.host = "web.example.com";
  };
  deps.database = ref.data.postgres;
};
```

`instances.<namespace>.<name>` is the core cluster declaration in Kix. Each
entry places a package instance (or an imported external resource created with
[`kix.mkImport`](/docs/how-to/adopt-existing-resources/import-an-existing-service-with-kix-mkimport/)) into `<namespace>`
under the instance name `<name>`.

## Summary of instance fields

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| [`package`](#package) | raw package function or attrset | required | Package definition or `kix.mkImport` marker evaluated for this instance. |
| [`config`](/docs/reference/instance-schema/config/) | deferred module | `{ }` | Per-instance option values evaluated against the package's `options`. |
| [`deps`](/docs/reference/instance-schema/deps/) | `attrs of anything` | `{ }` | Explicit dependency overrides (`ref.<ns>.<inst>` or direct values) keyed by build argument name. |
| [`aliases`](/docs/reference/instance-schema/aliases/) | `list of string` | `[ ]` | Dependency-resolution names for this instance. Replaces `meta.defaultAliases` when non-empty. |
| [`optional`](/docs/reference/instance-schema/optional/) | `bool` | `false` | Keeps the instance dormant unless an active instance transitively depends on it. |
| [`availability`](#availability) | `null \| "none" \| "pod" \| "node" \| "zone"` | `null` | Overrides `cluster.availability.default` for this instance. |
| [`partsOverlays`](/docs/reference/instance-schema/partsoverlays/) | `list of function` | `[ ]` | Functions (`scope: self: base: attrset`) that override or extend the instance's evaluated parts. |
| [`labelStyle`](#labelstyle-and-selectorlabels) | `"kix" \| "helm"` | `"kix"` | Label key convention (`app.kubernetes.io/*` vs `app`/`release`) used for selectors and metadata. |
| [`selectorLabels`](#labelstyle-and-selectorlabels) | `null \| attrs of string` | `null` | Explicit pod selector labels for adopting workloads with immutable existing selectors. |
| [`extraDeps`](#extradeps-and-platformintents) | `list of raw` | `[ ]` | Additional ordering dependencies on a `kix.mkImport` instance's `PackageInstance` marker. |
| [`platformIntents`](#extradeps-and-platformintents) | `attrs of anything` | `{ }` | Enforcer-agnostic connectivity intents for a `kix.mkImport` instance's pre-installed pods. |
| [`version`](#version) | `null \| string` | `null` | Optional instance-level version annotation override. |

## `package`

```nix
instances.apps.web.package = packages.web;
```

`package` selects the package that an instance evaluates. It is required for
every managed instance.

The value is normally a package function:

```nix
{ scope, lib, kix, ... }:
{
  meta.version = "1.0.0";
  options = { /* ... */ };
  build = { self, config, ... }: { /* ... */ };
}
```

Kix also accepts an already evaluated package attribute set containing `build`.
Imports created with `kix.mkImport` use the same `package` field but follow the
import evaluation path.

The module type is raw so Kix can evaluate the package through its own fixed
point after cluster modules finish merging. Two cluster modules cannot supply
different `package` values for the same instance without resolving the module
conflict.

The instance name and namespace do not need to match the package's attribute
name. They determine resource naming and dependency-resolution context for this
particular evaluation.

## `availability`

Set `instances.<namespace>.<instance>.availability` to override
`cluster.availability.default` for one instance:

```nix
instances.apps.preview = {
  package = packages.echo-server;
  availability = "none";
};
```

| Property | Value |
| --- | --- |
| Type | `null` or `"none" \| "pod" \| "node" \| "zone"` |
| Default | `null`, which uses `cluster.availability.default` |
| Upper bound | `cluster.availability.substrate` |

An override may be higher or lower than the cluster default, provided the
substrate supports it. A package's [`meta.availability.max`](/docs/reference/package-schema/meta/#availability)
may lower the resolved level further and emits a warning when it does. A
workload's own `availability.max` on its builder call lowers the level for that
workload only.

The resolved value is passed to the package as its `availability` argument and
controls derived placement and PodDisruptionBudgets. Explicit instance options,
including replica counts, still override package defaults derived from the
level, except that a replica count above one under a `none` ceiling is an
evaluation error.

## `labelStyle` and `selectorLabels`

Kubernetes workload `spec.selector.matchLabels` is immutable after creation.
When adopting an existing Deployment or StatefulSet into Kix, use `labelStyle`
or `selectorLabels` so the rendered selector matches the live workload:

- `labelStyle = "kix"` (the default) generates `app.kubernetes.io/name` and
  `app.kubernetes.io/instance` selector labels.
- `labelStyle = "helm"` generates `app` and `release` selector labels matching
  classic Helm chart conventions.
- `selectorLabels` overrides the auto-generated selector labels with an exact
  attribute set of strings when the live workload uses custom selector keys.

## `extraDeps` and `platformIntents`

Both fields apply only to import instances (`package = kix.mkImport { ... }`):

- `extraDeps` adds explicit deployment-ordering dependencies to the import's
  `PackageInstance` marker when no Nix string context connects the import to
  an upstream resource or instance. Each entry must be a Kix resource or
  `ref.<namespace>.<instance>`. Setting a non-empty `extraDeps` list on a
  managed instance is an evaluation error.
- `platformIntents` declares enforcer-agnostic network connectivity intents for
  the pre-installed pods represented by the import, using the same schema as
  [`networkPolicy.platformIntents`](/docs/reference/cluster-module/networkpolicy/).
  When a network policy enforcer is active in the cluster, Kix materializes
  these intents into policy resources and attaches them as dependencies on the
  import marker.

## `version`

`version` (`null` or `string`, default `null`) records an optional version
string on the instance configuration. Package version compatibility checks read
the package's [`meta.version`](/docs/reference/package-schema/meta/#version)
(or `out.version` on an import).
