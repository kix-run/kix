Use kind to run a Kubernetes cluster in Docker for local Kix development. The
`kix-examples` repository includes a single-node kind configuration and clusters
that are safe to deploy together.

This guide assumes Docker, kind, kubectl, and the Kix CLI are installed.

## Create the cluster

From the `kix-examples` repository, create the configured cluster:

<Command
  commands={["kind create cluster --config kind-config.yaml"]}
  cwd="kix-examples/"
/>

The configuration names the cluster `kix-demo`. Kind creates the kubectl
context `kind-kix-demo` and selects it as the current context.

Confirm that kubectl can reach the API server:

<Command {...clusterInfo} />

If another context is current, select the kind context explicitly:

<Command commands={["kubectl config use-context kind-kix-demo"]} />

## Check the cluster definition

Validate the example before connecting Kix to Kubernetes:

<Command {...check} />

This evaluates the cluster and runs its configured validation without applying
resources.

## Deploy the application

Deploy the cluster and accept the plan:

<Command expandable {...deployApplication} />

Kix builds the manifests, compares them with the current activation, applies
resources in dependency order, waits for readiness, runs the production health
check, and records the new activation.

The captured deployment ends with the activation becoming `Active`. A failed
resource or post-deploy check prevents that transition.

## Inspect the result

Check the namespaces and workloads with kubectl:

<Command {...getNamespaces} />

<Command {...getWorkloads} />

Use Kix to see the status associated with the cluster definition:

<Command {...status} />

## Remove the local cluster

When you no longer need it, delete the kind cluster:

<Command commands={["kind delete cluster --name kix-demo"]} />

This removes the local Kubernetes cluster and everything deployed into it. It
does not change the files in `kix-examples`.
