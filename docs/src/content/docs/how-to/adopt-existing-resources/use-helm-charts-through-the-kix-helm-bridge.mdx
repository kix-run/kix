Use `kix.helmChart` when you need to fetch, render, and deploy an upstream
Helm chart that does not have a native Kix package yet.

:::caution[Helm is a fallback bridge]
Wrapping a Helm chart brings its rendered YAML into Kix's deploy graph, but you
give up several guarantees that native Kix packages provide: `config.values` is
an untyped attribute set rather than a validated option schema, intra-chart
dependencies and network policies rely on YAML heuristics rather than `.out`
references, `cluster.availability` does not scale or spread workloads
automatically, and upstream chart defaults often require patching or exemptions
to pass Kix scorecard rules. Prefer native Kix packages whenever one is
available; see
[Helm is a fallback, not the target model](/docs/explanation/helm-integration/#helm-is-a-fallback-not-the-target-model)
for the full trade-offs.
:::

This guide uses the Reflector chart. You need the chart repository, chart name,
version, and SRI hash.

## Add the chart instance

The version and hash pin the chart archive. `releaseName` controls the release
name passed to Helm and therefore affects names generated by the chart.

Pass chart values under the instance's `config.values` attribute, using the
option names and value types documented by the upstream chart.

## Check the rendered chart

Evaluate the cluster and run Kix's validation checks:

<Command {...check} />

Inspect one of the resources produced by the chart:

<Command {...deployment} />

The rendered Deployment carries Kix's cluster and package metadata. Kix also
reconstructs dependencies between the chart's ServiceAccounts, RBAC resources,
Services, and workloads.

## Deploy the chart

Deploy and inspect the package instance:

<Command
  commands={[
    "kix deploy how-to-helm-bridge",
    "kix status how-to-helm-bridge",
    "kubectl get deployment -n reflector-system reflector",
  ]}
  cwd="kix-examples/"
/>

When you update the chart, change `version` and `hash` together, run `kix check`,
and review `kix diff` before deploying.

Kix picks the chart's root resource: the only Service, or, with no
Service, the only Deployment, StatefulSet, or DaemonSet. When the chart
renders several, evaluation fails and lists them; name the one consumers
connect to with `root = { kind = "Service"; name = "<name>"; };` in the
`kix.helmChart` arguments. Charts that need output builders or
cross-chart dependencies should use a dedicated Kix package built with
`scope.helm.importChart`.
