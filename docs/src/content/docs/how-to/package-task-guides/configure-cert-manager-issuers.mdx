Use the `cert-manager` and `cluster-issuers` packages together to install
cert-manager and make a `ClusterIssuer` available to application packages.

This guide creates a self-signed issuer for local development. It assumes the
target Kubernetes version is 1.21 or newer.

## Add cert-manager and an issuer

Add both instances to the same namespace:

<Snippet {...certManagerAndIssuer} />

The `cluster-issuers` package depends on `certManager`, so Kix connects it to
the cert-manager instance and orders the issuer after cert-manager's CRDs.

`lib.mkForce` replaces the package's default issuer set. `mainIssuer` must name
one of the entries in `issuers`; application packages use that issuer when
they request certificates through the `clusterIssuer` dependency.

For an ACME issuer, replace the self-signed entry with an `acme` entry that
sets `server`, `email`, `privateKeySecretName`, and `cloudflareSecret`. Set
`dnsZones` when the Cloudflare solver should handle only particular zones.

## Check the issuer

Evaluate the cluster before deploying it:

<Command {...check} />

Inspect the generated issuer:

<Command {...issuer} />

The empty `selfSigned` object is the complete cert-manager configuration for a
self-signed issuer.

## Deploy and verify readiness

Deploy the cluster, then ask Kubernetes for the issuer condition:

<Command
  commands={[
    "kix deploy how-to-package-cert-manager",
    "kubectl get clusterissuer local-self-signed",
  ]}
  cwd="kix-examples/"
/>

The issuer is ready when the `READY` column is `True`. If it is not ready,
inspect its conditions and cert-manager controller logs:

<Command
  commands={[
    "kubectl describe clusterissuer local-self-signed",
    "kubectl logs -n cert-manager deployment/cert-manager",
  ]}
/>

For ACME issuers, also confirm that the named Cloudflare API token Secret
exists and contains the configured key.
