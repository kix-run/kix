import Command from '/src/components/Command.astro';
import exportCluster from '/src/command-output/how-to/application-export-exit/export.json';
import exportFiles from '/src/command-output/how-to/application-export-exit/files.json';
import noAnnotations from '/src/command-output/how-to/application-export-exit/no-annotations.json';

Use `kix export` when you need a directory of Kubernetes manifests without
Kix's deployment records. The default export mode removes Kix annotations and
omits `Activation` and `PackageInstance` resources.

## Export the cluster

Choose an output directory with `--out`:

<Command {...exportCluster} />

Kix evaluates and builds the cluster before writing the files. It does not
connect to Kubernetes.

The output is grouped by namespace. Cluster-scoped resources are written
under `_cluster`:

<Command {...exportFiles} />

Each filename contains the resource kind and name, such as
`how-to-app/Deployment-production.yaml`.

Exit mode drops the `Activation` and `PackageInstance` objects themselves, but
not the two CustomResourceDefinitions that declare those kinds. Those are
ordinary cluster-scoped resources in the cluster's graph, so they export like
any other, which is why they appear under `_cluster` above. Delete them by
hand if the receiving system should carry nothing of Kix's.

## Review the export

Compare the files with a live cluster before handing them to another system:

<Command
  commands={["kubectl diff --server-side -R -f ./handoff/"]}
  cwd="kix-examples/"
/>

Then confirm no Kix annotation survived the export. The search finds nothing
and exits with status 1, which is the result you want here:

<Command {...noAnnotations} />

That pattern matches annotation keys, which all end in a slash. It does not
match the two CRD names, where `kix.run` is a bare suffix.

Labels such as `app.kubernetes.io/managed-by` remain part of the resource
metadata, so review and adjust labels if the receiving system has its own
ownership convention.

## Export again

Kix refuses to write into an existing output directory. Remove or archive the
previous export, or pass `--force` when replacing it is intentional:

<Command
  commands={[
    "kix export how-to-application --out ./handoff --force",
  ]}
  cwd="kix-examples/"
/>

`--force` only lifts the refusal. Every file the new export writes replaces
the old one, but nothing removes a file the previous export wrote and this one
does not. A resource you deleted from the cluster stays behind as stale YAML,
and the `kubectl apply -R -f ./handoff/` that the receiving system runs would
recreate it. Export into a fresh directory, or delete the old one first.

:::note[Reference]
See [`kix export`](/docs/reference/cli/export/) for the exact modes, directory
layout, and options.
:::
