import auditExport from '/src/command-output/how-to/application-export-audit/export.json';
import internalCrs from '/src/command-output/how-to/application-export-audit/internal-crs.json';

Use `kix export --with-kix-metadata` when the exported manifests need to retain the Kix
metadata that connects resources to packages, dependencies, and an
activation. This export is intended as evidence or as input to an audit
process.

## Create the audit export

Pass `--with-kix-metadata` and choose an output directory:

<Command {...auditExport} />

Kix evaluates and builds the cluster locally. The export includes every
rendered resource, including `Activation` and `PackageInstance` custom
resources, and preserves its `kix.run/*` annotations.

## Inspect the provenance metadata

Exported manifests preserve their `kix.run/identity-hash`, `kix.run/package`,
and `kix.run/package-namespace` annotations (plus `kix.run/depends-on` on
resources that have dependencies), which record resource identity, package
membership, and dependency edges. The export also writes `Activation` and `PackageInstance` manifests into
the directory tree, with the `Activation` resource under `_cluster/` serving as
the root of the rendered deployment graph:

<Command {...internalCrs} />

## Keep audit and handoff exports separate

Do not use the audit export when another deployment system needs ordinary
application manifests. Its internal custom resources and Kix annotations are
part of the evidence being preserved.

Leave out `--with-kix-metadata` for that workflow:

<Command
  commands={["kix export how-to-application --out ./handoff"]}
  cwd="kix-examples/"
/>

:::note[Use it in a task]
See [Export plain YAML](/docs/how-to/operate-a-cluster/export-plain-yaml/) when
you need manifests for handoff or application by another tool.
:::

:::note[Reference]
See [`kix export`](/docs/reference/cli/export/) for exactly what each export
keeps.
