If you compare builds against saved snapshots, run `kix snapshot` again so each snapshot includes the new `kix-snapshot.json` state file. `kix diff --from <snapshot>` now reports no differences for a snapshot taken right after a deploy. Previously, it listed every object as changed because Kix no longer writes build annotations such as `kix.run/identity-hash` to live cluster objects. `kix snapshot` now writes `kix-snapshot.json` alongside the YAML files, saving the deployment records, the revisions recording what Kix applied, and each live object with `Secret` values redacted. With `kix-snapshot.json` present, `kix diff --from` runs the same comparison as `kix plan --read-only`, including drift and orphan checks, without reporting false differences on `Secret` values or fields modified by the API server. Without `kix-snapshot.json` (for example, in an older snapshot or a `kix export` directory), `kix diff --from` matches objects by kind, namespace, and name against what `kix deploy` sends, which can show `Secret` values and fields modified by the API server as differences. Snapshot YAML files now include only the current `Activation` record, and diffing against a manifest directory no longer marks resources `"tracking annotation only"` when only a dependency changed. The closing note of a comparison with a snapshot or another saved directory now says it compared saved objects, not the cluster.
