If you compare builds against saved snapshots, run `kix snapshot` again so each snapshot includes the new `kix-snapshot.json` state file. `kix diff --from <snapshot>` now reports no differences for a snapshot taken right after a deploy. Previously, it listed every object as changed because Kix no longer writes build annotations such as `kix.run/identity-hash` to live cluster objects. `kix snapshot` now writes `kix-snapshot.json` alongside the YAML files, saving Kix's deployment records, what Kix last applied, and each live object with `Secret` values redacted. Snapshot YAML files now include only the current `Activation` record. With `kix-snapshot.json` present, `kix diff --from` runs the same comparison as `kix plan --read-only`, checking drift and removed objects without false differences on redacted `Secret` values or fields changed by the API server. Without `kix-snapshot.json` (for example, in an older snapshot or a `kix export` directory), `kix diff --from` matches YAML files by kind, namespace, and name against what `kix deploy` sends, so those false differences can still appear. Against a snapshot or manifest directory, `kix diff --from` no longer marks resources `"tracking annotation only"` when only a dependency changed. Its closing note now states that it compared saved files without reading the cluster.
