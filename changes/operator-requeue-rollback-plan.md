`kix rollback --operator` now restores the target deployment record as the cluster's current deployment and marks the previous record `Superseded`, matching `kix rollback`. Previously it overwrote the current record to point at the earlier build, which made `kix history` list that build twice. Running `kix deploy --operator` when the build is already deployed now redeploys the build and waits for the Kix operator to finish instead of returning immediately. In both cases, the operator reruns any failed Job marked `kix.run/rerun`, matching `kix deploy` and `kix rollback`. To track each run, `kix deploy --operator` and `kix rollback --operator` write a request token to `spec.request` on the deployment record, and the operator updates `status.startedRequest` and `status.finishedRequest`. Records without `spec.request`, including those written without `--operator` or by earlier versions of Kix, continue to work unchanged. `kix rollback` also now shares `kix deploy`'s plan preview, refusal advice, confirmation prompt, and closing summary, so it shows live cluster drift before applying and lists failed resources and record status if the rollback fails.
