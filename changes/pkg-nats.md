The new experimental package `packages.experimental.nats` deploys NATS 2.15.3 with JetStream persistence as a StatefulSet with one volume per pod. It runs a single standalone server by default, or a cluster of 3 or more servers (an odd count) when `clustered = true`. Kix rejects availability levels that conflict with `clustered` because NATS cannot switch a server with stored data between standalone and clustered modes in place without losing streams; back up streams with `nats stream backup`, change `clustered` and deploy, then restore them with `nats stream restore`. Every instance requires a `natsAuth` secret in the same namespace with `username` and `password` keys for client login. Consumers in the same namespace or connected across namespaces with `ref` read `out.url` or `out.host` for client port 4222 and `out.monitoringHost` for monitoring port 8222, and generated network policy opens only the port each consumer reads. Each instance also runs a `prometheus-nats-exporter` sidecar (with Prometheus alerts when a `prometheus` provider is configured) and a post-deploy check that publishes and reads back a test message.
