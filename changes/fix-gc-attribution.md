Pass `--include unattributed` to `kix gc --full-scan` to delete stale Kix-labeled objects that do not match any deployment record on the cluster. By default, `kix gc --full-scan` now lists these objects under "Objects with no matching deployment record" and keeps them, and the Kix operator leaves them alone too, even when only one Kix cluster has deployment records on the Kubernetes cluster. Earlier versions could mistake another Kix cluster's remaining objects for their own and delete them once that cluster's deployment records were deleted. With `--include unattributed`, `kix gc --full-scan` compares unattributed objects against the active deployment's build (or the build from your local files if no deployment is active) and deletes any that are not in it. Objects left behind by an earlier deploy or rollback without `--prune` do not need this flag. While the active deployment record tracks them in its kept-orphans `PackageInstanceRevision` (or a record written by an earlier version lists their build in `status.orphansKeptFrom`), `kix gc --full-scan` still attributes them to that Kix cluster and deletes them even after `kix gc` retires the record that deployed them. An object has no matching record when `kix gc` retired its deployment records and no remaining record tracks it as a kept orphan, when an earlier version of Kix applied it before `kix.run/activations` existed, or when it belonged to another Kix cluster whose deployment records were deleted.
