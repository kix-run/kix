Only one run at a time changes a Kix cluster. Each Kix cluster gets one `ActivationHead` object (`activationheads.kix.run`, named after the cluster) that holds its deploy lock, names the deploy record the cluster runs, and names the Kix that wrote to the cluster last. `kix deploy` (with and without `--only`), `kix rollback`, `kix gc`, `kix migrate domain`, and the Kix operator take the lock before they change the cluster, and create the head's CustomResourceDefinition when the cluster does not have it. A run that finds the lock held watches it for up to 30 seconds: it stops with exit code 1 and names the other run when that run renews the lock, and takes the lock over when nothing renews it, marking a record the stopped run was deploying `Failed`. A run that cannot renew its lock stops writing 20 seconds after its last renewal. A deploy refuses when another run changed the cluster between its plan and the moment it takes the lock, and `kix deploy --plan` refuses a saved plan of an earlier lock generation. `kix status` and `kix plan` show who holds the lock and say when that run has probably stopped. The checks for required stops and for an older Kix read the head's writer, and `kix gc` now makes both checks. A deploy that stops between naming its record on the head and setting the records' phases has its phases set by the next run.
