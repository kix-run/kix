Kix now uses a deploy lock so only one run can change a Kix cluster at a time. Each Kix cluster has an `ActivationHead` resource (`activationheads.kix.run`, named after the cluster) that holds the lock, names the active deployment record, and records the Kix version that last changed the cluster. `kix deploy` (with or without `--only`), `kix rollback`, `kix gc`, `kix migrate domain`, and the Kix operator create the `activationheads.kix.run` CRD if needed and take the lock before changing the cluster. If another run holds the lock, Kix watches it for up to 30 seconds: if the holder renews its lease, Kix exits with code 1 and identifies that run; if nothing renews the lease for 30 seconds, Kix takes over the lock and marks any other record the stopped run was deploying as `Failed`. Any run that cannot renew its lease stops writing 20 seconds after its last renewal. Commands also stop if another run changed the cluster between planning and taking the lock, and `kix deploy --plan` rejects saved plans from an earlier lock generation. `kix status` and `kix plan` show any active lock holder and note when its lease has expired. Required-stop and version-downgrade checks now read the last writer from `ActivationHead`, `kix gc` now runs both checks, and if a deploy stops after recording the new active deployment on `ActivationHead` but before updating record phases, the next run repairs those phases.
