No changes to cluster definitions are needed. `kix check`, `kix build`, `kix plan`, `kix deploy`, and other commands that build a cluster now show warnings from the Kix library that Kix previously hid when evaluation succeeded. These cover `LoadBalancer` Services when `cluster.roles.loadBalancer.binding` is not set, `HorizontalPodAutoscaler` objects when `cluster.roles.metricsApi.binding` is not set, `DaemonSet` and privileged workloads when the matching `cluster.capabilities` option is not set, multi-replica workloads whose pod spread rules require multiple nodes when `cluster.capabilities.multiNode` is not set, workloads capped by `availability.max`, workloads that reference a `Service` without using its address, and route and network policy warnings from `kix.expose`. Because `kix.run/built-via` on the `Activation` object points to a build index that includes the warning list, the first deploy after upgrading updates `Activation` on any cluster that gains one of these warnings. Workloads and other resources do not change.
