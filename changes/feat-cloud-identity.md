library = ["kix.cloudIdentity", "kix.mkImport", "kix.flavors.eks"]

Packages that call AWS, Google Cloud, or Azure APIs (starting with `packages.experimental.external-dns`) can now authenticate through their Kubernetes ServiceAccount instead of a Secret by taking a cloud identity in `deps`: `kix.cloudIdentity.aws { roleArn = "..."; }`, `kix.cloudIdentity.gcp { }` (with optional `serviceAccount`), or `kix.cloudIdentity.azure { clientId = "..."; }` (with optional `tenantId`). Kix writes the required ServiceAccount annotations and pod labels and restarts pods when the identity changes. `kix.flavors.eks`, `kix.flavors.gke`, `kix.flavors.gke-autopilot`, and `kix.flavors.aks` configure this automatically; on EKS, `cluster.flavor.eks.cloudIdentity = "pod-identity"` switches from IAM roles for service accounts (IRSA) to EKS Pod Identity, and self-managed clusters can declare a `cloudIdentity` import using `kix.cloudIdentity.irsa`, `kix.cloudIdentity.eksPodIdentity`, `kix.cloudIdentity.gke`, or `kix.cloudIdentity.azureWorkloadId`. Package authors can support cloud identities with `kix.cloudIdentity.use` (or `kix.cloudIdentity.annotationsFor` when an operator creates the ServiceAccount), and `kix.mkImport` now accepts `annotationDomains` for annotations read by controllers outside Kix.
