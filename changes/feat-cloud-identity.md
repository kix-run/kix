Packages that call AWS, Google Cloud, or Azure APIs (starting with `packages.experimental.external-dns`) can now authenticate through their Kubernetes ServiceAccount instead of a Secret. Pass `kix.cloudIdentity.aws { roleArn = "..."; }`, `kix.cloudIdentity.gcp { }` (with optional `serviceAccount`), or `kix.cloudIdentity.azure { clientId = "..."; }` (with optional `tenantId`) to the package's credentials dependency in `deps`. Kix writes the required ServiceAccount annotations and pod labels, and restarts pods when the identity changes. `kix.flavors.eks`, `kix.flavors.gke`, `kix.flavors.gke-autopilot`, and `kix.flavors.aks` enable this automatically. On EKS, set `cluster.flavor.eks.cloudIdentity = "pod-identity"` to use EKS Pod Identity instead of IAM roles for service accounts (IRSA). On self-managed clusters running the AWS or Azure workload identity webhook, add `kix.modules.experimental.irsa-webhook` or `kix.modules.experimental.azure-workload-identity-webhook` to `modules` alongside the flavor. Package authors can support cloud identities with `kix.cloudIdentity.use` (or `kix.cloudIdentity.annotationsFor` when an operator creates the ServiceAccount), and `kix.mkImport` now accepts `annotationDomains` for annotations read by external controllers.
