`external-secrets` now runs External Secrets Operator v2.15.0 instead of v2.11.0. The first deploy restarts the controller, the webhook, and the cert-controller once and updates the 25 custom resource definitions with new optional fields. Existing ExternalSecrets, stores, and the Secrets they wrote carry over unchanged. Upstream recommends upgrading one minor version at a time, and this deploy moves four minor versions at once. No release from v2.12 to v2.15 changes a stored API version or needs a migration step. Some failures now look different. Events and PushSecret status conditions give less detail about provider errors, and the controller log keeps the full error. The controller refuses to write a Secret whose assembled form is a service account token or keeps a bootstrap token type. A templated value larger than 1 MiB fails to render. A webhook provider response larger than 10 MiB fails to sync, and the controller flag `--webhook-provider-max-response-size`, set through `extraArgs`, raises that limit. To go back, deploy the previous Kix version. The v2.11.0 controller reads the objects that v2.15.0 left behind, and the API server drops fields that only v2.15.0 defines, such as the Password generator's `prefix`, from the objects that set them.
