With `networkPolicy.enable = true`, Kix now writes `<namespace>-default-deny` only in namespaces that hold at least one active instance Kix deploys, or that the cluster definition declares under `namespaces`. A namespace that holds only imports (`kix.mkImport`, such as a flavor's `kube-system/platform-dns`) or only inactive `optional` instances loses its default-deny policy on the next deploy, and its pods accept and send all traffic again. To keep the policy there, declare the namespace: `namespaces.<name> = { };`. The new option `networkPolicy.platformNamespaces` lists namespaces that never get a default-deny policy. The `gke`, `gke-autopilot`, `eks`, and `aks` flavors set it to `[ "kube-system" ]`, so on those flavors `kube-system` loses its default-deny policy even when Kix deploys a workload there. That workload keeps its own policies. To keep the old behavior, set `networkPolicy.platformNamespaces = [ ];`. In a namespace without a default-deny policy, a Prometheus or VMAgent scrape target gets scrape ingress only when another policy already isolates its pods. None of the clusters in this repository change.
