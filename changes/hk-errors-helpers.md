Cluster definitions that use only built-in packages need no changes. In custom packages that call `kix.mergeGuarded`, `kix.mergeEnv`, `kix.guardArgs`, `kix.storage.mkClasses`, `kix.checkSecretKeys`, `kix.contracts.secret.helpers.use`, `kix.contracts.smtp.helpers.server`, `kix.contracts.smtp.helpers.settings`, or `kix.contracts.oidc.helpers.client`, remove `who` and pass `inherit scope;` (passing `who` now fails evaluation). A contract's `check` and `require`, and `kix.contracts.redis.helpers.requirePlaintext`, take `scope` in place of the `who` text, as in `kix.contracts.postgresDatabase.check scope { ... }`. A contract's `assertions` takes only the dependency, as in `deps.database.assertions = kix.contracts.postgresDatabase.assertions;`. `kix.contracts.experimental.gatewayApi.helpers.crdsFor` takes `scope`, and its `errorsFor` takes no `who`. Passing text in place of `scope` or the dependency fails with this id. In `kix.mergeGuarded`, rename `what` to `option` (passing `what` fails with `[K0998]`). In `kix.storage.mkClasses`, pass `optionPath` without a `config.` prefix, such as `"classes"`. All four helpers now report errors through `scope.fail`, which sets both `instance` and `package` for built-in packages in error output and `kix check -o json`. `kix.mergeGuarded` and `kix.mergeEnv` (when an `owned` entry omits `fix`) now tell users to remove disallowed fields or variables from that option. `kix.mergeGuarded` also accepts `object` to identify a Kubernetes resource, and `option = null` when overrides do not come from an instance option. `kix.mergeEnv` accepts `option` (default `"env"`) to name the option in errors, and its `owned` entries accept `reason` instead of `from` when a package rejects an environment variable outright.
