If your cluster uses only built-in packages, no changes are needed. If you maintain custom packages, update calls to library and contract helpers that previously took `who`; passing `who` (or passing a string where `scope` or a dependency is expected) now fails evaluation with `[K6417]`. Remove `who` and pass `inherit scope;` in `kix.mergeGuarded`, `kix.mergeEnv`, `kix.guardArgs`, `kix.storage.mkClasses`, `kix.checkSecretKeys`, `kix.contracts.secret.helpers.use`, `kix.contracts.smtp.helpers.server`, `kix.contracts.smtp.helpers.settings`, `kix.contracts.oidc.helpers.client`, and `kix.contracts.experimental.gatewayApi.helpers.crdsFor`. Remove `who` from `kix.contracts.experimental.gatewayApi.helpers.errorsFor`. Pass `scope` instead of `who` to `<contract>.check`, `<contract>.require`, `<contract>.requireAs`, and `kix.contracts.redis.helpers.requirePlaintext` (for example, `kix.contracts.postgresDatabase.check scope { ... }`), and pass only the dependency to `<contract>.assertions` (for example, `deps.database.assertions = kix.contracts.postgresDatabase.assertions;`). Also rename `what` to `option` in `kix.mergeGuarded` (passing `what` fails with `[K0998]`), and pass `optionPath` without a `config.` prefix in `kix.storage.mkClasses` (such as `"classes"`). These helpers now report errors through `scope.fail`, which populates `instance` (and `package` for built-in packages) in terminal output and `kix check -o json`. In addition, `kix.mergeGuarded` now tells users to remove locked fields from `option` and accepts `object` (to name a Kubernetes resource) and `option = null` (when overrides do not come from an instance option). `kix.mergeEnv` accepts `option` (default `"env"`), tells users to remove claimed variables from `option` when an `owned` entry omits `fix`, and accepts `reason` instead of `from` on `owned` entries that reject a variable outright.
