Cluster definitions that use only built-in packages need no changes. Custom packages must update calls to library and contract helpers that previously took a `who` string (passing `who`, or passing text in place of `scope` or a dependency, now fails evaluation with `[K6417]`). In `kix.mergeGuarded`, `kix.mergeEnv`, `kix.guardArgs`, `kix.storage.mkClasses`, `kix.checkSecretKeys`, `kix.contracts.secret.helpers.use`, `kix.contracts.smtp.helpers.server`, `kix.contracts.smtp.helpers.settings`, `kix.contracts.oidc.helpers.client`, and `kix.contracts.experimental.gatewayApi.helpers.crdsFor`, remove `who` and pass `inherit scope;`. In `kix.contracts.experimental.gatewayApi.helpers.errorsFor`, remove `who`. In `<contract>.check`, `<contract>.require`, `<contract>.requireAs`, and `kix.contracts.redis.helpers.requirePlaintext`, pass `scope` instead of `who`, as in `kix.contracts.postgresDatabase.check scope { ... }`. In `<contract>.assertions`, pass only the dependency, as in `deps.database.assertions = kix.contracts.postgresDatabase.assertions;`. In `kix.mergeGuarded`, also rename `what` to `option` (passing `what` fails with `[K0998]`). In `kix.storage.mkClasses`, pass `optionPath` without a `config.` prefix, such as `"classes"`. These helpers now report errors through `scope.fail`, which sets `instance` (and `package` for built-in packages) in error output and `kix check -o json`. When an `owned` entry omits `fix`, `kix.mergeGuarded` and `kix.mergeEnv` now tell users to remove disallowed fields or variables from that option. `kix.mergeGuarded` also accepts `object` to identify a Kubernetes resource, and `option = null` when overrides do not come from an instance option. `kix.mergeEnv` accepts `option` (default `"env"`) to name the option in errors, and its `owned` entries accept `reason` instead of `from` when a package rejects an environment variable outright.
