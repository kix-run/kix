`caddy` now runs Caddy 2.11.9 instead of 2.10.0. Caddy keeps the certificates and keys it stored in `/data`, and deploying the older package again reads what 2.11.9 wrote. Some requests now get a different result with no error. A request whose headers exceed 16 KiB gets `431`, so raise `max_header_size` in the Caddyfile's server options if your clients send large cookies or tokens. Caddy drops request headers whose names contain `_` or `.`, unless the Caddyfile lists them in `expected_underscore_headers` or `expected_dot_headers`. A request body read or a response write that stalls for one minute ends the connection, which `read_body_idle` and `write_idle` change. A site no longer inherits `client_auth` from a wildcard site, so set `client_auth` on each site that needs it. Caddy 2.11 also refuses some Caddyfiles that 2.10 accepted, such as two `expression` lines in one matcher set or an unknown TLS `protocol_min`. The new pod then fails to start and the old pod keeps serving. Read the breaking changes in the release notes of Caddy 2.11.6, 2.11.8, and 2.11.9 before you upgrade. The release also fixes many security issues, most of them in `php_fastcgi`, `file_server`, and the admin API.
