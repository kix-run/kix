Evaluation errors and warnings now include more context and clearer fixes. Duplicate-resource errors name the instances that build the same object and explain how to fix the collision. `scope.forNamespace` errors name the calling instance and list the cluster's declared namespaces. Dependency errors on an instance pulled from `availablePackages` name the instances that needed it. Errors for a missing cluster role list the built-in packages that provide that role, and `meta.conflictsWith` errors explain how to resolve the conflict. When multiple packages in `availablePackages` match a dependency, Kix reports every ambiguous dependency in one run. The suggested `instances` lines keep the namespace, name, and aliases Kix uses when adding the package automatically, preserving existing instances and their data. Scrape network-policy warnings now set `instance` and `object` to the scraper resource and the instance that built it. For package authors, `meta.availability` and `availability` on workload builders accept an optional `reason` string alongside `max`, and `meta.conflictsWith` entries accept `{ key; reason; }`. Kix includes `reason` in availability and conflict messages, and `tailscale` now explains why only one instance can run per cluster. Failed assertions in `deps.<name>.assertions` now set `dependency` to `<name>`. A contract's `require` validator sets `dependency` to the contract's `alias`, and the new `requireAs` validator takes a custom dependency name.
