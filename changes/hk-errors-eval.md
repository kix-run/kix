Packages can now explain availability ceilings and instance conflicts: `meta.availability` and workload-builder `availability` accept an optional `reason` alongside `max`, and `meta.conflictsWith` entries accept `{ key; reason; }`. Kix includes `reason` in the corresponding warnings and errors, and `tailscale` now explains why only one instance can run per cluster. Evaluation diagnostics also give clearer context and fixes. Duplicate-resource errors name the instances that build the colliding object, and `scope.forNamespace` errors name the instance that requested a missing namespace. Dependency errors on a package added from `availablePackages` name the instances that required it. Errors for a missing cluster role list the packages that provide that role, and `meta.conflictsWith` errors explain how to resolve the conflict. When multiple packages in `availablePackages` match a dependency, the suggested `instances` lines use the same namespace, name, and aliases that auto-instantiation chooses, preserving existing instances and their data. Assertions in `deps.<name>.assertions` now set `dependency` to `<name>`. A contract's `require` sets it to the contract's alias, and the new `requireAs` takes the dependency name for a consumer that uses another one. When several packages in `availablePackages` match dependencies, Kix reports every such dependency at once. Scrape warnings in `kix-warnings.json` set `object` and `instance` to the scraper and the instance that built it.
