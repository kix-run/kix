`clickhouse`, `clickhouse-cluster`, and `clickhouse-keeper` now run ClickHouse 26.8.39.19, the August 2026 LTS release, instead of 26.3.33.24 (26.3.32.14 for Keeper). `clickhouse-database` runs its setup Job with the same image. The first deploy after you upgrade restarts every ClickHouse and Keeper pod once. The operator restarts the replicas of `clickhouse-cluster` and `clickhouse-keeper` one at a time. ClickHouse 26.8 reads the data that 26.3 wrote. Several defaults change between 26.3 and 26.8, so some queries can return different results. Read the "Backward Incompatible Change" sections of ClickHouse's release notes for 26.4 to 26.8 before you upgrade. For example, `max_insert_threads` now defaults to the number of CPU cores, and `date_time_input_format` now defaults to `best_effort`. On amd64 nodes, ClickHouse 26.8 needs a CPU with AVX2 support. If your `serverConfig` sets `insert_deduplication_version`, remove it before you upgrade: 26.8 does not start with any value other than `new_unified_hash`. Until every replica reports 26.8, do not run DDL or a lightweight `UPDATE`, because 26.8 writes `UPDATE` changes in a format that 26.3 cannot read. To go back, deploy the previous Kix release, for example with `kix rollback`. Going back works only if you have not used a feature that is new in 26.8, and not after a lightweight `UPDATE` on 26.8.
