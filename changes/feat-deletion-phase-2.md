`kix status`, `kix plan --prune`, and `kix gc` now show more detail when Kubernetes is still deleting an object. `kix status` reports any deleting object in the current deploy as `being deleted` under every check (instead of `not ready` or `changed`), showing when deletion started and which finalizers hold it. It also lists deleting objects from outside the current deploy under `Not in the current deploy, still being deleted`. In `kix status -o json` and `-o yaml`, `problems` uses `deleting` instead of `not_ready` or `changed`, resources add `deleting_since` and `finalizers`, clusters add `leaving`, and every `summary` adds `deleting` and `leaving`. `kix plan --prune` and `kix deploy --prune` now list each pruned object that has finalizers or is already being deleted. When a custom resource's kind declares a `controller` (on `scope.mkCRD` or `scope.mkCRDRef`) that is not ready, missing from the cluster, or unreadable, the plan warns without changing the exit code. Plan `prune` entries add `finalizers`, `deleting_since`, and `controllers`. `kix gc` now accepts `--timeout` (except with `--operator`) to set how long it waits for a deleted object while no finalizer is removed (`3m` by default, and at most 5 minutes in total per object).
