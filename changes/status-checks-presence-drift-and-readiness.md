`kix status` now runs three checks on every object of a cluster's current deploy: is it on the cluster, does it still hold what Kix applied, and is it ready. It shows one line per package and lists only the objects with a problem. `-v` lists every object, `-q` prints only the problems, `--check presence|drift|readiness` runs only the checks you name, and `--package` shows one package. It exits 0 when every check passes, 2 when an object is missing, changed, or not ready, and 1 when Kix cannot answer. Before, it exited 0 whatever it found, so a script that runs `kix status` must now accept exit code 2. `-o json` prints one object with a `schema_version`, the clusters, their packages, and each object's facts, in place of a bare list of objects. The cluster name is now optional: without it, `kix status` checks every Kix cluster that has a deploy on the Kubernetes cluster. It reads only the cluster, so it works outside a project and no longer evaluates the cluster definition. Objects of a kind your Kubernetes account may not list, such as Secrets, count as not checked, and Kix names the kinds. `kix health` and `kix drift` reported them as missing.
