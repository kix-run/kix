Run `kix deploy --operator` or `kix rollback --operator` again after you fix the cause of a failing Kix operator deploy that has reached `Failed` (about 5 minutes for a fast failure with the default retry limit), because the operator no longer finishes it automatically. Previously, when a deploy failed (for example, when the operator pod could not decrypt a SOPS file or a resource never became ready), the operator retried every 30 seconds forever and left the Activation record `Deploying`, so fixing the cause at any later time finished the deploy. An attempt also fails when the operator cannot read the build named by the record (for example, a build missing from the store the operator reads) or cannot list the cluster's objects. It now retries 10 times by default (11 attempts in total), waiting 30 seconds between attempts, and then marks the record `Failed` with the attempt count and last error. Set `KIX_DEPLOY_RETRIES` on the operator to change the retry limit (`0` stops after the first failure, matching `kix deploy`). While waiting, `kix deploy --operator` and `kix rollback --operator` print each failed attempt and exit with that error when the record becomes `Failed`. The operator stores the count in `status.failedAttempts` on the Activation record, so restarting the operator does not reset it.
