kind = "fixed"
cli = ["kix plan", "kix deploy", "kix rollback"]

An admission webhook that cannot reach its Service no longer stops every deploy with `service "..." not found` for each object it checks. When the same deploy writes that Service, or another object of the package that serves the webhook such as the operator's Deployment, the plan lists the objects under "Not checked by the dry run", with the reason `webhook_backend_written_by_this_deploy` in `-o json`, and the deploy goes ahead. When the deploy writes nothing of that package, `kix plan` reports a refusal and `kix deploy` stops before it writes anything, with a message that says the webhook's backend is down and that `kix deploy <cluster> --reconcile` creates a deleted Service again. A webhook that answers and denies a write still stops the deploy. `kix rollback` decides which objects stop it by the same rules as `kix plan`, so an object in a Namespace or of a CustomResourceDefinition that the rollback creates no longer stops it. The dry run no longer retries a request that a webhook could not answer, which took about 20 seconds for each object. Each entry under `not_checked` in the plan document has a new field, `because`, that names the Namespace, CustomResourceDefinition, or Service the answer depends on.
