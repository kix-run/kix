Existing EKS clusters need no changes. EKS clusters (`kix.flavors.eks`) can now generate standard Kubernetes `NetworkPolicy` objects for the Amazon VPC CNI add-on. To enable this, turn on `enableNetworkPolicy` in the Amazon VPC CNI add-on configuration, then set `cluster.flavor.eks.networkPolicy = "vpc-cni"` and `networkPolicy.enable = true`. Leaving `cluster.flavor.eks.networkPolicy` at its default `"none"` while `networkPolicy.enable = true` stops the build with setup instructions. When policies require them, also set `cluster.network.serviceCidr` or `cluster.network.apiServer.cidrs` for API server egress, `cluster.network.apiServer.sources` for admission webhooks and aggregated APIs, and `cluster.network.nodeCidrs` for rules targeting nodes. Because EKS nodes and pods share VPC subnets with VPC endpoints, load balancers, and databases, outbound `world` rules keep those subnets (`world-egress-node-subnets` and `world-egress-pod-subnets`, without requiring `cluster.network.podCidr`). The `security.networkPolicyWidened` scorecard rule warns whenever VPC CNI `ipBlock` rules allow extra pod, node, or Service traffic, and warns about the roughly one-second startup window before egress rules apply.
