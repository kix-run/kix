kind = "added"
packages = ["experimental/external-secrets"]
+++
Existing `external-secrets` instances need no changes. You can now give the External Secrets controller an AWS, Google Cloud, or Azure cloud identity by setting `deps.controllerCredentials` on `packages.experimental.external-secrets`, such as `deps.controllerCredentials = kix.cloudIdentity.aws { roleArn = "..."; }` (or `kix.cloudIdentity.gcp` or `kix.cloudIdentity.azure`). Kix writes the required ServiceAccount annotations and pod labels on the controller, and restarts the controller pods when the identity changes. To authenticate a `SecretStore` or `ClusterSecretStore` with that identity, leave `auth` unset on AWS and Google Cloud (`gcpsm`) stores, or set `authType: WorkloadIdentity` without `serviceAccountRef` on Azure (`azurekv`) stores. Every such store in the cluster shares the controller's identity, so any namespace that can create a `SecretStore` can read whatever the cloud role can read. `deps.controllerCredentials` accepts only a cloud identity and rejects Secret instances. To use static keys, reference a Secret in the store's spec (such as `auth.secretRef`, or `authSecretRef` on Azure).
