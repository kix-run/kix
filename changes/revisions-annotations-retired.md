Update any external scripts, policies, or admission rules that inspect Kix's tracking metadata. Match the Server-Side Apply field manager `kix/<cluster>` instead of `kix`. Read deployed object lists from the `PackageInstanceRevision` resources linked in an `Activation` record's `status.revisions` (each entry has the object's `kix.run/identity-hash`, API group, kind, namespace, and name) instead of from `kix.run/activations` or `status.packageIndex`. Read applied hashes from `status.applied` on those revisions (mapping each `kix.run/identity-hash` to the hash of the Kix-owned live fields) instead of from `kix.run/applied-hash`. Kix no longer writes `kix.run/activations` or `kix.run/applied-hash` on deployed objects, and no longer writes `status.packageIndex` or `status.orphansKeptFrom` on `Activation` records. On the first deploy after upgrading, Kix renames each object's `kix` field-manager entry to `kix/<cluster>` and removes the retired annotations. If another Kix cluster on the same Kubernetes cluster still uses an earlier version of Kix, shared objects keep their `kix` field-manager entry and retired annotations until both Kix clusters deploy with this version. Until then, changing a shared field stops with a field ownership conflict naming `kix`.
