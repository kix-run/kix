Update any external scripts, policies, or admission rules that inspect Kix's tracking metadata: match field manager `kix/<cluster>` instead of `kix`, read deployed object lists from the `PackageInstanceRevision` resources named in an `Activation` record's `status.revisions` (which list each object's `kix.run/identity-hash`, API group, kind, namespace, and name) instead of `kix.run/activations` or `status.packageIndex`, and read applied hashes from `status.applied` on those revisions (which maps each object's `kix.run/identity-hash` to the hash of the fields Kix applied) instead of `kix.run/applied-hash`. Kix no longer writes `kix.run/activations` or `kix.run/applied-hash` on deployed objects, or `status.packageIndex` and `status.orphansKeptFrom` on `Activation` records. On the first deploy after upgrading, Kix renames each object's `kix` field-manager entry to `kix/<cluster>` and removes the retired annotations. If another Kix cluster on the same Kubernetes cluster still uses an earlier version of Kix, shared objects keep their `kix` field-manager entry and retired annotations until both Kix clusters have been deployed with this version; until then, changing a shared field stops with a field ownership conflict naming `kix`.
