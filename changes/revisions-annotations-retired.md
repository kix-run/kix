Update any external scripts, policies, or admission rules that inspect Kix's tracking metadata. Match the Server-Side Apply field manager `kix/<cluster>` instead of `kix` or `kix.run/identity-hash` to identify objects managed by Kix. Read deployed object lists and dependencies from `spec.objects` on the `PackageInstanceRevision` resources linked in an `Activation` record's `status.revisions` (each entry records a hash of the sent manifest, API group, kind, namespace, name, and `needs`) instead of from `kix.run/activations` or `status.packageIndex`, read package instance names and lifecycles from `spec.slot` on those revisions, and read applied hashes from `status.applied` (mapping each entry's manifest hash to the hash of Kix-owned live fields) instead of from `kix.run/applied-hash`. Kix no longer writes `kix.run/activations`, `kix.run/applied-hash`, `kix.run/identity-hash`, `kix.run/depends-on`, `kix.run/package`, `kix.run/package-namespace`, or `kix.run/lifecycle` onto deployed objects (`Activation` records keep their own annotations), and no longer writes `status.packageIndex` or `status.orphansKeptFrom` onto `Activation` records. Built manifests, including `kix export --with-kix-metadata`, still carry `kix.run/identity-hash`, `kix.run/depends-on`, `kix.run/package`, `kix.run/package-namespace`, and `kix.run/lifecycle`, and Kix strips them before sending manifests to the cluster.

On the first deploy after upgrading, Kix renames each object's `kix` field-manager entry to `kix/<cluster>` and removes the retired annotations. If another Kix cluster on the same Kubernetes cluster still runs an earlier version of Kix, shared objects keep their `kix` field-manager entry and retired annotations until both Kix clusters deploy with this version; until then, changing a shared field stops with a field ownership conflict naming `kix`.
