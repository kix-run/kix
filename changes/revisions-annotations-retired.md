Kix no longer writes the annotations `kix.run/activations` and `kix.run/applied-hash` on the objects it deploys, and the first deploy with this version removes them from every object of the Kix cluster. Deployment records no longer carry `status.packageIndex` or `status.orphansKeptFrom` either. Kix now applies under the field manager `kix/<cluster>`, where `<cluster>` is the Kix cluster's name, in place of `kix`, so `metadata.managedFields` shows which Kix clusters apply each object, and the first deploy renames each object's `kix` entry. A program that read `kix.run/activations` or `status.packageIndex` to find the objects of a deploy now reads the `PackageInstanceRevision` objects named in the deployment record's `status.revisions`, which list each object by API group, kind, namespace, and name. A program that read `kix.run/applied-hash` now reads `status.applied` on those revisions, which maps each object's `kix.run/identity-hash` to the hash of what Kix applied. A script, policy, or admission rule that matches the field manager `kix` must match `kix/<cluster>`. While another Kix cluster on the same Kubernetes cluster still runs an earlier version of Kix, an object that both Kix clusters deploy keeps both annotations and its `kix` entry until that Kix cluster is deployed with this version too. Until then, a deploy that changes a value on that object stops with a field ownership conflict that names `kix`.
