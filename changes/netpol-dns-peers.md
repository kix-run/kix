No changes are required for existing clusters. Providers of the `dns` role can now declare the DNS endpoints allowed by generated network policies: set `dnsPeers` on `kix.mkImport`, or `meta.dnsPeers` in a package. Each entry selects pods by label (`{ namespace; podSelector; }`, where `namespace` defaults to the provider's namespace) or an IP range (`{ cidr; }`, rejected by the `cilium` enforcer, which supports pod selectors only). Kix uses this list for the DNS egress rule in generated workload policies and in `cilium-cluster-dns-egress`, and still defaults to `k8s-app: kube-dns` pods in `kube-system` when unset. `packages.experimental.coredns` now declares its own pods in `meta.dnsPeers`, so `networkPolicy.enable = true` no longer requires it to run in `kube-system`. The `gke` and `gke-autopilot` flavors set `dnsPeers` on `platform-dns` to `kube-dns`, `node-local-dns`, `169.254.169.254/32`, and `169.254.20.10/32`. If no `dns` provider is active and the cluster has a single `dns` import (such as `platform-dns`), Kix still uses its `dnsPeers` even when `optional = true` leaves that import inactive.
