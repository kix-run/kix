Kix now installs and updates its own four CustomResourceDefinitions (`activations.kix.run`, `packageinstances.kix.run`, `activationheads.kix.run`, and `packageinstancerevisions.kix.run`) before it changes a cluster. Before upgrading, grant every Kubernetes account that runs `kix deploy`, `kix rollback`, `kix gc`, or `kix migrate domain`, and the Kix operator's account, `get` on those four CRDs. The account that runs the first upgraded Kix on a cluster also needs `create` on `customresourcedefinitions` to install the CRDs that are missing, and `update` on them when a later Kix brings a newer definition. Grant every such account `get`, `list`, `create`, and `update` on `activationheads.kix.run`, which holds the deploy lock, and `get`, `list`, `create`, and `delete` on `packageinstancerevisions.kix.run`, plus `patch` on `packageinstancerevisions/status`, which list the objects each deploy applied. An account that only runs `kix plan` needs `list` on `activationheads.kix.run` and on `packageinstancerevisions.kix.run`. `kix plan` and `kix deploy` read each object of a kind the account may not list one at a time, and stop when the account may neither list nor get it, naming the kinds. If you use operator mode, upgrade the Kix operator before you run the upgraded Kix against its cluster, because an older operator writes the retired annotations `kix.run/activations` and `kix.run/applied-hash` back onto every object it applies. Commands stop before changing anything when these permissions are missing, reporting `[K9557]` when Kix cannot read, create, or update one of its CRDs. Every command that changes a Kix cluster also stops with `[K9557]`, before it plans, while a current, queued, or deploying deployment record of that Kix cluster was submitted to the operator and the operator does not list `revisions` in `kix.run/operator-features` on `activations.kix.run`. An operator from Kix 0.9 or earlier lists no features and is refused too. If the operator was uninstalled, run `kix deploy <cluster> --operator-removed` once. Other Kix clusters on the same Kubernetes cluster are not affected. `--operator` commands also stop with `[K9557]` until the operator lists `requests`, `head-lock`, and `revisions`.
