Pass `--operator-removed` to `kix deploy <cluster>` once after uninstalling the Kix operator so you can deploy the cluster directly again. Kix stops with `[K9557]` before modifying a cluster whose current, queued, or deploying deployment record was submitted to an older operator, because Kix cannot tell whether that operator is still running or was uninstalled. Running `kix deploy <cluster> --operator-removed` marks queued operator records `Superseded`, marks in-progress operator records `Failed`, and clears `spec.source` from those records and the active record before showing the plan (so those record updates stay in place even if you decline the plan). Later commands do not need `--operator-removed` unless `kix rollback` restores an older operator-managed record. Do not pass `--operator-removed` while an older operator is still running, and do not combine it with `--operator`. Because Kix cannot check whether an operator is still running, it prints a `kubectl` command to look for operator pods after taking the cluster back. If no operator record needs updating, Kix prints a note and changes nothing. `kix plan --operator-removed` previews the plan without modifying cluster records. It rejects `--out` because `kix deploy --plan` would take the cluster back first and then reject the saved plan as out of date.
