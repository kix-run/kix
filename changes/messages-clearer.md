Kix's errors and command output are shorter and say what to do next. An error from a package, a contract, or the Kix library shows without a stack trace, names the instance and the setting to change, and gives the fix, and `kix check -o json` lists it under the eval row's `findings`. Other evaluation errors no longer start with the internal command line or the warning about uncommitted files in Git, and show stack frames only when they point at your project's own files. Seventeen library errors that were cut short now print in full. An error caused by a bug in Kix gives the address to report it, https://github.com/kix-run/kix/issues. `kix plan`, `kix diff`, `kix deploy`, `kix gc`, and `kix rollback` describe in plain words what changes on the cluster, whether Pods restart, and whether objects that left the build stay or are deleted. `kix plan` shows the line that differs when a long text field drifted, and a failed apply ends with the apiserver's message alone. `kix diff` and `kix gc` put the objects of other Kix clusters on one line, and when `kix gc` has nothing to delete it counts the objects still in use and the older deploy records it keeps for rollback. `kix check` lists scorecard findings and long detail under its table, `-v` adds the info findings, and `-o json` gives them under the `scorecard` row's `findings`. Setting `package = ./dir` without `import` now says to add `import`. Warnings printed without `-v` no longer carry a timestamp and a module path, Kix no longer prints the Kubernetes client's log line for each request it retries, and progress lines write no terminal control codes when output goes to a file or a pipe. When no kubeconfig context is set and you pass no `--context`, Kix says so and how to choose one. When `kix upgrade` stops for an edit to `flake.nix`, it says that it saved its progress in `kix-upgrade.json`. Packages of your own can raise the same kind of error with `scope.fail`, and cluster definitions with `kix.fail`. An assertion can now give `fix`, `id`, and `option`.
