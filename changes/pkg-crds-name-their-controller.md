`victoria-metrics-operator`, `arc`, `cdi`, `cert-manager`, `clickhouse-operator`, `envoy-gateway-controller`, `external-secrets`, `infisical-operator`, `kubevirt`, `mayastor`, `prometheus-operator`, `rabbitmq-operator`, `snapshot-controller`, `stackgres-operator`, `tailscale`, `velero`, `volsync`, and `zfs-localpv` name the workload that reconciles a custom resource kind as that kind's `controller`. A prune that removes custom resources of these kinds together with their operator now deletes the custom resources first and keeps the operator until they are gone, and a stuck delete names the operator and says whether it is ready. The first deploy after the upgrade applies each custom resource of these kinds again, because its `kix.run/depends-on` annotation changes. No action is needed.
