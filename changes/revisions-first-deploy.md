The first deploy of each Kix cluster with this version moves it to the new bookkeeping. That deploy rewrites the metadata of every object of the Kix cluster once: it renames the object's field manager `kix` to `kix/<cluster>` and removes the annotations `kix.run/activations` and `kix.run/applied-hash`. The plan says how many objects it rewrites in a line that starts with `Upgrade:`, and `kix plan -o json` gives the number as `metadata_rewrites`. Controllers that copy an object's annotations into its Pods may restart those Pods once. The same deploy applies again each unchanged object that has no `kix.run/applied-hash` annotation, and an object that cedes fields with `ownership.cede` can show once as changed on the cluster, because Kix now leaves ceded fields out of the hash of what it applied. The Kix operator does not repair drift on a Kix cluster until one deploy with this version, from the command line or with `--operator`, has run on it, and `kix deploy --only` refuses until a full deploy with this version has. Do not run `kix gc` with an earlier version on a Kix cluster this version has deployed: an earlier `kix gc` reads the removed annotations and can delete objects that are still deployed. If an earlier version of Kix deploys the Kix cluster anyway, the next deploy with this version moves it again.
