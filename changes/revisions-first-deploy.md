Once you deploy a Kix cluster with this version, do not run `kix gc` against it with an earlier version of Kix. Older versions of `kix gc` look for the retired tracking annotations and could delete active objects. On the first deploy after upgrading (or the Kix operator's next deploy or drift repair), Kix converts the current deployment record and any `Failed` or `Partial` records to `PackageInstanceRevision` resources. It also renames each object's field manager from `kix` to `kix/<cluster>` and removes the retired `kix.run/activations` and `kix.run/applied-hash` annotations. `kix plan` shows how many objects get this one-time metadata update under `Upgrade:`, and `-o json` reports the count in `metadata_rewrites`. Controllers that copy resource annotations onto Pod templates may restart their Pods once during this update. Unchanged objects with no recorded applied hash are reapplied once, and objects with `ownership.cede` may report a one-time change because Kix now excludes ceded fields from applied hashes. If the first deploy is interrupted, converted records remain valid and the next deploy finishes updating any remaining objects. If an older version of Kix deploys to the cluster later, deploying again with this version runs the migration again.
