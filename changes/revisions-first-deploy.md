Once you deploy a Kix cluster with this version, do not run `kix gc` against it with an earlier version of Kix, because older `kix gc` versions look for the retired tracking annotations and could delete active objects. On the first deploy after upgrading (or the Kix operator's next deploy or drift repair), Kix converts each earlier deployment record that later runs still consult (the current deployment record and any `Failed` or `Partial` records) to `PackageInstanceRevision` resources, renames each object's field manager from `kix` to `kix/<cluster>`, and removes the retired `kix.run/activations` and `kix.run/applied-hash` annotations (`kix plan` shows this count under `Upgrade:`, and `-o json` reports it as `metadata_rewrites`). Controllers that copy resource annotations onto Pod templates may restart their Pods once during this rewrite, unchanged objects without a recorded applied hash are reapplied once, and objects with `ownership.cede` may report a one-time change because Kix now excludes ceded fields from applied hashes. If the first deploy is interrupted, converted records remain valid and the next deploy finishes updating any remaining object metadata; if an older version of Kix deploys to the cluster later, deploying again with this version re-runs the migration.
