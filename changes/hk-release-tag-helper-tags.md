No configuration changes are needed. Packages that check container image tags against their pinned upstream release now report mismatches in a consistent format and accept tags with or without a leading `v`, such as custom image rebuilds. Previously, `kubevirt`, `cdi`, `prometheus-operator`, and `velero` required a leading `v`, while `cnpg-operator` and `rabbitmq-operator` rejected one. `arc` still rejects tags starting with `v` because its controller cannot parse a `v` prefix in runner-set version labels. When a component image tag does not match, `mayastor` now reports that component's image option instead of always reporting `image.tag`.
