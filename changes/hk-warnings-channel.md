If you read bundles on a separate machine, upgrade Kix on the machine that reads bundles before or alongside the machine that runs `kix bundle`, because older versions of Kix reject bundles that contain warnings. If you write custom packages that call `scope.requireMetricsApi`, include its return value in the package's `warnings` function; `scope.requireMetricsApi` now returns a list of warnings instead of `null`. Cluster definitions need no changes. Kix now shows warnings that were hidden whenever evaluation succeeded: package warnings from `cilium`, `descheduler`, `mayastor`, `plausible`, `rabbitmq-cluster`, and `spegel`; warnings on custom resources that reference a Service address without declaring whether their pods connect to it (`factBehavior`); and warnings when a package returns a non-resource value under `secrets` or `crds` in `build`. `kix graph`, `kix list images`, and `kix list resources` now print warnings to stderr, matching `kix build`, `kix plan`, and `kix deploy`. `kix bundle` now stores build warnings in the bundle, and `kix plan --bundle`, `kix deploy --bundle`, `kix diff --bundle`, and `kix graph --bundle` print them to stderr. Package `warnings` and `assertions` functions also now receive `clusterConfig`.
