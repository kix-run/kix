`openbao` moves to OpenBao 2.7.3 from 2.7.1. OpenBao 2.7.2 fixes four advisories: GHSA-736f-82w7-hj22 (path handling in the `cert` and `approle` auth methods), GHSA-q824-44ff-f5j5 (client credentials in the OIDC provider), GHSA-h76r-48x5-36hg (wildcards in SSH identity templates), and GHSA-5pmx-2p74-x478 (key backup in the `transit` engine). OpenBao 2.7.3 fixes two more. GHSA-h8fh-pmch-cjww: a request that a standby pod forwarded to the active pod skipped the listener's request size limits and its `disable_unauthed_*` settings, and the active pod mishandled its forwarded client certificate headers. This affects instances with more than one replica. GHSA-fgmw-h9wp-wc7g: an auth method that matches entity and group alias names without regard to case can let one user log in as another whose name differs only in case. OpenBao 2.7.3 adds the auth mount setting `case_sensitive_alias` to turn on exact matching. Every mount, including the Kubernetes auth mount this package creates, still ignores case until you set it, and OpenBao 2.8.0 will turn it on for new mounts. The Kubernetes auth method takes alias names from service accounts, which are lower case, so this package's logins are not exposed. Upstream has assigned these advisories no CVE ids. The first deploy after you upgrade restarts each OpenBao pod once, one at a time. Your data carries over, and you do not need to change anything.
