If two Kix clusters on the same Kubernetes cluster deploy the same resource, make their definitions produce identical field values or deploy that resource from only one Kix cluster. When two Kix clusters set a shared field to different values, applying that resource now fails with `[K5636]`, and `kix plan` and `kix deploy`'s dry-run check report the refusal before anything is applied (stopping `kix deploy` before it applies anything under the default `--on-error stop`), naming the resource, the other Kix cluster, and the conflicting fields (previously, the last deploy overwrote the field without warning). Passing `--force-conflicts` takes ownership for the deploying Kix cluster, which causes the other Kix cluster's next deploy to fail with `[K5636]` until their definitions match. When one Kix cluster removes a shared resource from its build, pruning now releases its field ownership on that resource so the remaining Kix cluster owns it cleanly; if releasing ownership fails or `--skip-orphan-check` is set, Kix keeps the resource in its kept-orphans list and retries on the next deploy.
