`kubevirt` installs KubeVirt v1.9.1 instead of v1.5.0. KubeVirt supports updates only from the latest patch of one minor to the latest patch of the next, so this jump skips its supported path. To follow that path, set the instance's `image.tag` to v1.5.3, v1.6.6, v1.7.4, and v1.8.4 in turn, deploy once for each, and then remove the setting. Running virtual machines keep running on their v1.5.0 virt-launcher pods until they restart or migrate. KubeVirt v1.9 turns on every Beta feature gate by default, so virt-operator now also runs virt-template-apiserver and virt-template-controller in the `kubevirt` namespace. To turn off a gate, list it in `extraSpec.configuration.developerConfiguration.disabledFeatureGates`. virt-exportproxy now always runs, because VMExport is no longer behind a gate. VirtualMachines now take changes to their template live by default (rollout strategy `LiveUpdate`). Set `extraSpec.configuration.vmRolloutStrategy = "Stage"` to keep the old behaviour. Releases since v1.5 removed the `instancetype.kubevirt.io/v1alpha1` and `v1alpha2` APIs and the macvtap and SLIRP network bindings, and renamed several metrics and recording rules. Move objects and virtual machines off these before you upgrade. KubeVirt documents no way back to v1.5.
