`external-dns` runs upstream v0.24.0 instead of v0.23.0, and its pod restarts once on the first deploy. With the `gateway-httproute` or `gateway-grpcroute` source, a hostname from the `external-dns.kubernetes.io/hostname` annotation or from `--fqdn-template` now replaces the hostname of the Gateway listener. With `policy = "sync"`, external-dns then deletes the records it made from the listener's hostname. If you need those records, add their hostnames to the route's `hostnames` or to the annotation before you upgrade. To see what external-dns would change, deploy once with `extraArgs = [ "--dry-run=true" ]`. v0.24.0 also ignores the legacy `external-dns.alpha.kubernetes.io/` annotation prefix and reads only `external-dns.kubernetes.io/`. With `policy = "sync"`, external-dns deletes the DNS records of any resource that carries only the old prefix. Rename those annotations to `external-dns.kubernetes.io/` before you upgrade, or set `extraArgs = [ "--enable-legacy-annotation-prefix" ]` while you migrate (upstream plans to remove this flag).
