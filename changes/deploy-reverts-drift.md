Before running `kix deploy` or `kix rollback`, list any fields that another controller should keep owning in `ownership.cede` on the resource. Both commands now automatically restore Kix-managed fields that changed on the live cluster, even when the resource did not change in the build, and take ownership back from other field managers without requiring `--reconcile` or `--force-conflicts`. `kix plan` marks these writes with `↺`, lists the drifted fields and field managers under `Drift`, and sets `reason` to `reverts_drift` on their `objects.writes` entries in `-o json`; Kix cedes fields listed in `ownership.cede` and never counts them as drift. During apply, Kix overwrites only the exact fields, managers, and live values shown in the plan (retrying up to 5 times if unrelated updates occur, and stopping if the drifted values changed after planning). Kix never forces fields owned by another Kix cluster: it applies shared objects without force (`reason`: `held_by_other_cluster`), sharing ownership when values match and stopping with `[K5636]` when they conflict. In operator mode, the Kix operator never takes fields back from another field manager: if another manager owns a drifted field on an object, the operator leaves that entire object unchanged, emits a `DriftNotReverted` Warning Event naming the manager and fields, and repairs the remaining objects. On objects where no other manager owns the drifted fields, the operator restores changes such as deleted fields or `kubectl scale` edits on its next drift repair; on objects with no field-manager entry for this Kix cluster (such as shared objects applied under `kix` by an earlier version), it applies without force so Kubernetes adds its entry when values match and rejects the apply when they conflict.
