`kix deploy` and `kix rollback` now put back fields that changed on the cluster since Kix applied them, also on objects whose build did not change, and take those fields from the field manager that changed them. Earlier versions left such an object as it was and only listed the drift in the plan. The plan counts these objects in a line that starts with `↺`, names the managers and fields in its drift section, and gives the entry in `objects.writes` of `kix plan -o json` the `reason` of kind `reverts_drift`. Kix applies such an object only while it is as the plan read it: when something changes it after the plan, the deploy stops and names the object. A field the package cedes with `ownership.cede` never counts as drift, and Kix never takes it back. If another controller is meant to own a field that the plan shows as drift, cede that field before you deploy. When another Kix cluster applies the changed field, Kix does not take it, and the deploy stops with `[K5636]`. The Kix operator never takes fields from another field manager: it leaves such an object as it is, posts a `DriftNotReverted` Warning Event that names the manager and the fields, and repairs the rest. The operator now puts back a change that no field manager owns, such as a removed field or a replica count set with `kubectl scale`, on its next drift repair.
