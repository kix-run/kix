Before running `kix deploy` or `kix rollback`, add any fields that an in-cluster controller should keep owning (such as an autoscaled replica count) to `ownership.cede` on the resource. Forced applies, including `--force-conflicts`, now leave ceded fields with the manager that holds them. If you previously relied on `--force-conflicts` to take back a ceded field when a resource changed in the build, remove that field from `ownership.cede`.

`kix deploy` and `kix rollback` now restore Kix-managed fields that changed on the live cluster, even on unchanged resources, and take ownership back from other field managers without `--reconcile` or `--force-conflicts`. Fields listed in `ownership.cede` never count as drift. `kix plan` marks reverted writes with `↺`, lists the changed fields and managers under `Drift`, and sets `reason` to `reverts_drift` on their `objects.writes` entries in `-o json`.

Before forcing an object, Kix sends the same apply without force as a dry run during planning and again right before writing (adding three API requests per reverted object during planning and one at the write). It forces the write only when both checks report the exact same fields, field managers, and live values, retrying up to 5 times if other fields change in between and stopping if the conflicted fields changed after planning. If the dry run cannot determine the conflicting fields during planning, Kix applies without force so the plan shows the conflict. `kix deploy --plan` also rejects a saved plan when a reverted field's managers or live value changed after saving, except for any second change to a Secret value or a same-length change to a value over 16 KiB (plan files omit Secret values and store only the byte length of values over 16 KiB).

Kix never takes fields back from another Kix cluster. It applies shared objects without force (`reason`: `held_by_other_cluster`), sharing ownership when values match and stopping with `[K5636]` when they conflict. In operator mode, the Kix operator never takes fields back from another field manager. When another manager owns a drifted field, the operator applies the manifest without the fields that manager holds (restoring the rest of the object), emits a `DriftNotReverted` Warning Event naming the manager and fields until the drift is resolved, and repairs the remaining objects. When no other manager owns the drifted fields (such as deleted fields or `kubectl scale` edits), the operator restores them on its next drift repair. On objects with no field-manager entry for this Kix cluster yet (such as shared objects applied under `kix` by an earlier version), the operator applies without force so Kubernetes adds its entry when values match and rejects conflicts.

Kix also treats two cases that Kubernetes previously rejected with a field ownership conflict as reverting drift and applies them with force after the same dry-run check: a manual edit on an object whose dependencies changed, and an edit by another field manager on an object written by an interrupted deploy of this Kix cluster. When an interrupted deploy recorded no applied hashes for an object and the object shows no drift, `kix plan` reapplies the object and names that deploy as one that may have written it (`reason`: `unfinished_deploy`).
