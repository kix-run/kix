Kix now names every object with its API group, so two kinds that share a name in different groups never look like one object. Text output, resource ids in JSON, and plan files write `Deployment.apps/web@shop` where they wrote `Deployment/web@shop`; a kind in the core group keeps its short form, such as `Service/web@shop`. Update scripts that read these ids. The plan, status, and deploy log JSON have a new `schema_version`, and `kix deploy --plan` refuses a plan file saved by an earlier version, so make the plan again after you upgrade. Rules about Kubernetes' built-in kinds now apply only in the kind's own group: a custom resource named `Deployment`, `Job`, `Secret`, `Namespace`, or `CustomResourceDefinition` is checked for readiness through its conditions, pruned and recreated like any other object, and gets no SOPS values, and `kix.run/rerun` applies only to `batch` Jobs. A build that moves an object to another API group, such as a custom resource whose CRD moved from `certmanager.k8s.io` to `cert-manager.io`, now creates the object in the new group and, with `--prune`, deletes the one in the old group.
