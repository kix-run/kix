Update scripts that parse resource IDs in Kix output, or that check `schema_version` (now `"2026-11-15"`) in plan, `kix status`, or `kix deploy --log-format json` JSON output. Re-run `kix plan --out` for any plan file saved before upgrading, because `kix deploy --plan` refuses plan files from earlier versions. Kix now includes the API group in resource IDs so two kinds with the same name in different groups stay distinct. Text, Markdown, JSON, YAML, and saved plan files write `Deployment.apps/web@shop` instead of `Deployment/web@shop`, while core `v1` kinds keep `Service/web@shop`. In JSON and YAML output, `kix graph`, `kix list resources`, and `kix status` also include `group` on each resource outside the core `v1` group. Rules for built-in Kubernetes kinds now apply only in each kind's own API group. Custom resources that share a built-in kind name use custom-resource readiness checks (`kix.run/readiness` or `status.conditions`) and can be pruned and recreated like any other custom resource. Only core `v1` `Secret` objects get SOPS decryption and secret redaction in plans and diffs, and `kix.run/rerun` applies only to `batch` `Job` objects. Moving an object to another API group, such as `certmanager.k8s.io` to `cert-manager.io`, now creates the object in the new group and, with `--prune`, deletes the one in the old group.
