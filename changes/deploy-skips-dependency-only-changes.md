A deploy no longer writes to an object whose own manifest is unchanged when only an object it depends on changed. Before, such an object was applied again to update its tracking annotations, which raised its `metadata.resourceVersion` and could restart Pods through controllers that copy annotations. If an operator or controller of yours acts only when its custom resource is written, it no longer sees a write when a Secret or ConfigMap that resource depends on changes, so restart it or change the resource when you need it to act. `kix plan` and `kix plan --read-only` no longer list "tracking annotation only" changes, and `dep_affected_resources` in `-o json` is always empty in a plan of a deploy. `kix diff` between two builds still lists them. The first deploy after upgrading compares each object with a new hash, so it applies every object once, except objects an earlier Kix recorded as applied from the same build file that still match what it applied.
