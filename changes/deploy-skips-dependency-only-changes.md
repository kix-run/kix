If you run an operator or controller that reconciles a custom resource only when that resource itself is written, update the custom resource or restart the controller when a Secret or ConfigMap it depends on changes. `kix deploy` no longer reapplies an unchanged object when only its dependencies changed. Previously, Kix reapplied dependent objects to update their tracking annotations, which bumped `metadata.resourceVersion` and could restart Pods when controllers copied annotations. `kix plan` and `kix plan --read-only` no longer report "tracking annotation only" changes, and `dep_affected_resources` in `-o json` is always empty for both commands (`kix diff` between two builds still lists them). On the first deploy after upgrading, Kix switches to a new manifest hash: objects that did not change in the build (including their dependencies) and still match what the earlier version of Kix applied are skipped, while all other objects are reapplied once.
