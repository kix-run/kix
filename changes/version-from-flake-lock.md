kind = "error"
id = "K4476"

A project's version of Kix now comes from `flake.lock`: the release tag of the flake input named `kix`, such as `github:kix-run/kix/v0.10.0`. Kix runs that version and installs it when needed. Kix refuses a `kix` line in `kix.toml` with `[K4476]`. To upgrade a project from Kix 0.9, first install Kix 0.10 with `kix self update` or the install script, and check that `kix --version` prints it, because `kix upgrade` in Kix 0.9 writes the `kix` line back. Then delete the `kix` line, rename a `kixpkgs` input to `kix`, run `kix upgrade --to <version>` with the version the `kix` line named, and then run `kix upgrade`. The first command adds the tag and writes `flake.lock` without building anything. The second command builds the project with both versions and shows what the new version changes. When `flake.lock` names no version, Kix reports `[K4476]` first with these steps. A project without `flake.lock`, or whose `kix` input has no release tag, stops with a message that gives the same two commands. A `kix` input on a local folder or a branch, an `--override-input kix`, or a project whose `kix.toml` sets `library = "self"` (because its own flake provides the Kix library) is a development library: Kix runs the version you started, prints a note, and compares no versions. `library = "input"`, the default, means the `kix` input holds the Kix library. The library a project evaluates must now be the running Kix, so Kix stops before it evaluates when `flake.nix` names another tag than `flake.lock`, and says which `kix upgrade --to` to run. That upgrade sets `flake.nix` back to the locked tag and upgrades from there.
