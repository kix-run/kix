You can now create PostgreSQL databases and login roles with [DB Operator](https://github.com/db-operator/db-operator) 2.47.0 using `packages.experimental.db-operator`, `packages.experimental.db-operator-instance`, and `packages.experimental.db-operator-database`. `db-operator` installs the operator, its CRDs, and its admission webhook using a `cert-manager` certificate. `db-operator-instance` registers an in-cluster or external PostgreSQL server and its admin `Secret`. `db-operator-database` creates a database and login role for an application and writes the generated credentials to a `Secret` in the application's namespace. It satisfies `kix.contracts.postgresDatabase` (like `cnpg-database` and `stackgres-database`), so packages that take a `database` dependency, such as `metabase`, work with it without changes. When network policies are enabled, Kix allows traffic from the Kubernetes API server to the webhook and from the operator and applications to in-cluster PostgreSQL servers. See "Create databases with DB Operator" in the how-to guides to get started.
