kind = "fixed"
packages = ["experimental/cnpg-database", "experimental/stackgres-database", "experimental/mayastor"]

Kix no longer resolves an instance's dependency to the instance itself. Previously, if an instance's name or `aliases` matched one of its own dependencies, the build failed with a stack overflow. Because of this, `mayastor` also needed an explicit `deps.storageClasses` setting whenever its `aliases` included `storageClasses`. Kix now skips the instance itself and uses another matching instance, or reports the dependency as missing. Pointing `deps.<name>` at the instance itself fails with an error. Inactive `optional = true` instances no longer resolve their dependencies, so an unmet dependency on an unused optional instance no longer fails the build. Kix also now warns whenever a resource in `root.postHooks` does not depend on `root.resource` or an entry in `root.requires`. Previously, any other dependency on the hook hid that warning. `cnpg-database` and `stackgres-database` move their `Database` and bootstrap `Job` from `root.postHooks` to `root.requires`, which moves them on each `PackageInstance` from `kix.run/post-hooks` to `kix.run/package-requires` without changing deploy order.
