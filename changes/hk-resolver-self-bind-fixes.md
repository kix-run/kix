Kix no longer resolves an instance's dependency to the instance itself. Previously, if an instance's name or `aliases` matched one of its own dependencies, the build failed with a stack overflow. Kix now skips the instance itself and uses another matching instance, or reports the dependency as missing. Managed instances still take precedence over imports, so an instance that answers a name itself does not bind an import of that name. `mayastor` no longer refuses `storageClasses` in its own `aliases` when etcd's class comes from `etcd.storage.storageClassName` or from another managed instance. Pointing `deps.<name>` at the instance itself fails with an error. Inactive `optional = true` instances no longer resolve their dependencies, so an unmet dependency on an unused optional instance no longer fails the build. Kix also now warns whenever a resource in `root.postHooks` does not depend on `root.resource` or an entry in `root.requires`. Previously, any other dependency on the hook hid that warning. `cnpg-database` and `stackgres-database` move their `Database` and bootstrap `Job` from `root.postHooks` to `root.requires`, which moves them on each `PackageInstance` from `kix.run/post-hooks` to `kix.run/package-requires` without changing deploy order.
