kind = "fixed"
packages = ["experimental/cnpg-database", "experimental/stackgres-database", "experimental/mayastor"]
+++
Kix no longer resolves an instance's dependency to the instance itself. Previously, if an instance's name, aliases, or roles matched one of its own dependencies, evaluation failed with a stack overflow. Kix now skips the instance itself during automatic resolution and uses another matching instance, or reports the dependency as missing. Pointing `deps.<name>` at the instance itself with `ref` now fails with an error. Managed instances still take priority over `kix.mkImport` instances, so a managed instance that matches one of its own dependencies does not automatically use an import with that name. Set `deps.<name>` with `ref` to use the import. With this fix, `mayastor` accepts `"storageClasses"` in its `aliases` when etcd gets its StorageClass from `config.etcd.storage.storageClassName` or from another managed `storageClasses` provider.

Inactive `optional = true` instances no longer resolve dependencies, so an unmet dependency on an unused optional instance no longer fails the build. Kix also now warns whenever a resource in `root.postHooks` does not depend on `root.resource` or an entry in `root.requires`. Previously, if the hook referenced any other resource in the package, Kix skipped that warning. In `cnpg-database` and `stackgres-database`, the `Database` custom resource and bootstrap `Job` move from `root.postHooks` to `root.requires`. On each `PackageInstance`, this moves the entry from `kix.run/post-hooks` to `kix.run/package-requires` without changing deploy order.
