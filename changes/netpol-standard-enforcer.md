Existing GKE clusters need no configuration changes. On the next deploy, Kix adds a `platform-network-policy` import record in `kube-system` (`gke-managed` on Autopilot). GKE clusters (`gke` and `gke-autopilot`) can now set `networkPolicy.enable = true` to generate standard Kubernetes `NetworkPolicy` objects for GKE Dataplane V2, and reject `cilium` instances because Dataplane V2 already enforces network policy. When you enable `networkPolicy.enable = true` on GKE, set `cluster.network.apiServer.cidrs` to the control plane endpoint address if any workload is bound to a `Role` or `ClusterRole`, and set `cluster.network.nodeCidrs` to the node IP ranges if any rule targets nodes (for example, Prometheus scraping `node-exporter`). `kix check` stops and names any required option that is missing, and `cluster.network.apiServer.sources` defaults to the `konnectivity-agent` pods in `kube-system`. Generated `NetworkPolicy` objects that allow broader traffic than Cilium carry the `kix.run/network-policy-widened` annotation, which the new `security.networkPolicyWidened` scorecard rule reports as a warning. Validation check 12 now skips `NetworkPolicy` objects generated by Kix (`kix.run/derived: "true"`), and the `hostNetwork` workload warning now refers to network policy in general instead of `CiliumNetworkPolicy`. For custom scorecard rules, cluster-level rules now receive `derivedResources`, and setting `detail = true` on a finding reports it at `info` severity (shown with `kix check -v`).
