Existing GKE clusters need no configuration changes: their next deploy adds a `platform-network-policy` import record in `kube-system` (`gke-managed` on Autopilot), and they can now turn on generated network policies with `networkPolicy.enable = true`. The `gke` and `gke-autopilot` flavors declare GKE Dataplane V2 as an exclusive network policy enforcer (rejecting `cilium` instances) and emit standard Kubernetes `NetworkPolicy` objects. When enabling `networkPolicy.enable = true` on GKE, set `cluster.network.apiServer.cidrs` to the control plane endpoint address if any workload is bound to a `Role` or `ClusterRole`, and set `cluster.network.nodeCidrs` to the node IP ranges if any rule targets nodes (such as Prometheus scraping `node-exporter`); `kix check` stops and names any required option that is unset, while `cluster.network.apiServer.sources` defaults to the `konnectivity-agent` pods in `kube-system`. Policies that allow broader traffic than Cilium would carry the `kix.run/network-policy-widened` annotation and trigger warnings from the new `security.networkPolicyWidened` scorecard rule. In addition, validation check 12 now skips `NetworkPolicy` objects generated by Kix (`kix.run/derived: "true"`), cluster-level scorecard rules receive `derivedResources`, and any scorecard rule can set `detail = true` on a finding to report it at `info` severity (shown only with `kix check -v`).
