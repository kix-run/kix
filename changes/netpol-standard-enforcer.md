Generated network policy now works on GKE. The `gke` and `gke-autopilot` flavors declare GKE Dataplane V2 as the network policy enforcer, so `networkPolicy.enable = true` writes standard `NetworkPolicy` objects instead of failing, and a `cilium` instance is refused on these flavors. Set `cluster.network.apiServer.cidrs` to the control plane's address when a workload is bound to a Role or ClusterRole, and `cluster.network.nodeCidrs` to the node range when a rule needs the nodes, such as a Prometheus scrape of node-exporter; `kix check` names the option when one is missing. `cluster.network.apiServer.sources` defaults to the `konnectivity-agent` pods on GKE. A rule that allows more than the Cilium policy would carries `kix.run/network-policy-widened`, and the new `security.networkPolicyWidened` scorecard rule reports it. Validation check 12 no longer checks the `podSelector` of policies Kix generates, and a cluster scorecard rule can mark a finding `detail = true` to list it only under `kix check -v`. Existing GKE clusters gain a `platform-network-policy` import record in `kube-system` (`gke-managed` on Autopilot) and need no change.
