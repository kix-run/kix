`kix deploy`, `kix plan`, `kix rollback`, `kix gc`, and the Kix operator now recover when a deployment record references a `PackageInstanceRevision` that is missing from the cluster or unreadable (unless a newer version of Kix wrote it). Previously, Kix told you to redeploy the record's build to recreate the missing revision, then refused that redeploy too. Now, if the command's build or a deployment record's build on the machine includes that revision, Kix reconstructs its object list, reapplies those objects on the next apply, and restores the `PackageInstanceRevision` on the cluster during a deploy, rollback, or operator drift repair. Commands stop only when no build on the machine includes the revision, and the error now names the deployment record whose commit to check out and redeploy. `kix gc --full-scan` can also rebuild a lost `keptOrphans` revision while other revisions are missing or unreadable, as long as their builds are available on the machine.
