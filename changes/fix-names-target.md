No changes to existing cluster definitions or commands are needed. `kix plan`, `kix deploy`, `kix rollback`, `kix gc`, and `kix migrate domain` now print the kubeconfig context and API server URL before connecting (for example, `Connecting to context prod (https://prod.example:6443)...`), so you can stop a command aimed at the wrong cluster. `kix plan --read-only` prints the same line to stderr. `kix history` now shows the context and API server URL in its heading, and `kix status` adds the API server URL beside the context. Before a cluster's first deploy, `kix plan` and `kix deploy` also print a note when `cluster.kubernetes.uid` is unset, showing the setting that binds the definition to the connected Kubernetes cluster. Structured outputs include the target cluster too: `kubernetes` (`{ context, server }`) in saved plan files, `kix plan --read-only`, and `kix history`; `kubernetes.server` beside `kubernetes.context` in `kix status`; and an opening `"type": "kubernetes"` event in `kix deploy --log-format json`.
