Update any scripts or policies that read import-marker `PackageInstance` objects on the cluster to read `spec.imports` on `PackageInstanceRevision` resources instead. Kix no longer creates `PackageInstance` objects on the cluster for import markers (`kix.mkImport`, `scope.mkCRDRef`, `scope.mkSecretRef`, and `scope.mkServiceRef`), so `kubectl get packageinstances` lists only deployed package instances, and multiple Kix clusters sharing a Kubernetes cluster no longer conflict on shared markers (such as flavor defaults). Each package instance's revision records its markers and their target objects under `spec.imports`. `kix deploy` still checks that an imported target exists before applying any resource that depends on it; if you add an import dependency to a resource whose own manifest does not change, Kix leaves that resource untouched and checks the imported target on the next deploy that writes a dependent resource. Import-marker `PackageInstance` objects created by earlier versions of Kix remain as removed resources until `kix deploy --prune` or `kix gc` deletes them (unless another Kix cluster on an earlier version still deploys them).
