# 2026-11-24 · `cli/kix/src/cluster/secrets.rs` · Kix applies `Secret` values through `stringData`, so the `kix` field manager never owns `data` keys.

Releasing a previous field manager (such as Flux's `kustomize-controller`) with an empty server-side apply deletes `data` from an adopted `Secret` and leaves the live `Secret` empty. Because Kix writes `Secret` keys into the write-only `stringData` field, `kix` owns `f:stringData.<key>` in `managedFields` while `data.<key>` stays owned by the previous manager or by no manager at all. After `data` was wiped on a migrated SOPS `Secret`, `kix status` still reported every resource `ok`, and only `kix plan --reconcile` showed `+ $.data`. For the same reason, removing a key from a SOPS file leaves the old key in `data` on the cluster, because `kix` never owned `data.<key>`.
