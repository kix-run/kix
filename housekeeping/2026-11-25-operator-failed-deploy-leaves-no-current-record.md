# 2026-11-25 · `cli/kix-operator/src/controller.rs` · A failed operator deploy leaves the Kix cluster with no current deployment record.

`start_queued` marks the `Active` record `Superseded` before it applies anything. When the new deploy then ends `Failed`, the cluster has no `Active` or `Degraded` record, so `kix status` finds nothing deployed and `kix rollback --operator` must pick the superseded record by hand. `kix deploy` without `--operator` keeps the previous record `Active` until its own run finalizes. Now that the operator gives up after `KIX_DEPLOY_RETRIES`, this state is reached often (seen on kind with a SOPS file the operator could not decrypt). The early supersede also means `finalize_deploy` finds no current record, so an operator deploy never writes `status.previousActivation` or `kix.run/previous`, and `kix rollback` lists it with no predecessor.

Decision required from the maintainer: what the operator does with the old record's drift repair while, and after, a newer deploy fails.

The shared `finalize_deploy` already supersedes the current record when a deploy finishes, so deleting the early supersede is one line. The cost is in drift repair: an `Active` record is repaired every 300 seconds, so the old record would start repairing again once the new one is `Deploying` or `Failed`.

- A. Keep the old record current until finalize, as `kix deploy` does. The old record's repair waits while an operator deploy of the same cluster is `Queued` or `Deploying`. After the new record is `Failed`, the repair resumes and returns the cluster to the old build: it deletes what the failed deploy added and restores what it changed. Cost: an automatic rollback that users must be told about, and a failed deploy's partial changes no longer stay for inspection. Gains `previousActivation`, a correct `kix status`, and a cluster that matches its current record.
- B. Keep the old record current until finalize, but pause its repair while a newer record of the cluster is `Failed`, until a new deploy or rollback finishes. Cost: a rule whose meaning depends on other records' state, and a current record that does not describe the cluster (the CLI has the same gap after a failed `kix deploy`, but runs no repair).
- C. Keep the early supersede, and teach `kix status` and `kix rollback --operator` to name the newest `Superseded` record that `was_ever_current` when no record is current. Cost: two commands each work around the missing record, and operator records still have no predecessor link.

Recommendation: A. It moves the decision of when the old record stops being current to the one place the CLI already uses, and the operator's contract becomes "the cluster converges on the current record" without exceptions.
