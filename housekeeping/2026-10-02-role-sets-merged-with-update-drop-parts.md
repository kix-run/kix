# 2026-10-02 · `kix/lib/vocab/rbac.nix` · Merging two role sets with `//` drops parts whenever both use the same role name, and nothing reports it.

`buildRoleSet` keys its parts by the Kubernetes name, `<role>` and `<role>-binding`, so a ClusterRole set and a Role set that share a name return the same keys, and `clusterSet // namespacedSet` keeps only the Role pair. The dropped ClusterRole is missing from `rawManifests`, the scorecard, and every check. If another part `requires` it, the CLI still deploys it through `kix.run/depends-on`; if not, it is never deployed. Nothing refuses the merge.

No package hits it on 2026-10-02. Of the fourteen other files that call both `mkClusterRoleSet` and `mkRoleSet`, arc, cert-manager (controller, cainjector, webhook), descheduler, prometheus-operator, reloader, snapshot-controller, victoria-metrics-operator, and zfs-localpv merge sets with `//` but give each set's roles different names; infisical-operator, mayastor, and tailscale read each set by fixed keys, so the shared `${name}` in tailscale's cluster and operator sets is safe. A rename in any of the first group would drop parts without an error.
