# 2026-11-28 · `cli/kix/src/cluster/tenancy.rs` · A lost revision that no build at hand names can only be repaired with the old build's commit.

Kix reads a missing or unreadable revision from the build a command deploys or from the build of the record naming it when this machine holds it (`Tenancy::with_rebuilt`). When no such build names it, deploy, rollback, and `kix gc` refuse, and the message says to deploy the named record's build again from its commit. A user who no longer has that commit, and whose machine lacks the build, has no way out short of editing the record by hand.

Options. (1) Leave it: the state needs a revision deleted by hand, and the remedy works whenever the source is in git. Costs nothing. (2) Let `kix gc --full-scan` rebuild a lost built revision as it rebuilds the kept-orphans list: name every object the cluster's field manager applied that no other revision names, and file it under the kept orphans, so a later `--prune` can delete it. Costs a second repair path, and the list may name objects the lost revision did not. (3) Let the deploy do (2) itself. Costs a prune decision made on a guess, which `complete_for_own` exists to prevent. I recommend (2) if users report the state, else (1).
