# 2026-10-02 · `cli/kix-cli/src/commands/deploy.rs` · `kix deploy` finds no previous Activation when the flake attribute differs from the cluster's `buildCluster` name.

`load_old_from_cluster(&args.cluster, ...)` passes the flake attribute (`harbor` in `kix deploy harbor --flake ./clusters`) to `activation::find_active`, which lists records by the `kix.run/cluster` label. The records carry the evaluated name, `test-harbor` from `clusters/test-harbor.nix`. Every deploy of such a cluster prints "No previous activation on cluster. First deploy.", so a repeat deploy re-applies everything (266 configured in the W6 kind run K8), reruns Jobs under the rerun rule, and never prunes objects the build dropped. `clusters/flake.nix` maps `harbor`, `metabase`, and other attributes to clusters named `test-*`; `health.rs` and `rollback.rs` read `args.cluster` the same way. The deploy already holds the evaluated name in `new_graph.cluster_name`, but the local activation cache is keyed by the attribute.

Decision required from Adam: which name identifies a cluster for Activation lookup and the local cache, the flake attribute or the `buildCluster` name, or whether the build should refuse a mismatch.
