# 2026-11-27 · `cli/kix/src/plan/saved.rs` · `kix deploy --plan` does not notice that the same manager changed a drifted field's value again after the plan was saved.

The saved-plan check compares reverted drift by object, path, and field manager (`Rule::NewRevertedDrift`) and ignores the `live` value each drift entry may carry (it is left out when unknown). If `kubectl` changes `spec.replicas` from 3 to 5 after the reviewer saw "3 live", the deploy still takes it back, to the build's value, without the reviewer having seen 5. The fresh plan's values guard the forced apply, but not the step from the reviewed file to the fresh plan. Closing it needs `saved::compare` to compare the `live` values, and a rule for entries where the value is absent. The revert-precondition report said the drift entries carry no values; `DriftChange` in `kix/src/plan/document.rs` has an optional `live`.
