# 2026-10-02 · `kix/lib/meta.nix` · `meta.conflictsWith` matches aliases, so two instances that both set `aliases` escape the one-per-cluster check.

`checkMetaStatic` (`kix/lib/meta.nix:210-228`) looks each `conflictsWith` name up in `resolutionIndex.byKey`, whose keys are instance names and aliases. An instance's `aliases` replace the package's `defaultAliases` (`meta.nix:131`). So when two instances of a package that declares `conflictsWith = [ "cluster:<defaultAlias>" ]` both set `aliases`, neither carries the default alias, the check finds nothing, and the build fails later on a duplicate resource that names no instance, or not at all. A `meta` marker keyed on the package rather than on an alias would cover the cluster singletons (cert-manager, stackgres-operator, infisical-operator, tailscale, kubevirt, cdi, velero, arc, reloader; PURIST B7 in the rework notes).

cert-manager itself is covered by another check: its `meta.annotationDomains` makes a second instance fail first, in one namespace or in two and with or without `aliases`, with "kix: annotation domain 'cert-manager.io' is declared by two instances: cert-manager/cert-manager and cm2/cert-manager. Exactly one package owns an annotation domain." A cert-manager user therefore never sees the "conflicts with 'certManager' (cluster-wide)" message.
