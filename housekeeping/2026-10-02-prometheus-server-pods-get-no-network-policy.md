# 2026-10-02 · `kix/packages/prometheus` · Under default deny the Prometheus server pods get no egress policy, so Prometheus discovers and scrapes nothing.

The prometheus-operator creates the server StatefulSet from the Prometheus custom resource, and no package writes a `kix.operandPolicy` for its pods. On a fresh ludo-kind (W6 kind run K2, Cilium with `networkPolicy.enable`), Cilium dropped about 24,600 SYN packets from `prometheus-prometheus-server-0` to the API server on 6443 in 90 minutes, and `/api/v1/targets` listed no active target. Every "target up" check in the rework plans (loki, ingress-nginx, immich 8081/8082, coredns, stackgres 9187) fails on that cluster for this reason before the scrape-ingress gap in `2026-10-01-netpol-has-no-scrape-ingress-derivation.md` comes into play. The server needs DNS, the API server, and egress to every scrape target, and Alertmanager.
