# 2026-11-18 · `cli/kix/src/cluster/readiness/declared.rs`, `kubevirt` · Declared readiness waits forever on a running VirtualMachine whose generation moved.

Declared readiness requires `status.observedGeneration` to reach `metadata.generation`. A KubeVirt VirtualMachine uses `status.observedGeneration` for the generation its running VMI started from, and keeps `status.desiredGeneration` for what virt-controller has seen. Any spec change that does not reach the running VM raises the generation, so the VM stays "observed generation 1 of 3" until it restarts. A KubeVirt upgrade raises the generation of every existing VM without a user change: the kind test of v1.5.0 to v1.6.6 to v1.7.4 timed out on VirtualMachine `demo` at the second step, as did the v1.5.0 to v1.9.1 test after the upgrade. A readiness rule could name the field that holds the observed generation, such as `/status/desiredGeneration`.
