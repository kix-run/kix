# 2026-11-24 · `v2_discussions/177_workload_cloud_identity.md` · The cloud identity plan names victoria-metrics-operator, but the pods that call a cloud API belong to victoria-metrics-cluster.

Section 8 lists `stable/victoria-metrics-operator` because it has a `serviceAccountAnnotations` option. That option sets annotations on the operator's own ServiceAccount, and the operator calls no cloud API (its `go.mod` at v0.75.2 lists the AWS SDK only as an indirect module). The only pods in the VictoriaMetrics packages that reach object storage are vmbackupmanager sidecars in the vmstorage pods, which `stable/victoria-metrics-cluster` sets up through `extraSpec.vmstorage.vmBackup`. Those pods run as the ServiceAccount the VMCluster's `spec.serviceAccountName` names, or one the operator creates, so the identity belongs on victoria-metrics-cluster, through `kix.cloudIdentity.annotationsFor` or a ServiceAccount the package renders itself. The operator's `serviceAccountAnnotations` option has no description, and no cluster in `clusters/` sets it.
