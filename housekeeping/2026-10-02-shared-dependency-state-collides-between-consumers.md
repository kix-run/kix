# 2026-10-02 · `kix/lib/eval` · Two instances that resolve to one shared dependency can collide inside it, and Kix cannot see it.

Harbor writes to fixed Redis database indexes (0, 1, 2) and a fixed job-queue prefix (`harbor_job_service_namespace`) in its `valkey` dependency. Two Harbor instances in one namespace both auto-resolve the same valkey by alias, so one jobservice can dequeue the other's garbage-collection or replication jobs and the registries share one layer cache. The name-collision checks look at Kubernetes object names, not at keys, database indexes, schemas, or bucket paths inside a dependency, and a package has no way to learn that a sibling instance consumes the same dependency. `kix/packages/harbor/default.nix` documents the limit in its header (one valkey per Harbor) instead of refusing it.
- Hit again 2026-10-02 with `stackgres-database`: two `metabase` instances whose `deps.database` names the same instance evaluate without a warning, then share one schema, each migrating it and each encrypting stored credentials with its own key. n8n and immich have the same shape. A role binding can be exclusive (`kix/lib/eval/hooks.nix`); a `database` dependency cannot say it needs to be the only consumer.
- Hit again 2026-10-02 with `persistent-volume-claim`: a `storage` dependency resolves by alias in the consumer's namespace, so two packages that each take `storage` (vaultwarden and grafana, verified) both mount one ReadWriteOnce claim. The second pod cannot start on another node, and two programs write one directory. lib-reference-checks considered a check for a shared RWO claim and did not add one. The loki package header and `kix.modules.monitoring` give Loki's claim its own name and alias for this reason.
- Hit again 2026-10-17 with `clickhouse-database`: `database` and `user` default to the instance name, so two instances named alike in two namespaces on one ClickHouse server share a user, and the second bootstrap's `ALTER USER` replaces the first one's password. Each still evaluates, and the first consumer's logins start failing after the second deploy. `kix/lib/tests/units/plausible.nix` (plausible-two-namespaces) sets both names by hand for this reason.
