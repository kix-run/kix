# 2026-11-24 · `kix/packages/stable/victoria-metrics-cluster` · The VictoriaMetrics backup sidecar cannot take a cloud identity, only a Secret.

When `extraSpec.vmstorage.vmBackup` is set, vmbackupmanager runs in the vmstorage pods and uploads to object storage with keys from `vmBackup.credentialsSecret`. A user on EKS, GKE, or AKS cannot give it a cloud role through `kix.cloudIdentity`. vmbackupmanager is an Enterprise component (the CRD has `acceptEULA`), so the adoption waits for a user who needs it. Before building it, check upstream whether vmbackupmanager uses the cloud's default credentials when no credentials file is given, and on which clouds. Also decide which ServiceAccount carries the identity. The pods run as the one the VMCluster's `spec.serviceAccountName` names, which vminsert and vmselect share, or as one the operator creates, which would need `kix.cloudIdentity.annotationsFor` and gets no restart stamp. The operator pod itself calls no cloud API.
