# 2026-10-02 · `kix/packages/velero` (`out.mkBackup`, `out.mkSchedule`) · A Backup or Schedule that requires none of its own instance's resources fails the PI wiring check.

`inVeleroNamespace` adds velero's `backupStorageLocation` to the CR's `requires`. That location belongs to the velero instance, so the CR references nothing in the calling instance, and `inverseDeps` in `kix/lib/eval/instance.nix` does not add it to the caller's PackageInstance. `nix flake check ./clusters` failed on `pi-wiring-cluster-velero` with "'Schedule/smoke-daily' in 'smoke' is not referenced by its PackageInstance or its dependencies" until `clusters/test-velero.nix` gave the Schedule `requires = [ self.deployment ]`. The Backup in the same file passed only because it already required the smoke Deployment and ConfigMap.

The example under "Declare backups and restores" in `docs/src/content/docs/how-to/package-task-guides/deploy-velero.mdx` now lists `requires = [ self.deployment ]` and says why. The builders could instead attach the CR to the calling instance themselves. The cluster builds (`nix build ./clusters#cluster-velero`) do not run the PI wiring check; only `nix flake check ./clusters` does. This is the same gap as `2026-10-01-kix-monitor-alert-rules-unreachable-from-package-instance.md`: a part reachable only through another instance's resources falls outside its PackageInstance.
