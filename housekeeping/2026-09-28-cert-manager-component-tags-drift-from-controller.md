# 2026-09-28 · `kix/packages/cert-manager` · Overriding `image.tag` moves only the controller, so one instance can run two cert-manager releases.

One cert-manager release tags the controller, webhook, cainjector, acmesolver and startupapicheck images alike, but `webhook.image`, `cainjector.image` and `acmesolver.image` are separate `kix.options.image` options with their own `v1.17.1` default. An instance that sets `image.tag = "v1.18.0"` gets a v1.18.0 controller next to a v1.17.1 webhook and cainjector, with no warning. startupapicheck follows `config.image.tag` directly and so cannot be pinned by digest at all.

A package cannot default one option from another: `evaluateInstanceConfig` in `kix/lib/eval/resolve.nix` evaluates only the package's options, the dependency injections and the instance config. A proposed fix is an optional package-level `config` module appended there (and passed through by `eval/instance.nix`, `eval/cluster.nix` and `eval/import.nix`), so cert-manager could set `webhook.image.tag = lib.mkDefault config.image.tag` and the same for each component. An instance's own component tag would still win, and `kix.options.image` drops the default digest once the tag moves.
