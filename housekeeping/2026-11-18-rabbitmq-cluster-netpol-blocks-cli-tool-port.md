# 2026-11-18 · `kix/packages/experimental/rabbitmq-cluster` · Network policy blocks the CLI tool port, so `rabbitmqctl list_queues` times out on a cluster of three nodes.

With an enforcer, the package opens only epmd (TCP 4369) and Erlang distribution (TCP 25672) between the RabbitMQ pods. A `rabbitmqctl` run inside one pod listens on a port in the range 35672 to 35682, and the other nodes connect back to it there. Cilium drops those connections (seen with `cilium-dbg monitor --type drop` on clusters/test-rabbitmq.nix, RabbitMQ 4.3.6 and 4.4.1). `rabbitmqctl list_queues` and `list_unresponsive_queues` without `--local` then end with `Some queue(s) are unresponsive` after their timeout, although every queue is healthy. Commands that talk to one node, and the HTTP API, work. RabbitMQ's networking guide lists 35672-35682 as the CLI tools' port range.
