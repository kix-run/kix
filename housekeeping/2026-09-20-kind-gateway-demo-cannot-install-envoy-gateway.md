# 2026-09-20 · `demo/deploy-ludo-kind-gateway.sh` · The envoy-gateway controller install fails twice on the kind gateway variant.

The script applies the upstream Gateway API CRDs with kubectl, then installs the envoy-gateway Helm chart, which ships the same CRDs. The chart's apply conflicts with the client-side-applied annotations (`conflict with "kubectl-client-side-apply"`) and Helm aborts before the controller exists. With `--skip-crds` the chart's own CRDs (EnvoyProxy) are skipped too, so `kix deploy` then fails on `EnvoyProxy/gateway-proxy`. Separately, the chart's certgen Job runs under Cilium's `policyEnforcementMode = always`, which the `cilium` package sets; nothing opens apiserver egress for `envoy-gateway-system`, so the Job fails and the release never installs. Seen 2026-09-20 while testing readiness declarations on kind. Workaround used: a hand-written CiliumClusterwideNetworkPolicy allowing the namespace, then `helm show crds | kubectl apply --server-side --force-conflicts`, then the chart with `--skip-crds`.
