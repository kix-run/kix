# 2026-10-02 · `kix/packages` · Packages share code by importing files from each other's directories, and there is no rule for where shared code lives.

`loki-logs` imports `../clickhouse-logs/vector-agent.nix`, `victoria-metrics-alert` imports from `victoria-metrics-operator` and `alertmanager`, `clickhouse-database` and `clickhouse-cluster` import `../clickhouse/contract.nix`, and `immich-machine-learning` imports `../immich/release.nix`. A reader of the owning package cannot tell that another package depends on the file, so a change there breaks a package that is not in the diff. Kixpkgs needs a defined practice: where shared package code lives (for example a family directory or a shared module location), how it is named, and when it belongs in kix/lib instead. The package-review skill and BEST-PRACTICES should then state it.
