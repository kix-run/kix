# 2026-10-01 · `kix/packages/{grafana,kube-state-metrics,node-exporter,prometheus-operator,victoria-metrics-operator}` · Five monitoring packages take placement options that duplicate `partsOverlays`.

grafana, kube-state-metrics, and node-exporter each take a `nodeSelector` option; prometheus-operator and victoria-metrics-operator take `nodeSelector`, `tolerations`, and `affinity`. Each option copies one pod-spec field under the same name, so a cluster author meets two ways to place the same pod, and other packages offer only the instance's `partsOverlays` (BEST-PRACTICES §5.3). victoria-metrics-operator also takes a `logLevel` option that only sets the `--zap-log-level` flag, which `extraArgs` could carry. node-exporter is a DaemonSet that must run on every node, so its selector is the one case where an option may earn its place.
