# 2026-11-24 · `kix/packages/experimental/velero` · Velero cannot take Azure disk snapshots with a cloud identity.

The Azure volume snapshotter reads `AZURE_SUBSCRIPTION_ID` and `AZURE_RESOURCE_GROUP` only from a credentials file (velero-plugin-for-microsoft-azure `volume_snapshotter.go`, `Init`), even when the pod authenticates with Entra Workload ID. Upstream's guide mounts a file holding only those non-secret values next to the identity. In Kix, `deps.cloudCredentials` holds either a Secret or an identity, so the package refuses an Azure `volumeSnapshotLocation` with an identity. Users on AKS must use CSI snapshots or file-system backup instead. Fixing it needs a way to give the package that file beside the identity, such as an optional second dependency or package options the package renders into a file.
