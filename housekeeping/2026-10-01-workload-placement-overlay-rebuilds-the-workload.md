# 2026-10-01 · `partsOverlays`, `docs/.../patch-package-output-with-overlays.mdx` · Placement goes through `partsOverlays`, but the only way to add a `nodeSelector` is to rebuild the Deployment, which the overlay how-to warns against.

Packages have no `nodeSelector`, `tolerations`, or `affinity` options; placement is an instance `partsOverlays` entry. An overlay receives the built part, so changing one pod-spec field means calling `scope.mkDeployment` again from `rawManifest` and copying `name`, `extraDeps`, and the metadata labels across. The how-to (`patch-package-output-with-overlays.mdx:41-44`) says to avoid overlaying a workload because the rebuild loses what the workload builders attached. A lib helper that patches a workload's pod spec in place would give the convention a supported path.
