# 2026-11-24 · `cli/kix/src/cluster/secrets.rs` · A number in a SOPS file reaches the Secret in sops's spelling, not the file's.

sops parses an unquoted number before it encrypts it, so the file's text is lost at encryption. Seen with sops 3.13.3: `007` becomes `7`, `0x1F` becomes `31`, `1.0` becomes `1`, `1.10` becomes `1.1`, `1e3` becomes `1000`, `12345678901234567890123` becomes `1.2345678901234568e+22`, and `12345678901234567890` (above the signed 64-bit range) makes `sops encrypt` fail with "unknown type: uint64". A PIN, a zip code, or a version string therefore deploys with a different value and no warning. The encrypted file carries `type:int` or `type:float` on each such value, so Kix could warn before decrypting that the value should be quoted to keep it exact.
