# 2026-11-27 · `cli/kix/src/cluster/apply/ssa.rs` · A value no field manager owns that changes again after the plan is set to the build's value without a check.

A scale to zero through the scale subresource leaves `spec.replicas` with no owner in `managedFields` (`UnrecordedScale`). A forced revert asks the API server what it would take, and the server names only fields another manager owns, so such a field is never on the list. A second unrecorded change after the plan leaves the list unchanged, and the apply sets the manifest's value. An unforced apply would do the same, so the gap is about the check, not about force. The old rule, which required the object's `resourceVersion` to match the plan's, caught it. Comparing the whole object without `status` and server-managed metadata would cover it, at the cost of stopping on any unrelated write.
