# 2026-11-18 · `kix/packages/experimental/clickhouse-operator` · The operator cannot list the objects of a ClickHouseKeeperInstallation, so it never deletes the ones a CHK no longer needs.

Every CHK reconcile logs `discoveryStatefulSets():...FAIL to list StatefulSet - err: unable to list: analytics-ha because of unknown namespace for the cache`, and the same for ConfigMaps, Services, Secrets, PVCs, and PDBs. Seen on kind with `clusters/test-clickhouse-operator-upgrade.nix`, with operator 0.27.3 and 0.27.4. Upstream issue Altinity/clickhouse-operator#2117 gives the cause: the Keeper cache is built with `DefaultNamespaces = { "": {} }` whenever `watch.namespaces.include` is unset or holds a regular expression, and controller-runtime v0.18.7 cannot list one namespace from that cache. The package sets `watch.namespaces.include = [ ".*" ]`, so it always hits the bug. The upstream issue says deleting a CHK still works through owner references, and that a Keeper scale-down may leave objects behind; nobody has tested that. Check again at the next operator release.
