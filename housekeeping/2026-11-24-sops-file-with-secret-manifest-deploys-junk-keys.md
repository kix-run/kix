# 2026-11-24 · `cli/kix/src/cluster/secrets.rs` · A SOPS file that holds a whole Secret manifest deploys without error and writes the wrong keys.

Flux encrypts a complete Secret manifest (`apiVersion`, `kind`, `metadata`, `stringData`). Passed to `scope.mkSecret { source = ...; keys = [ "username" "password" ]; }`, `kix deploy` printed "hydrated 5 keys from SOPS" and wrote `apiVersion`, `kind`, `metadata`, `stringData`, and `type` into the Secret, with the nested values as JSON text. `parse_secret_data` turns every top-level key into a Secret key, refuses only a top level that is not an object, and never compares the decrypted keys with the declared `keys`. The page `use-sops-backed-secrets-if-production-ready.mdx` says the deploy stops when the decrypted document is not a top-level key-value map. Anyone moving from Flux hits this first, and the workload can keep running on keys left over from Flux until those are removed.
