# 2026-11-24 · `cli/kix/src/cluster/secrets.rs` · Passing an encrypted `Secret` manifest to `scope.mkSecret` deploys without error and writes manifest fields as `Secret` keys.

Flux SOPS files encrypt a full Kubernetes `Secret` manifest (`apiVersion`, `kind`, `metadata`, `stringData`, and `type`), whereas `scope.mkSecret` expects a flat key-value map. When a Flux SOPS file is passed to `scope.mkSecret { source = ...; keys = [ "username" "password" ]; }`, `kix deploy` prints `hydrated 5 keys from SOPS` and writes `apiVersion`, `kind`, `metadata`, `stringData`, and `type` as `Secret` keys, serializing nested maps as JSON strings. Existing pods can keep running on keys left behind by Flux until Flux's field ownership is removed, hiding the mistake. `parse_secret_data` (`cli/kix/src/cluster/secrets.rs`) accepts any top-level JSON object without rejecting nested objects or checking the decrypted keys against the `keys` declared on `scope.mkSecret`, even though `use-sops-backed-secrets-if-production-ready.mdx` says Kix stops when the decrypted document is not a top-level key-value map.
