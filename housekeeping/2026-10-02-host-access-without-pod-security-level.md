# 2026-10-02 · `kix/packages` · Packages that run privileged or host-network pods declare no `meta.podSecurity`, so a cluster with a baseline or restricted Pod Security level rejects their pods at admission.

`meta.podSecurity` raises the namespace's `pod-security.kubernetes.io/enforce` label to the level a package needs (`kix/lib/eval/cluster.nix:105-151`). These packages hold a host-access grant in `meta.unsafe` and declare no level: `cilium` (`privileged`, `host-network`), `smartctl-exporter` (`privileged`), and `firezone` (`privileged`). `prometheus-operator` renders `hostNetwork = true` when its `hostNetwork` option is set, with no grant and no level. Nothing checks that a package rendering `hostNetwork`, `hostPID`, `hostPath`, or a privileged container declares a level, so the build passes and the deploy fails. A scorecard rule over the rendered pod specs would catch the next one.
