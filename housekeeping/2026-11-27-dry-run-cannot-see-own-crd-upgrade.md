# 2026-11-27 · `cli/kix/src/cluster/classify.rs` · The dry run cannot see that a deploy will update one of Kix's own CRDs.

`InstalledKinds` knows that Kix installs its four CRDs when a deploy starts, so on a fresh cluster their objects are not checked (`crd_installed_by_kix`). It does not know that `own_crds::ensure_all` replaces a CRD whose number is lower than this Kix's. Once a definition's number is raised, the dry run checks Activation, PackageInstance, or revision objects against the old CRD on the cluster, and a field only the new CRD allows comes back `invalid`, so the deploy stops on a refusal that the real deploy would not meet. Every number is 1 today. When one is raised, the dry run must read the live CRD and treat the kind as changed by this deploy (`ChangedCrds`).
