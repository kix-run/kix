# 2026-11-06 · `kix/packages/cilium/netpol-rules.nix` · Policy readiness waits on a Valid condition that only an optional operator validator writes.

Every CiliumNetworkPolicy and CiliumClusterwideNetworkPolicy waits for `Valid=True`. The cilium-operator writes that condition from its network policy validator (`operator/pkg/networkpolicy/cell.go` in Cilium 1.19), which the flag `validate-network-policy` turns on by default. A cluster that sets it to false never gets the condition, and every policy waits until the readiness timeout with "no Valid condition yet". The package does not pin the flag or refuse the setting, and nothing in the deploy output names the flag. The same validator fails a policy with `Valid=False` when it uses an `authentication` rule while the operator runs with mesh authentication off, so that message can point at operator configuration rather than the policy.
