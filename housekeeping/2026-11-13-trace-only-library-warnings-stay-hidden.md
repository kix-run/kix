# 2026-11-13 · `kix/packages/experimental/cilium/netpol-rules.nix` · Cilium's warning about a named target port exists only as a `lib.warn` line, so Kix never shows it when the build succeeds.

`portsToCilium` warns with `lib.warn` when a Service's `targetPort` is a name, because Cilium drops egress on a named port and the consumer's traffic is blocked at runtime. The netpol plugin calls it through the enforcer's `out.netpol` functions (`mkServiceEgressRule` and others in `kix/lib/plugins/netpol/interface.nix`), which return rules and have no way to return a warning. Every other library and package warning now reaches the warning list.
- Hit again 2026-11-14 while giving warnings a record type.
- Partly fixed 2026-11-15 and 2026-11-23: every other trace and `lib.warn` in `kix/lib` and `kix/packages` now returns a warning record. This one needs a choice about the enforcer interface: an optional `egressPortWarnings` function the plugin calls on each edge's ports and returns through the workload interceptor's `warnings`, an error in place of the warning, or the plugin resolving named target ports to numbers from the target workload so the rule works.
