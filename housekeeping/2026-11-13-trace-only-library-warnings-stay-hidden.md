# 2026-11-13 · `kix/lib/scope/validators.nix`, `kix/lib/scope/builders.nix` · Some library warnings exist only as `builtins.trace` lines, so Kix never shows them when the build succeeds.

`kix check` lists the warnings in the cluster's `diagnostics.warnings` (written to `kix-warnings.json`), but several warnings never reach that list. They are traced where they arise and nowhere else: the capability and role warnings in `scope/validators.nix` (for example the warning that `cluster.roles.loadBalancer.binding` is unset, so Kix skipped checking for a load balancer), the edge and interceptor warnings traced onto a workload's `outPath` in `scope/builders.nix`, and the traces in `core/resource.nix`, `eval/auto.nix`, and `eval/view.nix`. They need a channel from resource construction into `_diagnostics`, which `v2_discussions/80_structured_diagnostics.md` sketches.

Packages and vocabulary helpers also warn with `lib.warn`, which reaches no command either: `kix/lib/vocab/expose.nix` (`kix.expose`), and the `spegel`, `mayastor`, `rabbitmq-cluster`, and `cilium` packages (`grep -rln 'lib.warn' kix/packages kix/lib/vocab`). The library tests print them as `evaluation warning:` lines. Each can return a record through the package's `warnings` or an instance processor instead.
- Hit again 2026-11-14 while giving warnings a record type.
- Partly fixed 2026-11-15: the warnings of `scope/validators.nix`, the workload warnings in `scope/builders.nix`, and the `lib.warn` calls in `kix/lib/vocab/expose.nix` now reach the warning list through each resource's `_warnings`. Still traced: `scope.requireMetricsApi` when a package calls it directly (it returns null, so it has nowhere to put a warning; the fix is an API that returns the warning for the package's `warnings`), and the traces in `core/resource.nix`, `eval/auto.nix`, and `eval/view.nix`.
