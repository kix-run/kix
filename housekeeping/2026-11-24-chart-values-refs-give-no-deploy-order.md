# 2026-11-24 · `kix/lib/helm.nix` · Passing a dependency's `out` value in chart `values` does not order the chart's workloads after that dependency.

`renderSpec` strips string context when serializing `values` to JSON, so `backendHost = backend.out.fqdn` renders the hostname without recording a dependency. Passing `deps = [ backend ]` to `importChart` generates network policies, and when `networkPolicy.enable = true` the chart's Deployment comes after `Service/backend` only because its generated egress policy depends on that Service. In `kix build` output for a local test chart, the chart's Deployment has no dependency on `backend` when `networkPolicy.enable = false`, and never waits for `backend`'s own workload. `housekeeping/2026-10-02-import-chart-deps-has-no-user.md` says `deps` gives "the ordering", which holds only for the Service and only when network policy is enabled.
