# 2026-11-18 · `kix/lib/flavors/kind.nix` · The kind flavour waits for kind's own CoreDNS even when a managed coredns instance serves DNS.

The flavour declares the `platform-dns` import of `Deployment/coredns` as required. A managed instance that claims the `dns` role does not turn the import off. On a kind cluster created without kubeadm's CoreDNS addon, every deploy waits for `PackageInstance/platform-dns` until it times out with "import target Deployment/coredns (apiVersion apps/v1) not found". `clusters/test-coredns.nix` sets `platform-dns.optional = true` to deploy at all. The flavour could drop the import when another instance provides `dns`, or mark it optional as the other flavours do, which loses the DNS ordering that 2026-10-02-optional-platform-dns-orders-no-workload.md describes.
