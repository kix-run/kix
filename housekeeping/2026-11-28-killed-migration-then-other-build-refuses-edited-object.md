# 2026-11-28 · `cli/kix/src/cluster/revision/convert.rs` · A migration deploy killed after its conversion, then a deploy of another build, reports a field conflict where it should report drift.

The conversion re-keys each converted entry to the object hash of the build the converting run deploys (`Carry::revision`, `BuildHashes::object_hash_for`), and a record is converted once. If that run is killed and the user then deploys a different build, an object edited before the upgrade has no entry for its new object hash. The plan applies it without force, and Kubernetes refuses it with a field ownership conflict. The test `a_migration_that_stops_after_its_conversion_still_reports_drift` covers only the same build on both runs. Options in the review-fix report: keep the old identity hash beside the object hash in converted entries, re-key from the live identity hash, or accept and document `--force-conflicts`.
