# 2026-11-23 · `cli/kix/src/cluster/kept.rs` · A ceded path with a selector of two keys works in the deploy retry and fails in the check that the cluster kept what Kix sent.

Two functions match a `kix.run/cede-fields` declaration against a path. `covers` in `cli/kix/src/cluster/apply/ssa.rs` matches it against the API server's conflict path, and it understands `spec.ports[port=53,protocol="UDP"].name`. `cedes` in `kept.rs` matches it against a path from the diff engine, where a list item is named by the key that `kix_core::manifest::diff::keyed_lists` picks, such as `53:UDP` or the port's `name`. `cedes` returns `false` for any selector with more than one key, and a selector of one key matches only when its value is the diff key. So a package that declares `spec.ports[port=53,protocol="UDP"].name` gets the retry without that field, and the deploy then warns that Kubernetes did not keep that field when the controller changes it. A declaration with `[*]` is not affected.

The diff key of an item depends on both lists (ports switch to `port:protocol` when any item has no name), so `cedes` cannot work it out from the path alone. A fix needs one field path type that both functions use, matched against the item itself rather than its diff key.
