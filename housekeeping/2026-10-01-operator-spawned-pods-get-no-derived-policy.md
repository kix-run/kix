# 2026-10-01 · `kix/lib/plugins/netpol` · Pods an operator creates at runtime get no derived network policy.

Netpol derives egress and ingress only for workloads a package renders and for the operands of a CR that declares `factBehavior`. Pods a controller launches on its own get nothing, so under default-deny they cannot reach DNS, the API server, or their store until the package writes a `kix.operandPolicy` for them. Velero's data-path pods and kopia maintenance Jobs need one (`velero-data-path` in `kix/packages/velero/default.nix`), and so does any operator that runs Jobs. A missing policy shows up only on a cluster with network policy on, as a backup or Job that times out.

- tailscale: the proxies, the DNSConfig nameserver, and Recorder pods get `kix.operandPolicy` policies (`proxyPolicies` in `kix/packages/tailscale/default.nix`), and the backend side of a proxy is opened by `out.mkBackendPolicy`. The proxy policies select by the operator's labels, which do not tell LoadBalancer proxies from egress proxies, so both accept traffic from the cluster.
- stackgres: `kix/packages/stackgres-cluster` writes policies for the SGCluster's pods (`app=StackGresCluster`), which also covers the scheduled backup CronJob's pods. SGDbOps Job pods (`app=StackGresDbOps`) and the pods of a manually created SGBackup (`app=StackGresBackup`) get none, so a restart, vacuum, or majorVersionUpgrade SGDbOps cannot reach the API server under the namespace default-deny. SGShardedCluster, SGDistributedLogs, and SGStream pods built from `stackgres-operator`'s `out.crds` get none either.
