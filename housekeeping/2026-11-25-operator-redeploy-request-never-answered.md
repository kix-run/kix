# 2026-11-25 · `cli/kix-operator/src/controller.rs` · A request to deploy the current build again is never answered when the operator's run stops at a failure.

`kix deploy --operator` of the build that is already `Active` writes a request on that record, and the operator runs `Reconcile::Redeploy`. When that run stops at a failed resource, the reconcile returns an error and the record stays `Active`. The next reconcile finds no pending request and runs `Reconcile::Repair`, which never writes `status.finishedRequest`, so the command waits out its 600 seconds and times out even if a later repair succeeds. The retry count does not apply either, because the record is never `Deploying`. Marking the current record `Failed` would leave the cluster without a current record, so the answer needs another way to report a failed request on a current record, such as a failure field the CLI reads once `finishedRequest` matches, gated by a new `kix.run/operator-features` value so an older CLI does not take it for success.
