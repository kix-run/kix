# 2026-11-18 · `kix/packages/experimental/stackgres-cluster` · An SGCluster applied outside Kix gets no network policy, so its controller cannot reach the API server under default deny.

Found while testing the StackGres 1.19.5 bump on kind with `networkPolicy.enable = true`. An SGCluster that Kix does not build (here `data/pg2`, applied with kubectl) sat in the `data` namespace under `data-default-deny`. Its cluster-controller timed out on `10.96.0.1:443` and crashed in a loop, so the cluster never bootstrapped. The Kix-built `pg` in the same namespace worked, because `pg-operand-egress` and `pg-operand-ingress` select only its Pods. Where to look: the policies that `stackgres-cluster` writes select by the SGCluster the package builds, and nothing covers other SGClusters in a namespace that has default deny.
