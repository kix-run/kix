# 2026-11-20 · `.github/workflows/pages.yml` · The release index is signed only when the whole site, docs included, builds, so a week of broken docs builds stops Kix from choosing releases.

Kix refuses an index seven days after kix.run made it, and "Sign the release index" is one step at the end of the single `deploy` job, after the landing page, every docs build, and the `kix-examples` checkout. A docs build that stays broken for a week therefore stops `kix self install <minor>`, `kix upgrade`, and `kix self update` everywhere. Exact versions still install with a warning. GitHub also turns off a scheduled workflow in a public repository after 60 days without activity, which would stop the daily signing. The workflow `index-expiry.yml` opens an issue when the live index has less than three days left, so a person hears about it in time, but the renewal itself still depends on the docs build.

Options: (1) a separate small workflow that builds and signs only the index, and deploys it where the Worker serves it (for example Workers KV or R2, since a Pages deploy replaces the whole site); (2) keep one workflow but let the site deploy with the last good docs when a docs build fails; (3) a scheduled check that opens an issue when the live index has less than three days left. Option (3) is in place. I recommend (1) as well.
