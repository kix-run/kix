# 2026-10-02 · `kix/lib/eval/resolve.nix` · An instance named `prometheus` answers every `prometheus` dependency in its namespace, even when it is a Prometheus server and not the operator.

`prometheus` is the operator's alias, and an instance's name also answers a dependency of that name. Naming the prometheus package's instance `prometheus` (the obvious name) makes grafana's and kube-state-metrics' optional `prometheus` dependency resolve to the server, or to two candidates, and evaluation fails with "dependency 'prometheus' matches multiple instances" or a missing `mkServiceMonitor`. The monitoring module avoids it by naming the server `prometheus-server`; `kix/lib/tests/units/monitoring-stack.nix` hit it. ROADMAP's "DI capture-by-name hazard" item describes the same mechanism for `storage`.
