# 2026-10-01 · `kix/packages/firezone` · firezone breaks the option contract and takes its secrets as plain options, so `kix/package-eval.nix` exempts it from the contract.

Eight options (`wireguard`, `admin`, `secrets`, `database`, `saml`, `telemetry`, `service`, `resources`) are `types.anything` with non-empty defaults, so an instance that sets one key loses the rest and a misspelled key passes. Partial values work today only because `kix/lib/eval/resolve.nix` merges top-level defaults back after evaluation; `clusters/test-immich.nix` and `kix/package-eval.nix` both set part of `wireguard` and `admin`. The WireGuard private key, the admin password and the six application secrets are plain-text options written into a `scope.mkSecret`, so they sit in the cluster file and the Nix store. The package pins Firezone 0.7.26; upstream's current releases are the 1.x line, which this package does not support. It depends on the whole `postgres` cluster instead of a per-app `database`. Related entries: `2026-09-27-firezone-password-secret-ref-fails-build.md`, `2026-10-01-firezone-external-url-ignores-its-route.md`.

Decision required from Adam: rework firezone (1.x, typed options, credentials through secret dependencies) or delete it with its `clusters/test-immich.nix` instances. Either way, remove its entry from `optionContractExemptions` in `kix/package-eval.nix`.
