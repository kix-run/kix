# 2026-11-24 · `kix/packages/experimental/external-dns` · `external-dns` forbids authenticating with the node's cloud role, while `cert-manager` and StackGres will allow it.

When `config.provider` targets AWS, Google Cloud, or Azure and `deps.providerCredentials` is unset, `external-dns` fails evaluation with `[K1798]`. As `changes/feat-cloud-identity-external-dns-credentials.md` notes, this also blocks instances whose pods previously relied on the node's cloud IAM role. By contrast, `v2_discussions/180_cloud_identity_across_packages.md` allows `cert-manager` and StackGres to omit a `ServiceAccount` cloud identity so their pods can fall back to the node's role. On a self-managed cluster whose nodes hold DNS permissions, users will be able to run `cert-manager` with node credentials, whereas `external-dns` rejects that setup.
