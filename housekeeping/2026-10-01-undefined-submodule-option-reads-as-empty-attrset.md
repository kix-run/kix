# 2026-10-01 · package options · A submodule option with no default and no definition evaluates to `{ }` without its fields.

With the nixpkgs the flake pins, `lib.evalModules` gives such an option the value `{ }`, so a build that reads `config.x.field` stops with "attribute 'field' missing" at the read site instead of the module system's "accessed but has no value defined" error naming the option. `builtins.tryEval` cannot catch the missing-attribute error, so tests cannot assert on it either. `kix.options.image { }` works around it with an empty option default (`kix/lib/vocab/compose.nix`); any other required submodule option a package declares has the same gap. Reproduce: `(lib.evalModules { modules = [ { options.x = lib.mkOption { type = lib.types.submodule { options.f = lib.mkOption { type = lib.types.str; }; }; }; } ]; }).config.x.f`.
