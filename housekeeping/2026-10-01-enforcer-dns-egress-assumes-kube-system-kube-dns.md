# 2026-10-01 · `kix/lib/plugins/netpol/derive.nix` (`enforcerApi.dnsEgressRule`) · The DNS egress rule every workload gets names `kube-system` and `k8s-app: kube-dns` instead of reading the `dns` provider.

The enforcer package's `dnsEgressRule`, which `derive.nix` adds to every workload's policy, allows egress only to pods in `kube-system` labelled `k8s-app: kube-dns`. A managed DNS provider in another namespace, or with other labels, is unreachable under network policy, and nothing in the graph says so. The coredns package refuses to build outside `kube-system` when `networkPolicy.enable` is set, which covers coredns only. Deriving the namespace and selector from the `dns` provider's `out` would retire that check, and touches `plugins/netpol/derive.nix`, the enforcer's rule builder, and every flavour's `platform-dns` import.
- Checked 2026-11-23: a managed coredns's `out` has `selector` but no namespace, and the gke-autopilot and openshift imports sit outside their Service's namespace, so `findRoleProvider`'s `ns` is wrong for them. About twenty packages, and the cilium enforcer for its own pods, read `netpol.dnsEgressRule` as a constant, so a derived rule needs the library to build it in the handle it gives packages, with the dns provider's own instance excluded to avoid a cycle.
