# 2026-09-27 · `kix.untrackedRef` · A workload that mounts an optional Secret it creates itself has no way to name its creator, so the `untrackedReferences` audit lists it forever.

`kubevirt` mounts `kubevirt-operator-certs` and `stackgres-operator` mounts `${name}-certs`, both with `optional = true`. The operator Deployment that mounts each Secret is the one that creates it: stackgres sets `INSTALL_CERTS=true`, and the kubevirt Role grants `create` on that name. The `{ kind; name; by; }` form does not fit. A `kind` stamps `kix.run/expects`, so deploy would wait for a Secret that exists only after the Deployment runs, and `by` would make the Deployment depend on itself. The bare form is correct, so the audit reports 10 entries across every-package, 9 of them `stackgres-operator-certs` repeated in each package that pulls in stackgres-operator. The ref cannot be dropped either, because `scope/validators.nix` `checkNamespacedRefs` ignores `optional`.

Decision required from Adam: whether to add a form for a workload that creates its own optional Secret (for example `by = "self"` with no expectation, or `checkNamespacedRefs` accepting an `optional = true` mount), and have the audit skip it.
