# 2026-11-24 · `kix/packages/experimental/external-secrets`, `kix/lib/vocab/cloud-identity.nix` · `out.mkSecretStore` cannot pass its own instance to `kix.cloudIdentity.ambientProblem` as `holder`.

`kix.cloudIdentity.ambientProblem` expects `holder` to be a resolved dependency value and reads its `_meta.namespaceName`, `_meta.instanceName`, and `out.identityCloud`. Because `out.mkSecretStore` is defined inside the `external-secrets` package's own `build`, the consumer holds that dependency value, while `mkSecretStore` has only `scope` and no library helper for its own dependency handle. Writing `{ _meta = { namespaceName = scope.namespaceName; instanceName = scope.instanceName; }; out.identityCloud = ...; }` in the package would couple it to the internal `_meta` record shape. Section 7 of `v2_discussions/180_cloud_identity_across_packages.md` asks `mkSecretStore` to call `ambientProblem` on stores without `auth` whose cloud differs from the controller's identity. Pull request #340 ships without that check, so a store targeting another cloud than the controller's identity passes evaluation and fails at run time.

Decision required from the maintainer: how should a function in `out` name its own instance to `kix.cloudIdentity.ambientProblem` (options in the PR #340 description; see `v2_discussions/180_cloud_identity_across_packages.md`)?
