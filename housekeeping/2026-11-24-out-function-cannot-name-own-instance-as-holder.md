# 2026-11-24 · `kix/packages/experimental/external-secrets`, `kix/lib/vocab/cloud-identity.nix` · `out.mkSecretStore` cannot pass its own instance to `kix.cloudIdentity.ambientProblem` as `holder`.

Doc 180 (`v2_discussions/180_cloud_identity_across_packages.md`, section 7) asks `mkSecretStore` to refuse a store with no `auth` whose cloud differs from the controller's identity. `ambientProblem` takes `holder`, a dependency value, and reads its `_meta.namespaceName`, `_meta.instanceName`, and `out.identityCloud`. `mkSecretStore` is a function in the external-secrets instance's own `out`, so the consumer holds that dependency value and the function does not. No library helper gives a build its own instance as a dependency value. The only way today is for the package to write a record shaped like one (`{ _meta = { namespaceName = scope.namespaceName; instanceName = scope.instanceName; }; out.identityCloud = ...; }`), which ties a package to the internal shape of dependency values. So pull request #340 ships without the check, and a store for another cloud than the controller's identity builds and fails at run time.

Decision required from the maintainer: how an `out` function names its own instance to `ambientProblem` (options in the PR #340 description).
