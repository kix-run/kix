# 2026-10-01 · `kix/lib/modules.nix` · Whether the cluster runs kube-proxy is not a cluster fact Kix can read.

`cilium` keeps the chart's `kubeProxyReplacement = false` and a cluster turns replacement on through `values`, together with `k8sServiceHost`/`k8sServicePort`. Kix cannot check the node-side half: on k3s `--disable-kube-proxy`, on RKE2 `disable-kube-proxy: true`. Replacement on beside a running kube-proxy, or off on a node without one, breaks Service routing at runtime and nothing fails at evaluation. A `cluster.network` fact for kube-proxy would let the package derive the value and refuse a mismatch.
