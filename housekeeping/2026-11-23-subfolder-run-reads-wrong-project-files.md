# 2026-11-23 · `cli/kix-cli` · Kix run from a subfolder of a project evaluates the parent project but reads `kix.toml` and `flake.lock` from the subfolder.

When the `--flake` folder (by default the working folder) has no `flake.nix`, Nix looks for one in the folders above and evaluates that project. Kix reads the project's files from the `--flake` folder itself: `kix.toml` (`commands::select_builder`), the `[versions]` table (`kix::versions::choose` in `dispatch::prepare_evaluation`), and `flake.lock` (`select::project_kix`, which then skips choosing a version). So `kix build c` run in `clusters/` uses the default builder and the running Kix, whatever the project sets. A project that sets `builder = "nix"` fails with a builder mismatch that does not mention the folder. Kix should either find the project folder the way Nix does and read every file there, or refuse a folder without a `flake.nix`. `dispatch::require_flake` refuses only when no folder above has one either.
