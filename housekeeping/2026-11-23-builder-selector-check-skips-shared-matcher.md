# 2026-11-23 · `kix/lib/scope/validators.nix` · The workload builders compare a selector with its pod labels in their own code instead of the shared matcher.

`checkSelectorSubset` (called from `scope/builders.nix` in `mkWorkload` and the Helm workload path) asks the same question as cross-resource check 9 in `eval/validate.nix`, which uses `core/label-selector.nix`. The builder reads `matchLabels` only and compares values with `toString`, while the matcher also reads `matchExpressions` and compares values as they are. So two pieces of code decide whether a workload's selector matches its own pods, and they can disagree on a label value that is not a string. The builder's message, which names the missing and mismatched keys, is better than check 9's, so keep that message whichever way the two are joined.
