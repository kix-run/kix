# 2026-11-15 · `cli/kix-operator/src/controller.rs` · The operator cannot stop a deploy once it has started.

`run_reconcile` gives the engine a `CancelToken` that nothing cancels, and a readiness timeout fixed at 300 seconds that `kix deploy --operator --timeout` does not change. A newer request waits until the current deploy ends, however long its resources take. Cancelling on operator shutdown would be wrong today: a cancelled run marks its record `Failed`, and the operator resumes only `Deploying` records. Options: keep a token per Kix cluster in the operator's `Context` and cancel it when a newer request for that cluster arrives, which needs a watcher beside kube-runtime's controller (it runs one reconcile per object at a time); give the record a phase or field that says "interrupted, resume me" so shutdown can cancel; carry `--timeout` on the Activation request.

`start_queued` supersedes only an `Active` or `Degraded` record (`Records::active`). It may start a Queued record of the same Kix cluster while another record is still `Deploying`, so two deploys would write at once. I did not confirm this on a cluster.
