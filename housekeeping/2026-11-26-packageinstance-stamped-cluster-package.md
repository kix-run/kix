# 2026-11-26 · `cli/kix-core/src/eval/stamp.rs` · Every `PackageInstance` record carries `kix.run/package: _cluster`, so any reader of that stamp places it wrong.

The package index lists only the resources an instance renders, so `stamp_annotations` stamps the instance's own record as a cluster-level object. Readers that want the instance must call `store_graph::instance_of_record`, which reads the record's spec; `synthesize_placed` and `kix gc --full-scan` do. Other readers of `kix.run/package` (`scheduler/plan.rs` node labels, `upgrade/compare.rs`) still see `_cluster`. Stamping records with their instance would end the split, but it rewrites every live `PackageInstance` once and changes what `synthesize_placed` groups as a standalone package, so it needs its own change record.
