# 2026-11-26 · `kix/packages/experimental/stackgres-operator` · Prune deletes the StackGres operator before its webhook configurations.

The package renders `validatingWebhook` and `mutatingWebhook` with metadata only, because the operator writes the entries. The operator Deployment `requires` both configurations, and the operator Service depends on the Deployment's selector. So prune deletes the Deployment first, then the configurations. For a moment the API server calls webhooks with no pods behind them, and any StackGres create or update fails. The webhook Service edge in `graph::dependency_pairs` cannot help, since the manifest names no Service, and `requires = [ self.operatorService ]` on the configurations makes a cycle with the Deployment's `requires`. One option is to drop the Deployment's `requires` on the configurations, if the operator creates them when they are missing, and have the configurations require the Service. It needs a live test of a fresh install.
