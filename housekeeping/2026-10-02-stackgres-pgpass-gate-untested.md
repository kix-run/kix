# 2026-10-02 · `kix/packages/stackgres-cluster` · Replicas may lose streaming after a restart, and the deleted workaround's test has not run.

StackGres issue #1441 (open on 2026-10-01) reports Patroni's pgpass file going back to mode 0660 when a pod starts, after which libpq refuses it and a replica cannot stream from the primary. `stackgres-pgpass-perms-fix` worked around it with a cluster-wide `pods/exec` grant and is deleted. The default is now 2 instances at availability pod and node, and 3 at zone, which is the case the workaround served. Nobody has yet run the check on kind: with 2 instances, delete the replica pod, then run `stat -c %a /var/lib/postgresql/pgpass` in its patroni container and `patronictl list` (the replica should be `streaming`). A candidate fix if the mode reverts is `pods.persistentVolume.fsGroupChangePolicy = "OnRootMismatch"` on the SGCluster (the kubelet's recursive fsGroup chmod at mount is a suspected cause).
