# 2026-11-24 · `kix/packages/experimental/db-operator-instance` · A package cannot tell whether a dependency's address points inside or outside the cluster.

db-operator-instance must open world egress for the operator's controller when its `postgres` server is outside the cluster, and nothing when the address carries an in-cluster endpoint fact. Packages cannot read endpoint facts, so the package reads `out.external = true`, which the cluster author writes on the server's `kix.mkImport`. An import that forgets it gets no egress, and its DbInstance never becomes ready under default deny. The smtp contract has the same flag with the opposite default (`kix/contracts/stable/smtp.nix`). Options: a lib helper that reports whether a string carries an endpoint fact; an `external` field on a Postgres server contract that every server package publishes as false; or keep the per-import flag and document it in `kix.mkImport`'s reference.
- The two packages that read this flag give it opposite defaults: `kix/contracts/stable/smtp.nix` (`external = out.external or true`) treats a server without the flag as outside the cluster, and db-operator-instance treats one as inside. One concept has two defaults.
