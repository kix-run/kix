# 2026-11-27 · `cli/kix/src/cluster/drift.rs` · The operator sends an apply Kubernetes refuses, on every repair, when another manager owns a field the build spells differently from the server.

`drift::conflicts` walks the manifest along the path Kubernetes recorded for the other manager's field (`ForeignField::value_in`). It finds nothing for a list element whose key includes a part the server defaults (`k:{"port":80,"protocol":"TCP"}` against a manifest port without `protocol`), or for a Secret value given in `stringData` and stored as `data`. It then answers "no conflict", so the operator sends an unforced apply, Kubernetes refuses it, and the repair requeues with an error, where it should leave the object and emit `DriftNotReverted`. The CLI's forced revert now asks the API server with a dry run (`apply::takes_back`) and is not affected. Asking the server the same way would fix the operator too.
