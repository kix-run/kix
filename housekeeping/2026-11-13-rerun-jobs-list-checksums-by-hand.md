# 2026-11-13 · `kix/packages/*` · A rerun Job must list a checksum annotation for every object it reaches through the API, and a forgotten one goes unnoticed.

A Job with `kix.run/rerun: on-change` runs again when its `kix.run/rerun-hash` changes. That hash covers the Job's own manifest and the Kix-built Secrets and ConfigMaps its pod reads, but not the objects it reaches through the Kubernetes API or the network. Each package therefore lists `checksum/<name>` annotations for the objects its Job checks or bootstraps: the webhook checks in cnpg-operator, rabbitmq-operator, external-secrets, and stackgres-operator, the cert-manager startupapicheck, the ingress-nginx certgen Jobs, and the database server in stackgres-database and clickhouse-database. The cnpg-operator webhook check once missed both webhook configurations, and nothing checks that the list is complete.

Proposed design: `mkResource` folds the `out.contentHash` of each resource in a rerun Job's `requires` into `kix.run/rerun-hash`. `requires` then means "run again when this changes" for such a Job, and the lists go away. It costs a meaning for `requires` that differs between rerun Jobs and other resources, and a package that needs a Job to wait for an object without rerunning would need another way to say so.
