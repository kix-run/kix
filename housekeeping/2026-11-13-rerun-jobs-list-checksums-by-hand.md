# 2026-11-13 · `kix/lib/core/resource.nix` · A rerun Job must list a checksum annotation for every object it acts on, and a forgotten one goes unnoticed.

A Job with `kix.run/rerun: on-change` runs again only when its `kix.run/rerun-hash` changes, and that hash covers only the Job's own manifest. Each package therefore lists `checksum/<name>` annotations by hand for the objects its Job checks or bootstraps. The cnpg-operator webhook check missed both webhook configurations, the cert-manager startupapicheck missed the webhook Service, and the ClickHouse health probes missed the credentials Secret. The `rerun` cluster processor (`kix/lib/plugins/rerun/module.nix`) warns only for Secrets and ConfigMaps the Job reads through volumes and env, because it cannot tell an object the Job acts on from one it only waits for.

Proposed design: `mkResource` folds the `out.contentHash` of each resource in a rerun Job's `requires` into `kix.run/rerun-hash`. `requires` then means "run again when this changes" for such a Job, and the hand-written lists go away. It costs a meaning for `requires` that differs between rerun Jobs and other resources, and a package that needs a Job to wait for an object without rerunning would need another way to say so.

Another design option: the `rerun` cluster processor already works out, from string context, which Kix-built Secrets and ConfigMaps a rerun Job's pod spec reads without a checksum. Kix could fold the content hashes of those objects into the Job's `kix.run/rerun-hash` instead of warning about them. This covers the objects a Job reads, though not the ones it only acts on through the API.
