# Housekeeping review — 2026-09-20

Covers 46 entries written between 2026-09-18 and 2026-09-20. Two were
closed while reviewing; the rest of this document is the proposal as it
stood then. **Most of it was then carried out in the same session — see
"What was done" at the end for which themes landed, which were narrowed
and which were deliberately left.** 21 entries remain open.

Every entry comes from the same three days of work: the harbor rewrite,
the seal conversion of the operator packages, and the first real kind
deploys of both. Almost nothing here is a bug in one package. The bulk is
the lib and the CLI meeting real operators and a real CNI for the first
time and finding the gap between what the compiler checks and what
Kubernetes then does. The largest group is the scorecard: it cannot be
turned on in full on any cluster because several rules disagree with the
manifests the lib's own builders produce, so it was off everywhere and
found nothing until `clusters/test-harbor.nix` forced it on. The second
largest is the deploy verdict, which judges a workload by pods the
controller is about to replace.

## Themes, most worth doing first

### 1. Scorecard rules disagree with what the builders produce, so no cluster runs the full rule set

**Entries:** 2026-09-18 scorecard-off-in-every-cluster,
label-standards-fires-on-every-kix-workload,
nonroot-rule-fails-operator-packages,
cert-manager-annotation-domain-has-no-declarer,
two-of-64-packages-set-meta-owner; 2026-09-19
security-rules-fail-any-kix-managed-cni,
package-pdb-options-duplicate-the-derived-pdb (the `hasPDB` half),
from-workload-cannot-build-headless-service (the `selectorCoherence`
half).

**What it costs us:** The scorecard is the thing that would have caught
harbor's 15 label errors and its empty database password months earlier.
It was off because turning it on fails the build: `security.nonRoot`,
`noHostNetwork` and `noPrivileged` are errors and fire on every cluster
that installs cilium or an operator through kix. Turning it on with
overrides, as `test-harbor.nix` does, buys a build that prints about
sixty warnings, most of them wrong: `hasOwner` on every package,
`labelStandards` on every `mkWorkload` workload that does not hand-copy
its labels, `nonRoot` on the three operators that do set it (at pod
level, which the rule does not read), `annotationDomainOwnership` on
every TLS Ingress. Real findings (harbor's writable root filesystems,
arc's missing probes) are buried in that noise.

**What would remove it:** Two things, in order.

1. Make the rules read a sealed manifest the way Kubernetes does.
   `nonRoot` reads `spec.securityContext.runAsNonRoot` when the
   container does not set its own. `labelStandards` reads the labels
   `mkWorkload` stamps, or `mkWorkload` stamps `app.kubernetes.io/name`
   on the workload's metadata as well as its template (the second is
   better: every other tool reads metadata labels too). `hasPDB` reads
   the derived PDB or retires. `annotationDomainOwnership` follows the
   transitive dependency closure, or the flavor sets
   `scorecard.knownAnnotationDomains` for `cert-manager.io`, which the
   rule's own message already suggests.
2. Let a package declare the exemption it needs, the way `meta.unsafe =
   [ "raw-pvc" ]` already works for raw PVCs and is audited by
   `unsafeGrants`. Cilium declares `host-network` and `privileged`; the
   security rules skip the grant and the audit rule lists it. This keeps
   the errors as errors for everyone else, which a per-namespace
   severity override in a cluster file does not.

`hasOwner` is a decision, not a rule fix: either `meta.owner` is
required and `meta.nix` fails the build without it, or the rule is
`info`. Two of 64 packages set it today.

**Recommendation:** Do the two rule fixes (`nonRoot` pod-level,
`labelStandards` via `mkWorkload`) and the `meta.unsafe` grants for
cilium, then make `clusters/test-harbor.nix` run `rules = kix.rules`
with no overrides as a flake check that CI builds. Until a cluster
builds with the full set, every other rule in `kix/lib/rules/` is
untested against the lib.

### 2. Two committed generated outputs drift, and one of them has the site down

**Entries:** 2026-09-19 cli-snapshots-stale; 2026-09-20
offline-captures-stale-manifests.

**What it costs us:** `pages.yml` has failed on its last three runs on
main, since 2026-09-19 22:07 UTC, on the "Check offline captures are
fresh" step. That step sits inside the deploy job, so kix.run does not
redeploy while it is red, and GitHub Pages artifacts expire after about
a day. Separately, four CLI snapshot tests fail on main and nothing
runs `cargo test` in CI (ROADMAP already notes this), so the failure

**What would remove it:** Refresh both outputs now. Then move the

snapshots also want store paths and activation hashes normalised, or
they will go stale on every lib change that touches the example.

**Recommendation:** Refresh the captures today, on its own PR, so the
site deploys again. The CI workflows follow.

### 3. The deploy verdict reads the wrong pods

**Entries:** 2026-09-19 readiness-judges-a-workload-by-its-stale-pods,
controllers-without-probes-read-as-ready, job-ttl-zero-fails-readiness,
two-workloads-in-one-instance-can-share-a-selector.

**What it costs us:** Four wrong verdicts on the two kind runs: two
Deployments failed on pods the controller was deleting, one StatefulSet
failed on an old image, two controllers reported ready seconds before
crash-looping, one Job's success was reported as a fetch failure that
cancelled ingress-nginx and the Activation, and velero's Deployment was
judged by a node-agent pod because both workloads matched the same
selector. Each one costs a rerun and a bisect, and the false "ready" is
the worst kind: the deploy carried on and applied the dependents.

**What would remove it:** In `cli/kix/src/cluster/readiness.rs`, select
pods by the current revision (Deployment: newest ReplicaSet's
`pod-template-hash`; StatefulSet: `status.updateRevision`; DaemonSet:
`controller-revision-hash`) and give the controller a grace period
before failing on a pod of an old revision. A Job whose object vanishes
after the CLI has seen `succeeded >= 1`, or whose TTL is zero, counts
complete. In the seal, compare each workload's selector against the
other workloads' template labels in the same instance and refuse an
overlap; the seal already has every workload in hand. For probe-less
controllers, `reliability.hasProbes` already exists and only needs the
scorecard on (theme 1); a `minReadySeconds` default in `mkWorkload`
would make "Available" mean something in the meantime.

**Recommendation:** Revision-aware pod selection first; it is the
change that removes the class. The overlap check is a small validator
and can go with it.

### 4. Network policy is derived only from edges kix renders, and three kinds of traffic fall outside

**Entries:** 2026-09-18 no-netpol-edge-from-ingress-controller
(hit twice); 2026-09-19 pods-outside-kix-namespaces-have-no-dns,
named-target-ports-in-hand-written-services.

**What it costs us:** Every request through harbor's Ingress returned
504 until the package opened its web port to all pods. Every debug pod,
`kubectl run` and operator-created Job on a cluster with enforcement
`always` has no DNS, and the failure reads as a DNS outage. 33 Service
ports in 20 packages carry a named `targetPort`, and cilium drops
egress to a named port; the translator only warns when some pod dials
the Service, so the other packages find out on their first consumer.

**What would remove it:** `kix.expose` knows both ends of the ingress
edge, so it emits the controller-to-backend policy itself, with the
ingress or gateway package publishing its pod selector through `out`.
The cilium package gets a cluster-wide DNS egress policy when
enforcement is `always` (one CCNP allowing UDP 53 to the DNS role),
since kix chose the enforcement mode and owns its consequence. A
Service validator in the seal refuses a string `targetPort`, after a
one-time sweep of the 33 sites; the seal sees every Service, so the
check is cheap.

**Recommendation:** The validator and the sweep first (an afternoon,
and it stops the class). The ingress edge next; `v2_discussions/
archive/96_netpol_autogeneration_blindspots.md` already lists it.

### 5. Field ownership between kix and an operator is all-or-nothing

**Entries:** 2026-09-19
an-operator-that-rewrites-its-crd-conflicts-with-every-redeploy,
stackgres-operator-rewrites-its-own-webhook-rules,
diskpool-crd-is-installed-by-the-operator.

**What it costs us:** The second deploy of any cluster with
stackgres-operator fails and cancels the operator's PackageInstance and
the Activation. `--force-conflicts` gets past it once, for every
resource in the deploy, and the operator takes the field straight back.
The cdi case was fixed by shipping the CRD the way the operator rewrites
it, which is a fix per operator and per version.

**What would remove it:** A resource needs a way to say "this field is
the operator's". That is a design: a per-resource declaration compiled
into the manifest and read by `apply.rs`, which either omits those
fields from the apply or forces only that resource. The diskpool case
is the same shape from the other side: a kind an operator installs
needs a readiness barrier on the CRD's `Established` condition, not on
the operator's Deployment.

**Recommendation:** This needs a design doc in `v2_discussions/` via
the `structured-thinking` skill. Doc 146 has the CRD half and should be
the starting point.

### 6. A workload and the Service that selects it cannot reference each other, and the escape is broken

**Entries:** 2026-09-18 raw-selector-unreachable-through-manifest-cycle;
2026-09-19 naming-a-service-from-its-workload-recurses,
from-workload-cannot-build-headless-service.

**What it costs us:** openebs hit the cycle four times, each one a bare
Nix infinite recursion with no hint. The documented escape,
`rawSelector`, recurses too when the cycle runs through the manifest,
so harbor and openebs both invented their own. valkey hand-writes its
headless Service because `fromWorkload` cannot set `clusterIP`, and eats
a `selectorCoherence` warning on every build for it.

**What would remove it:** The selector is a pure function of the
instance labels and the component name. Compute it before the manifest
is sealed and expose it as `rawSelector` from the start, rather than
adding it after `sealResource`, so any resource can read it without a
store edge. Detect the cycle shape at seal time and name both resources
in the error. `fromWorkload` merges `spec` deep so `spec.clusterIP =
"None"` adds to the spec rather than replacing it.

**Recommendation:** The `fromWorkload` deep merge is a one-line fix and
removes one entry. The `rawSelector` change touches
`kix/lib/scope/builders.nix` where `architecture.md` warns about
forcing order; read that section first.

### 7. What a package claims about the world, nothing checks

**Entries:** 2026-09-19 untrackedref-hid-a-secret-that-nothing-creates,
hand-copied-operator-rbac-drops-rules-silently,
namespaces-cannot-set-a-pod-security-level,
priorityclassname-is-not-checked.

**What it costs us:** Each one is a deploy that looks healthy and is
not: pods stuck in Init on a Secret nothing creates, an operator that
starts and does nothing because a namespace Role was never copied, a
workload the apiserver rejects at admission for a PriorityClass nothing
built.

**What would remove it:** Four separate small pieces. A
`priorityClassName` lookup in `kix/lib/eval/validate.nix`, which already
resolves ServiceAccounts and ConfigMaps by name and lists PriorityClass
as cluster-scoped; the `system-*` classes are builtins. A rule that
lists every `untrackedRef` in a build so the claims are in one place. A
vendored upstream RBAC manifest per operator package with a test that
diffs the rendered roles against it, which is the CRD vendoring model
(`scripts/vendor-crds.py`, the `crd-vendoring` skill) extended one
kind. A `meta.podSecurity` that namespace emission reads, which is a
feature and belongs in `ROADMAP.md`.

**Recommendation:** The PriorityClass check first; it is the smallest
and the failure it prevents is total.

### 8. The availability level's first sweep left the per-workload cases

**Entries:** 2026-09-19 availability-ceiling-is-instance-wide,
descheduler-ships-with-zero-replicas,
package-pdb-options-duplicate-the-derived-pdb.

**What it costs us:** openebs's etcd and NATS quorums run with soft
spread because one control-plane agent lowered the whole instance;
external-dns carries a `pdb` option that duplicates the derived PDB and
fires on single-node clusters.

**What would remove it:** A per-workload ceiling (an attribute on
`mkWorkload` that overrides `meta.availability.max` for that workload),
deletion of the `pdb` option in external-dns, and a decision on
descheduler: enable it with a mapped count and a deliberate policy, or
delete the package.

**Recommendation:** These are the follow-ups doc 145 left; one pass.

### 10. CRD lifecycle leftovers from doc 146

**Entries:** 2026-09-19 mkcrd-builders-take-the-first-listed-version,
deploy-has-no-crd-guards.

**What it costs us:** A CR built from a vendored CRD whose storage
version is not listed first targets the wrong version; the cdi package
hides this by filtering the version out. Prune deletes a CRD, and with
it every CR of that kind, like any other resource.

**What would remove it:** `mkCRD` picks the version with `storage =
true` and `mkCR` takes a `version` override (doc 146 §5.5). The
scheduler refuses to prune a CRD without an explicit flag and checks
`status.storedVersions` before a CRD apply that drops a version (doc
146 §5.6).

**Recommendation:** Both are already designed; they are implementation.

## A second pass, later on 2026-09-20

Two more entries closed, two opened, so the directory still stands at 23.

**The hand-written PodDisruptionBudgets are gone.** caddy, ingress-nginx
and valkey each wrote one over pods the availability plugin already
covers, and caddy's and ingress-nginx's `minAvailable = 1` blocked
eviction outright on a single-replica cluster, which is the opposite of
what a PDB is for. alertmanager keeps its own and the comment now says
why: its pods are rendered by the Prometheus Operator, so there is no
workload for the plugin to derive from.

`reliability.hasPDB` was retired rather than fixed. It could not be
fixed: a package rule is handed the package's own manifests, so it can
never see the PDB the compiler derived, and with the packages cleaned up
it would have fired on all of them. Its one real case — a workload that
sets its own `topologySpreadConstraints`, which switches the derivation
off, and then has no PDB over its pods — is now a warning from the
availability plugin, where the skip is decided. That the scorecard
cannot see derived resources at all is a new entry; it is a decision
about what the scorecard is for, not a patch.

**A package can be imported again when its Services come from its
workloads.** The import scope now offers `mkDeployment`,
`mkStatefulSet`, `mkDaemonSet`, `mkJob` and `mkCronJob`. They seal
nothing and emit nothing: an import's contract is the root's `out`, and
a workload only has to carry the selector and the container ports that
`kix.service.fromWorkload` reads. valkey's two hand-written Services are
converted, which is what the reverted conversion was after, and the two
`selectorCoherence` warnings it was eating are gone.

**One regression found and fixed.** cilium's cluster-wide DNS egress
policy, added earlier the same day, hung off nothing: it was a part no
dependency reached, and the build had been saying so. It is on root's
`extraRequires` now.

**Noticed and not fixed:** eighteen of the 64 packages are named by no
cluster, so no build evaluates them. caddy was one of the three packages
edited here and the only one nothing could confirm.

## A fourth pass, with a cluster to test against

Two bare-metal test clusters arrived (stage1 and stage2, RKE2 with cilium),
which unblocked the entry the third pass said needed one.

**`kix.expose` opens the controller's way in.** An Ingress routes; it
opens nothing. Cilium enforces at the pod, so under default deny the
backend refuses the ingress controller like any other pod in any other
namespace, and every request through the Ingress ends as a 504 that
evaluation cannot see. `kix.expose` is the one place that holds both
ends of that edge — the backing Service is right there and the
controller arrived as a dep — so it now emits one policy per backend,
opening that Service's pod port to the controller's pods and no other
port to no other caller. `ingress-nginx` publishes the two facts the
rule needs as `out.podSelector` and `out.podNamespace`. harbor's
hand-written intent, which opened its web port to every pod in the
cluster, is gone; the derived pair is scoped to the core and portal
components.

The obvious route was a new `ingress-controller` role in the registry,
and it is wrong: `findRoleProvider` refuses two providers of one role,
and two ingress controllers in a cluster is a shape the package already
supports and its own header advertises. The `ingressNginx` dep the
caller already holds names the right controller without that.

## A fifth pass: the design decisions, taken

The directory had stopped shrinking on its own. What remained was
mostly questions about what kix should do, and each of those had been
carried from pass to pass as "needs a decision". Adam took eleven of
them in one sitting; this pass is what came of it.

**Decided and shipped.**

- **Field ownership.** A resource says which fields an operator takes
  over: `ownership.cede = [ "spec.versions" ]`, also on `scope.mkCRD`.
  Deploy applies without those fields when a 409 is confined to them,
  and fails any other conflict as before. cdi ships upstream's full
  version list again; stackgres-operator cedes its webhook rules. Two
  entries closed. The word is Adam's: "cede" was kept over "ignore" and
  "skip", because the fields are set at creation and given up later.
- **The scorecard scores what ships.** Manifest and package rules see
  `allPartResources ++ processorResources`, so a derived
  PodDisruptionBudget or materialised policy is scored like an authored
  one. harbor's findings did not change.
- **The scorecard is on by default and red in this repository.** The
  shipped default is the full rule set capped at warning
  (`scorecard.maxSeverity`); both flakes raise the cap to error through
  `mkFlake { clusterModules }`. Turning it on found 78 workloads the
  rules had never seen. The fixes are in the commit message; what needs
  root or the host now says so in `meta.unsafe` with the reason, and
  three application packages hold `run-as-root` only because their
  images do, which is a new entry. All 74 builds are green under the
  strict cap, including the two `ludo-kind` variants that were red on
  `main`: they resize claims of features the kind baseline turns off.
- **A workload can carry its own availability ceiling**
  (`availability.max` on the builder call). openebs's etcd and NATS
  spread hard on the zone key again; its eight single-replica
  controllers stay at pod.
- **`global` is gone.** Nothing set it and it could not work.
- **`meta.podSecurity`.** The namespace carries the most permissive
  level any instance needs; a hand-set stricter level is an eval error
  naming the instance. kubevirt declares privileged.
- **The annotation-ownership rule follows dependencies of
  dependencies.** cert-manager declares its domain; the rule finds it
  through the cluster-issuer.
- **`kix.expose` with `paths` renders an HTTPRoute.** Gateway API is
  the direction; Ingress stays supported.
- **Runtime-installed CRDs are `scope.mkCRDRef` with `installedBy`.**
  The marker already existed; openebs's DiskPool now uses it.
- **An untracked reference can name its creator** (experimental):
  `kix.untrackedRef { kind; name; by; }` orders the referrer after the
  creator and makes deploy wait for the object. ingress-nginx's
  admission Secret is the first user. Marked experimental in the code,
  with the two fallbacks written next to it.
- **Hand-copied RBAC stays hand-written**, recorded on the roadmap with
  the pointer to doc 35's derived RBAC as the change that would remove
  the copy rather than check it.

**Also closed on the way:** the import wait looks for an object at the
scope discovery reports, so cluster-scoped imports are found; the
manifest filename comment gives the real reason for encoding colons (a
Nix store name cannot hold one).

Thirteen entries closed and one opened. Fourteen remain, and the shape
has changed: four are coverage and CI (the 18 unevaluated packages, the
red flake check, the web lint, the Linux capture wrapper), three are
environment or upstream facts (audit mode on stage1 and stage2, the vendored
port names, the literal openebs labels), three are the diff-side half
of the CRD guards, the storage-class catalogue and the self-selecting
Service, and the rest are documentation and the three root images.
Nothing left in the directory is a question about what kix should do.
