# Housekeeping review: 2026-11-23

Covers 518 entries written between 2026-09 and 2026-11. Each entry was
checked against main at `51964ff8` by reading the code it names. 46 were
already fixed and are deleted. 472 remain open. Of those, about 35 are
partly fixed and about 35 can only be settled on a live cluster, on the CI
runners, or against an upstream project.

The entries were checked by reading code. No cluster was built and no
test was run, so a "still holds" verdict means the code that causes the
problem is still there.

Most entries are small, and most fall into a few groups with one cause
each. The largest group is the library and the CLI each having several
copies of one decision: seven label-selector matchers, four cluster-name
checks, two parsers for one annotation, and two code paths that decide
what a deploy will change. The second pattern is messages that leave out
who they are about, because the helpers that raise them take a free-text
name. The third is that Kix has no model for three things that operators
and Kubernetes do every day: a field that cannot change in place, a
status that is stale right after an apply, and a pod that the package
does not render. Each missing model shows up as ten to twenty package
entries. About 150 entries need a decision from a maintainer before
anyone can fix them, and they are marked below.
