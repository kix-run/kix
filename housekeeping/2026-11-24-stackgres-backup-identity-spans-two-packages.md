# 2026-11-24 · `kix/packages/experimental/stackgres-object-storage` · A cloud role for StackGres backups cannot be given in one package.

StackGres runs wal-g inside the Patroni container of each cluster pod, so the role must sit on the ServiceAccount `<cluster>-patroni`, which the operator creates from the SGCluster's `spec.metadata.annotations.serviceAccount` (stackgres-cluster). The switch that tells wal-g to use that role (`s3.awsCredentials.useIAMRole`, `gcs.gcpCredentials.fetchCredentialsFromMetadataService`) sits on the SGObjectStorage (stackgres-object-storage), which several clusters can share. Neither placement of `kix.cloudIdentity.*` keeps the rule from doc 177 that one identity binds one ServiceAccount of one instance, so the package still sends users to `extraSpec`.

Decision required from the maintainer: where the identity value lives for operator-made ServiceAccounts that another package's resource switches on. See `v2_discussions/177_workload_cloud_identity.md` section 8.
