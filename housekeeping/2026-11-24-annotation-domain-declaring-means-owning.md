# 2026-11-24 · `kix/lib/eval/hooks.nix`, `kix/lib/rules/architecture.nix` · A package cannot declare that it reads an annotation domain without owning it.

A package that reads a shared annotation domain, such as `external-secrets` reading `eks.amazonaws.com/role-arn` on a store's `ServiceAccount`, cannot list that domain in `meta.annotationDomains`. Listing a domain in `meta.annotationDomains` claims exclusive ownership of it. That declaration overrides any cloud-flavor import for the domain, and evaluation fails if a second package lists the same domain. `architecture.annotationDomainOwnership` then warns on every other instance that uses the domain without depending on that package. When `external-secrets` listed `eks.amazonaws.com` on a `kix.flavors.eks` cluster, the rule warned on `external-dns/route53` ("does not declare a dependency on 'external-secrets/external-secrets'") because Kix wrote `eks.amazonaws.com/role-arn` on `route53`'s `ServiceAccount`. On clusters without a cloud flavor, cluster authors must add such domains to `scorecard.knownAnnotationDomains` instead.
