# 2026-11-24 · `kix/lib/eval/hooks.nix`, `kix/lib/rules/architecture.nix` · A package cannot declare that it reads an annotation domain without owning it.

Doc 180 (`v2_discussions/180_cloud_identity_across_packages.md`, section 7) asks external-secrets to list `eks.amazonaws.com`, `iam.gke.io`, and `azure.workload.identity` in `meta.annotationDomains`, so that a consumer's plain annotations on a store's own ServiceAccount pass the scorecard. But a package that lists a domain owns it: it takes precedence over the flavor's import, and `architecture.annotationDomainOwnership` then warns on every other instance that writes the domain without depending on it. With the list in place, `external-dns/route53` on the eks flavor warned "does not declare a dependency on 'external-secrets/external-secrets'" for the role ARN Kix itself rendered on its ServiceAccount. A second package that lists the same domain fails evaluation. Pull request #340 leaves the list out, and the package docs point at `scorecard.knownAnnotationDomains` on a cluster with no cloud flavor.

Decision required from the maintainer: whether `meta` gets a way to declare a domain a package reads but does not own, or doc 180 drops this step.
