# 2026-11-24 · `kix/lib/eval/hooks.nix`, `kix/lib/rules/architecture.nix` · A package cannot declare that it reads an annotation domain without owning it.

`meta.annotationDomains` has one meaning: the package owns the domain. A package that lists a domain overrides a flavor import for it, and `architecture.annotationDomainOwnership` then warns on every other instance that writes the domain without depending on that package. A second package that lists the same domain fails evaluation. So a client that only reads a shared domain, such as the External Secrets controller reading `eks.amazonaws.com/role-arn` on a store's ServiceAccount, has no way to say so. When external-secrets listed `eks.amazonaws.com`, `external-dns/route53` on `kix.flavors.eks` warned "does not declare a dependency on 'external-secrets/external-secrets'" about the role ARN that Kix itself rendered on its ServiceAccount. Today the cluster author lists such a domain in `scorecard.knownAnnotationDomains` on a cluster without a cloud flavor.
