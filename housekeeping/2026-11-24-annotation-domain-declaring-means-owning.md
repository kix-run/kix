# 2026-11-24 · `kix/lib/eval/hooks.nix`, `kix/lib/rules/architecture.nix` · A package cannot list an annotation domain in `meta.annotationDomains` without owning it.

When a package lists a domain in `meta.annotationDomains`, it overrides any cluster flavor import for that domain, and `architecture.annotationDomainOwnership` warns on every other instance that writes the domain without depending on that package. Evaluation also fails if a second package lists the same domain. Section 7 of `v2_discussions/180_cloud_identity_across_packages.md` asks `external-secrets` to list `eks.amazonaws.com`, `iam.gke.io`, and `azure.workload.identity` in `meta.annotationDomains` so that cloud annotations on a store's own ServiceAccount pass the scorecard. With those domains listed, `external-dns/route53` on `kix.flavors.eks` warned `does not declare a dependency on 'external-secrets/external-secrets'` for the role ARN that Kix rendered on `external-dns/route53`'s ServiceAccount. Pull request #340 leaves `meta.annotationDomains` unset, and the docs tell users on clusters without a cloud flavor to add the domain to `scorecard.knownAnnotationDomains`.

Decision required from the maintainer: should `meta` add a field for annotation domains that a package reads without owning, or should `v2_discussions/180_cloud_identity_across_packages.md` drop this step?
