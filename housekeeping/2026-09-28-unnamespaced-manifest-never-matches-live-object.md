# 2026-09-28 · `cli/kix/src/cluster/apply.rs` · A namespaced manifest without a namespace never matches its live object.

Kix applies such a manifest (for example `scope.mkClusterResource` with `kind = "ConfigMap"`) to `default`, so the live object's `ResourceId` has namespace `default` while the build's has `_cluster`. `kix diff` then shows it as added and the live one as dropped, and `detect_changes` keys on kind/namespace/name, so deploy's rebuild-from-live and the operator's live comparison plan the live object as an orphan of a build that still contains it. With `--prune` on a single Kix cluster that deletes the object right after the deploy applied it. Seen with the `sweep-test-shared` ConfigMap in `two_kix_clusters_share_one_kind_cluster` (`cli/kix-cli/tests/kind_integration_test.rs`); `fetch::api_for` already maps `_cluster` to `default` for requests.
