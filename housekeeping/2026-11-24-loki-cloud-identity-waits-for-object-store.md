# 2026-11-24 · `kix/packages/experimental/loki` · Loki cannot take a cloud identity until the package can use an object store.

The package keeps its chunks and index on one claim, and its header says "filesystem storage only (no object store)". A cloud role has nothing to authorize until the object store that `ROADMAP.md` lists as open ("an object-store implementation behind the same `loki` alias") exists. When it does, the package should take a credentials dependency that holds a cloud identity or a Secret. Upstream Loki's switches to check then: for S3, leave the access keys unset so the AWS SDK default credential chain is used; for GCS, Google's application default credentials are used when no service account key is given; for Azure Blob, set `use_federated_token: true` in the `azure` storage block.
