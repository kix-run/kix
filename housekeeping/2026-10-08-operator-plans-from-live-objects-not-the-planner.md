# 2026-10-08 · `cli/kix-operator/src/controller.rs` · The operator plans from the live objects, so it cannot share `kix::plan::Planner` with the CLI.

The CLI compares the new build with the builds the cluster's records name and folds in failed and kept closures. The operator compares the build with every live object of the cluster (`SweepScope::Cluster`) and calls `detect_changes_live`. That is deliberate: the live objects already include what failed and kept deploys left, and the same loop corrects drift. The two can still disagree. On a Kubernetes cluster shared with another Kix cluster, an object whose records gc has retired is unattributed, so the operator never prunes it, while a CLI deploy can prune it through `orphansKeptFrom`. kixpkgs#210 item 1 called the operator's plan a correctness risk; changing it means choosing one decision model for both, not swapping in `Planner`.
