# kix/lib architecture

Internals map for editing the compiler. The tree is organized by the ring model (v2_discussions/119): the deeper the ring, the higher the bar for changes. For *authoring packages*, read `guide/` instead.

## Layout by ring

```
core/     Ring 0 — the artifact. Sealant + context machinery, PI/Activation CRs.
eval/     Ring 1 — the pipeline. Module eval, DI, fixpoints, edge analysis, hooks.
scope/    Ring 1 — the authoring surface. Builders, validators, labels.
vocab/    Open vocabulary — pure helper libraries, importable without the core.
plugins/  Ring 2 — cross-cutting layers attached via hooks. First: netpol.
```

Root files: `default.nix` (entry + YAML emission), `modules.nix` (option schema + hook options + plugin imports), `mkFlake.nix`, `meta.nix`, `env.nix`, `scorecard.nix`, `rules/`, `flavors/`, `modules/`, `helm.nix` + `helm-dag.nix` (own track, untouched by the rewrite; `helm-dag.nix#inferEdges` adds an `instance-of` edge from a chart custom resource to the chart's own CRD of its group and kind).

## Pipeline

```
flake.nix → mkFlake.nix → buildCluster (eval/cluster.nix)
  1. evalModules (modules.nix, imports plugins/netpol/module.nix)
  2. computeAutoInstances (eval/auto.nix)      # explicit wins
  3. namespaces: real vs sentinel (`_`-prefixed)
  4. resolution index (eval/resolve.nix)       # DNS-like DI map
  5. phase-1 pre-pass                          # introspect, resolve dep targets, config injections
                                               # (`ref.<ns>.<inst>` is a static pointer built over
                                               # every name step 2 could produce, so explicit wiring
                                               # is visible to steps 2 and 5 and injections follow it)
  ── three fixpoints ──
  6. instanceConfigs fixpoint                  # config-only; breaks function-injection cycles
  7. clusterInstances fixpoint: evaluateInstance (eval/instance.nix)
       mkScope (scope/) → build entries folded with `mergeCollide` (a repeated part is an error; parts fixpoint + overlays)
       → sealWorkload: edges → dnsDeps → workloadInterceptors → podSpec merge + pre-seal requires splice
       → collect → closure diagnostics → instanceProcessors → PI CR → view
  8. clusterProcessors (default-deny, platform intents, scrape policies, enforcer assertions)
     → aggregate, Activation CR, package index, extraImages
  → mkManifests → YAML dir (default.nix)
```

## The hook contract

Plugins attach through three module options; the netpol plugin is the reference implementation and doc 115 (hardening) is the intended second consumer.

A hook is a function `ctx → result` or `{ priority ? 1000; fn; }`. Execution order is **(priority ascending, then name)** — never bare attr-name order; declare a priority instead of encoding order into names. Results are shape-checked per channel (unknown keys throw with the hook's full name, `eval/hooks.nix`).

- `hooks.workloadInterceptors.<name> :: ctx → { requires?, resources?, warnings?, podSpec? }` — runs inside `sealWorkload` **before** `builtins.toFile` seals the workload (the only point where a dep can be added; post-pass is impossible under content addressing). `requires` splice pre-seal (earlier-wave guarantee); `resources` ride the `_injectedResources` sideband, drained after the parts fixpoint; `podSpec` is merged into `spec.template.spec` per top-level field with the author's fields winning and, between hooks, the earlier (lower priority) hook winning, so the merge is deterministic and part of the sealed identity. ctx carries `workloadInput` (raw, context intact), `workloadKind`, `selector` (raw labels — never `out.selector` of the resource under construction), `hostNetwork`, `edges` (precomputed), registries, `instanceName`/`namespaceName`/`packageMeta`, `emit`, `cluster` (`{ config, findRoleProvider }`).
- `hooks.instanceProcessors.<name> :: ctx → { resources?, warnings? }` — post-parts-fixpoint per instance. ctx carries `emit`, `allPartResources`, names, `packageMeta`, `cluster`. (Fact behavior is read off resources — `r.factBehavior` — not from ctx.)
- `hooks.clusterProcessors.<name> :: ctx → { resources?, checks?, warnings? }` — cluster aggregation. ctx carries `cluster`, `nsResources` (Namespace resource per Kix namespace), `realNsNames`, and `resources` (the sealed resources of every active instance, including instance-hook output; the netpol scrape join reads it). `resources` become the Activation extraDeps AND the manifest-list tail in hook execution order (one canonical order; content-addressed, so priorities are part of the output contract). A **check** is any lazy value that throws its own error message on failure; all checks are seq-forced before the cluster result is returned (no assertion/message pairs — validators keep authorship of their messages).

**Hooks emit through `ctx.emit`, never a scope.** The facade (`scope/builders.nix`) is sealing capability only: `mkResource` (instance-labeled, validator-checked, own namespace), `mkClusterResource`, `inNamespace nsName → { mkResource }` (foreign-namespace parenting, e.g. caller-side ingress CNPs). If a plugin needs more, extend the facade deliberately (design doc first) — handing hooks the authoring scope would make every plugin a de-facto core change.

Fixpoint safety: a hook may read `workloadInput` and outer-fixpoint data (DI deps, cluster config); it must not force the resource under construction, and returned resources must not close a cycle into the current parts fixpoint.

What stays core regardless of plugins: edge analysis + DNS dep injection (unconditional — workloads referencing cross-instance Services wait on the DNS provider's root resource, or on its marker when DNS is an import, even with netpol disabled), the pre-seal splice, the sideband drain, `findRoleProvider` + the role registry, `forNamespace` parenting. Also core: the `scope.networkPolicyEnforcer` **handle contract** — null unless `networkPolicy.enable` is on, an enforcer is declared, and the instance is not the enforcer itself. Packages (stackgres-cluster) branch on this handle; the enable-gate is load-bearing (`eval/instance.nix`).

## Non-obvious patterns

- **Store-path = DAG edge.** Resources never declare deps explicitly; `mkResource` reads Nix string context off the manifest JSON and stamps `kix.run/depends-on`. Manifests keep real names; context rides alongside. The CLI walks the store DAG rooted at the Activation CR. → `core/resource.nix`.
- **Two context channels: identity and facts.** Identity paths are the derivation record ("computed from X") — maximal, never filtered, drives ordering. Fact tokens are typed claims ("dialing this value's target reaches selector S on ports P") — minted on address-shaped `out` fields (`fqdn`/`url`/user outputs; `name` is structural, and a user output wrapped in `facts.structural` is too), conducted through non-workload seals (ConfigMap indirection works by default), terminated at workloads where interpreters project them (netpol edges, DNS deps). Facts are dependency-free pure payload (stable across producer churn, write-once tokens) and are stripped pre-`toFile` (never in the store DAG or `depends-on`). Naming-without-dialing triggers a lint; `facts.refOnly` acknowledges deliberate structural use. → `core/facts.nix`, `eval/edges.nix`.
- **The terminate/conduct table has three row sources.** Core K8s kinds are hardcoded (`facts.terminatorKinds` — spec facts, universal). CRD kinds are declared **on the CRD itself**: the `factBehavior` arg of `scope.mkCRD`/`scope.mkCRDRef` (`{ endpoint = "terminate"|"conduct"; podSelector = cr: {...}; }`, validated at the declaration site) threads through `mkCRDBuilders` into every CR built via `scope.mkCR` — behavior is a property of the kind, delivered along the same chain as the kind name and the CRD-before-CR edge, so ownership holds by construction, kinds can't collide across groups, and no registry or phase-1 index exists. Cluster operators override per-kind via `cluster.factBehavior` keyed `"group/Kind"` (wins over the CRD declaration; also the only channel for builder-less CRs — helm-rendered, raw kind strings). Terminate-by-CR means the *operand* pods dial: the netpol instance processor reads `r.factBehavior`/`r.absorbedEndpointFacts` straight off the resource and opens egress for `podSelector cr` plus caller-ingress into each target's namespace (these policies do not require the CR, because a CR's readiness can need the connection they open: a Velero BackupStorageLocation is Available only once its store answers); the CR also gets a DNS-root `requires` spliced at seal. An **undeclared foreign kind** (dotted non-`.k8s.io` group) absorbing endpoint facts warns three-valued style: conduct is assumed, the message names both fix channels. The same chain carries **readiness declarations**: `readiness = { path = "/status/..."; equals = "..."; }` or `readiness = { condition = { type = "..."; status = "True"; }; }` on `mkCRD`/`mkCRDRef` (validated in `mkCRDBuilders`) is stamped on every typed-chain CR as the `kix.run/readiness` annotation, which the CLI's `check_readiness` evaluates before any kind-based rule — controller health vocabulary stays in the owning package, not in a Rust match arm.
- **Sealing is one-way.** After `toFile`, a resource's identity is fixed; every consumer reference carries it as context. Anything that must influence a workload's dep list goes through the pre-seal pipeline, never a rewrite pass.
- **Three fixpoints, not one.** Phase-1 pre-pass (introspection), config-only fixpoint (lets function-shaped dep injections read consumer config without cycling), full instance fixpoint. → `eval/cluster.nix`.
- **DNS-like DI.** Explicit override → managed-over-import filter → unique same-ns → unique other-ns → arg default → throw; ambiguity always throws; aliases participate. `mkLocked` freezes config keys against injections. → `eval/resolve.nix`.
- **Self-enforcer skip is identity-based.** The netpol plugin nulls the enforcer for the enforcer's own instance by exact provider-instance match (ns + name), not by `meta.roles` membership — the peeked-index semantics v1 had.
- **Roles are the linker symbols.** `meta.roles` (registry-validated, one line per package) drives the provider index, DI aliasing, and binding-mode conflicts. `meta.provides` is deleted. Substrate capability options are three-valued: false = gate error, null = warning naming the axiom, true = pass.
- **Object names are checked during evaluation.** The Kubernetes OpenAPI schema leaves `metadata.name` unconstrained, so kubeconform accepts names that the API server rejects. `scope/validators.nix#checkResourceName` runs when `scopeMkResource` seals a resource. It requires an RFC 1035 label for a Service, a DNS-1123 label for a Namespace, and a DNS-1123 subdomain for other resources. RBAC resources are exempt because Kubernetes validates their names as path segments. Packages usually derive names from `scope.instanceName`; preserve camel-case DI names with `meta.defaultAliases` and use a lowercase instance name. See `scope/validators.nix` and `scope/builders.nix`.
- **Capability ownership is two declared invariants, not fingerprints** (v2_discussions/128; the capabilityOwnership rule and all `kix.run/capability` stamps are gone). Raw PVCs are an eval-time error in `scope/validators.nix#checkRawPvc`, escaped only by `meta.unsafe = [ "raw-pvc" ]` — a closed vocabulary (`unsafe.nix`) validated at scope construction and listed by the scorecard's `unsafeGrants` audit; helm-imported PVCs route through the wrapper's mkResource, so chart packages with persistence hold the same grant. Four further grants (`host-network`, `privileged`, `run-as-root`, `cluster-admin`) switch off `security.noHostNetwork`, `security.noPrivileged`, `security.nonRoot`, and `security.noClusterAdmin` for the declaring package: manifest-level rules receive `meta` in their context (`scorecard.nix#evaluateManifestRules`) and drop out via `appliesTo`. They exist because a CNI cannot pass those rules and the alternative was a per-namespace severity override, which exempts every other package in that namespace too. `kix/packages/cilium` holds the first three; `kix/packages/velero` holds `cluster-admin`. Operator packages declare `meta.annotationDomains` (open vocabulary; duplicate declarer = eager eval error, `eval/hooks.nix#buildAnnotationDomainIndex`); the `architecture.annotationDomainOwnership` package rule warns when a resource's `metadata.annotations` keys fall under a domain with no declarer anywhere (dead annotation — forgot the operator) or a declarer the instance has no DI dep on. Reserved suffixes (kubernetes.io, k8s.io, kix.run, helm.sh, kubebuilder.io) and `scorecard.knownAnnotationDomains` are exempt.
- **Secrets carry provenance.** `mkSecret` realizes `source` (SOPS) as its own store path and stamps `kix.run/{secret-keys,sops-source,content-hash,...}`; `mkSecretRef`/`mkServiceRef` emit PI import markers polled at deploy time; `reflect = true` sets `_kix.reflected`. → `scope/builders.nix`.
- **Ceded fields** (2026-09-20): `core/resource.nix#mkResource` takes `ownership.cede`, validates it and stamps `kix.run/cede-fields`; `scope/builders.nix#mkCRD` forwards it. The CLI side is `cluster/apply.rs#without_ceded_conflicts`. The lib never reads the annotation back.
- **The scorecard is on by default, capped at warning** (2026-09-20): `modules.nix` defaults `scorecard.enable = true`, `scorecard.rules = kix.rules` and `scorecard.maxSeverity = "warning"`; `scorecard.nix#capSeverity` lowers every resolved severity to the cap, so a user's cluster prints every finding and fails on none until it raises the cap. `mkFlake { clusterModules }` prepends modules to every cluster of a flake by wrapping `kix.buildCluster`; the root `flake.nix`, `clusters/flake.nix` and `ludo/flake.nix` use it to set the cap to error, which is what makes an error-severity finding red in this repository.
- **Scorecard rules score the shipped set** (2026-09-20): `eval/instance.nix` hands manifest and package rules `allPartResources ++ processorResources`, so a PodDisruptionBudget the availability plugin derived or a network policy the netpol plugin materialised is scored like an authored manifest; namespace and cluster rules already read `_hookResources`. Before this a rule about a derived resource was unwritable (`reliability.hasPDB` was retired for it).
- **Cluster- and namespace-level scorecard findings gate builds** (2026-08-31): `eval/cluster.nix` routes them through `scorecard.scorecardToWarnings` into `collectClusterDiagnostics` (`extraWarnings`/`extraAssertions` + `emitExtraWarnings`), so error-severity cross-resource rules (e.g. `architecture.monitorSelectorMatchesService`, the first `level = "cluster"` rule) fail the build like instance assertions instead of landing silently in the lazily-built `kix-scorecard.json`.
- **`out` is the public surface**; `rawSelector` and `kix.untrackedRef` are the deliberate context escape hatches. `rawSelector` is policed by `architecture.selectorCoherence`. `kix.untrackedRef` is the declaration that a name is external. The `architecture.untrackedReferences` audit (info) lists every external name that is not `creatorNamed`, and the cross-resource checks (`eval/validate.nix`) accept it because `buildCluster` collects those names, keyed by namespace, before string context is stripped.
- **Helm is lossy on purpose** and its workloads route through `scope.mkHelmWorkload`, so chart workloads get the same interceptor treatment as native ones. → `helm.nix` (own track).
- **A value that varies per deploy is committed, not injected.** Kix has no `--set` and no deploy-time value channel, and one would not work if it existed: change detection seals the previous build's identity hashes before the CLI could patch anything, so a post-eval value never reaches the comparison and the second deploy is a silent no-op. Values decided outside the compilation unit go into a pin file next to the cluster (`kix.pins`, read as JSON) and are written there by `kix pin`. JSON rather than Nix is load-bearing rather than stylistic: reading a Nix file means evaluating it, so a Nix pin file would execute whatever it held every time Kix read it, and writing one would mean hand-escaping registry-supplied strings into a programming language. The eval cache fingerprints `.json` alongside `.nix`, `.yaml` and `.yml`, so the choice costs nothing. The tag names a stream (`main`) rather than a build (`sha-<commit>`), so the digest is the only value that moves and CI never edits the cluster definition. `kix.image.ref` renders `repository:tag@digest`, and `security.noUnresolvedPlaceholder` is a ratchet against the sentinel that started this (`v2_discussions/archive/138`). The path to that file is named once, as `mkFlake { pins = ./pins.json; }`, and passed to any cluster that takes a `pins` argument, the same way `kix` and `packages` are. It cannot be handed to the CLI the same way: a path literal inside a flake evaluates to a store path, so `kix pin` finds the file by convention instead of reading a declaration, which is what keeps it working when evaluation does not. → `vocab/compose.nix`, `rules/security.nix`, `mkFlake.nix`, `cli/kix-cli/src/commands/pin/locate.rs`.
- **A resource living only at `parts.root` is dropped from the manifest set.** `collectResources` excludes the `root` key; every production package aliases root to a named part (`root = self.service`), which is why this never bites. A root-only resource also never gets its `_injectedResources` sideband drained. Latent footgun — worth a diagnostic eventually.

## When editing lib/

- `core/` changes touch the CLI contract (Activation closure, depends-on format, PI fields) — coordinate with `cli/`.
- `core/annotations.nix` and `cli/kix/src/manifest/keys.rs` are two halves of one constant. Change either and you change what is stamped on every resource on every cluster, so they move together and a move needs the compatibility layer in `cli/kix/src/legacy_domain/` (v2_discussions/137).
- Authoring-surface changes (scope builders, vocab, DI semantics) → update `guide/` and the `kix-migration` skill.
- A new cross-cutting concern should be a plugin registering hooks, not new calls inside `eval/`/`scope/`. If the three hook channels don't fit (see the import-marker gap in `eval/import.nix`), extend the contract deliberately — in a design doc first.
- Refactors must keep the manifest store path identical on `nix build ludo/#cluster-ludo-kind`; intentional output changes ship separately.
- If a change invalidates a pattern above, update this file.
