- [ ] Default metadata scoping — which resources should global metadata apply to? Not higher-order resources like Deployments/Services, but what about CRDs?
- [ ] **Cluster-level instances**: first-class home for instances whose resources are cluster-scoped (StorageClass, VolumeSnapshotClass, CSIDriver, ClusterRole-only bundles, etc.). Today `instances` is keyed by namespace, so flavors/clusters that need to group cluster-scoped resources resort to a sentinel key (`instances._cluster = { … }`) to land them under `$out/_cluster/` in the build output. `kix/lib/eval/cluster.nix` now filters underscore-prefixed namespace keys out of the `Namespace`/`ResourceQuota`/per-ns NetworkPolicy/default-deny CNP emission paths to make the sentinel pattern work; that is the hotfix shape, not the design. A proper API would let an instance declare it has no namespace (e.g. `instances.<name> = { scope = "cluster"; package = …; }` or a sibling `clusterInstances` attrset), drop the sentinel filter, and let scope-checking, scorecard rules, and DI resolution treat namespace-less instances as a first-class case rather than a string-prefix exception. The PackageInstance record of a sentinel instance goes to `cluster.recordNamespace` (default `kube-system`), since Kubernetes refuses a namespace named `_cluster`; a first-class design would keep that setting.

### Open design questions
- [ ] **One output system for every command** (2026-11-13). Some commands print only text, so a script cannot get JSON from every command, and each command decides for itself how it prints. A shared output layer could make every command give a typed response that renders as text, JSON, and YAML, and the Rust type system could refuse a command that does not. The starting point is the `FORMATS` table in `cli/kix-cli/src/dispatch.rs`, which lists the formats of each command, and the `CommandResponse` trait in `cli/kix-cli/src/output.rs`, which the commands that print data already implement.
- [ ] **Stability levels, what docs 165 and 166 left open** (`v2_discussions/archive/165_package_and_contract_levels.md`, `archive/166_contracts_as_first_class.md`, 2026-11-11).
  - Which experimental packages graduate as Lithus moves its clusters onto Kix packages. Graduation is a folder move, in any release.
  - Remove the `[K0549]` refusals for the names that moved to experimental (`kix/packages/was-stable.nix`, the lists in `kix/contracts/default.nix` and `kix/modules/default.nix`, the marker checks in `kix/lib/eval/auto.nix`, `kix/lib/meta.nix`, and `kix/lib/modules.nix`) in 0.11.
  - Whether `scripts/change-kind.py` should build clusters that use experimental packages, and what it demands when one fails.
  - Narrowing what a reader receives to the fields of the contract it takes, so a stable package cannot read the extra fields an experimental provider publishes.
  - Whether experimental packages and each contract get docs pages.
- [ ] **Versioning, what doc 164 left open** (`v2_discussions/archive/164_versioning_at_agent_speed.md` § 4, 2026-11-11).
  - Signing-key rotation breaks stepping: `kix upgrade` cannot verify an older release once its key is dropped. Keep every past public key, or sign the index of past releases with the current key.
  - How long a refusal for a removed option or flag lives. One minor is the floor, and `kix upgrade` relies on it.
  - Versioned docs: the site serves one version, so a user on an older Kix copies newer examples.
  - Whether `kix check` should print evaluation failures as JSON.
  - Whether six months is the right window for reading old cluster state.
  - Whether an older Kix should be refused on a cluster a newer minor deployed (doc 163 § 9, never built). Left out for now: with no way to withdraw a release, deploying with the previous Kix is how a user leaves a bad release. If built, it needs an explicit override.
  - `kix deploy --operator` does not check required stops, and a cluster with no deploy receipt passes the check.
  - [x] **Several versions of Kix in one project** (2026-11-21, `v2_discussions/173a_kix_versions_in_one_flake.md`). Each version is an input of `flake.nix` (`kix`, and others such as `kix-stable`), and `[versions]` in `kix.toml` lists the clusters under each. Kix finds the cluster in a command from the clap definition, runs the Kix its input pins, and evaluates with `kix` replaced by that input. `kix upgrade <input>` and `kix upgrade <cluster> --to <input>` move one input or one cluster. Open: a version of Kix released before this cannot be one of several, because it refuses the `[versions]` key; two versions that render one shared object differently (below) matter more once clusters on one Kubernetes cluster run different versions.
  - Left for later by doc 164 § 3: a security-only backport line, declared Kix version ranges for outside package sets, withdrawing a release, and an upgrade bot that opens a pull request for each release.
- [x] **A resource can cede fields to a controller** (2026-09-20, shipped 2026-09-20). Field ownership was all-or-nothing: an operator that rewrote a CRD Kix shipped (cdi drops a deprecated version from `.spec.versions`) or a webhook Kix applied (StackGres takes over `.webhooks[].rules`) made every later deploy a 409, and `--force-conflicts` took every field of every resource back. `ownership.cede = [ "spec.versions" ]` on the resource (also on `scope.mkCRD`) is stamped as `kix.run/cede-fields`; `apply.rs` retries a conflict confined to ceded paths without those fields, so the operator keeps them, and fails any other conflict as before. cdi ships upstream's full version list again and cedes `spec.versions`; stackgres-operator cedes `webhooks[*].rules`. The third entry in the group, Mayastor's runtime-installed DiskPool CRD, is a `scope.mkCRDRef` with `installedBy` (the marker deploy already waits on), not an ownership question.
- [x] **A workload can carry its own availability ceiling** (2026-09-20, shipped 2026-09-20). `meta.availability.max` capped a whole instance, so openebs's `max = "pod"` for three single-replica controllers also lowered etcd and NATS from `DoNotSchedule` to `ScheduleAnyway` on the zone key. `availability.max` on the builder call (`scope.mkDeployment { availability.max = "pod"; ... }`) seals that one workload at the lower level, warns once naming it, and stamps `_availability` on the sealed resource so the availability processors judge it there; the package's `availability` argument and every other workload keep the requested level. openebs dropped its instance ceiling for seven per-workload ones. Test a21.
- [x] **A `none` ceiling is one pod** (2026-10-01). `none` as a ceiling means a workload runs one pod at a time; `pod` keeps "survives a pod crash or rolling update". The availability plugin refuses a Deployment or StatefulSet above one replica under an effective ceiling of `none` (builder `availability.max` or `meta.availability.max`, the lower of the two), after overlays and for chart workloads too. Ceilings are validated where written (`checkCeiling`, builder `availability` keys, refused on DaemonSets), and a builder ceiling is recorded on the sealed workload even when it does not cap. `every-package-evaluates` runs each package at `none` and `zone`. Placement rule: package ceiling for program limits, builder ceiling for anything that depends on config or wiring. Tests `lib-availability-ceiling-*`. Under a package ceiling, `kix.availability.atLeast` refuses a threshold above it (`underCeiling`, 2026-10-02); `meta.availability` takes only `max`. grafana moved its limit to a builder ceiling; kube-state-metrics and prometheus-operator are `none` with one replica, and their `replicas` options and `monitoring.grafana.replicas` are gone.
- [x] **`architecture.clusterDomainLiteral` and the package-eval source scan** (2026-10-01): a rendered `cluster.local` fails a build on another domain; package-eval builds every package with `clusterDomain = "eval.kix.test"`.
- [x] **Version grammar** (2026-10-01): `kix/lib/core/version.nix`; `v` prefixes and vendor build tags parse; constraints compare at their own precision and unknown versions warn. `compatibleWith` now reads a managed dependency's `meta.version`. Since 2026-11-13 the PackageInstance record and `compatibleWith` share one rule (`meta.instanceVersion`): the instance's `version` option, then the package's `out.version`, then `meta.version`. Packages read `out.version` from the image tag with `kix.image.version` (`versions.ofTag`), so an instance with another image reports what it runs, and package-eval's `checkPublishedVersion` requires it of every package whose default tag names its `meta.version`. `kix list` still reads `meta.version`, because it does not build instances.
- [x] **`autoRoot` refuses to guess** (2026-10-01): a chart's root is the only Service, else the only workload; otherwise evaluation fails and `kix.helmChart { root }` names it.
- [x] **`kix.expose` with `paths` renders an HTTPRoute** (2026-09-18, shipped 2026-09-20). Multi-backend routing only rendered an Ingress, so harbor could not be exposed on a cluster that routes through a Gateway. `httpRoute.fromPaths` renders one HTTPRoute with a rule per path, each to its own backend, translating the Ingress `pathType` words. Ingress stays supported, but Gateway API is the direction every cluster is moving in and routing features are built for it first. Test t96. The network-policy edge from the Gateway's data plane is still open.
- [x] **A package asks for the Pod Security level its pods need** (2026-09-19, shipped 2026-09-20). `meta.podSecurity` on the package; the namespace carries `pod-security.kubernetes.io/enforce` at the most permissive level any of its instances needs, `namespaces.<ns>.podSecurity` sets it by hand, and a hand-set level stricter than an instance needs is an eval error naming the instance. kubevirt declares `privileged`, as upstream labels its namespace. Test t92.
- [x] **The `global` option is gone** (2026-09-19, removed 2026-09-20). Every key of `global` was fed into every package's option evaluation, so a key one package did not declare failed the whole build, and no cluster in the tree set it. Cluster-wide decisions already reach packages through typed channels: the availability level, network policy, the DI arguments. A future broadcast need gets its own typed channel rather than an untyped bag.
- [x] **Operator RBAC is vendored** (2026-09-19, shipped 2026-10-02). The `cdi` package had copied an upstream ClusterRole rule for rule and left out the namespace `Role` and its `RoleBinding`; the operator started, reported ready, and did nothing. kubevirt and cdi now keep upstream's operator roles under `<pkg>/rbac/*.json`, vendored from the release bundle by `scripts/vendor-crds.py` (`rbac/sources.txt`, `Kind/name` selectors) and checked in CI with the CRDs. The packages bind them through `scope.rbac` role sets. Deriving RBAC from declared CRDs (`v2_discussions/35_crd_derived_rbac_webhooks.md`) stays open.
- [x] **`kix.expose` opens the ingress controller's path to the backend** (2026-09-18, hit twice; shipped 2026-09-20). `ingress-nginx` publishes `out.podSelector` and `out.podNamespace`, and `kix.expose` emits one policy per backing Service opening that Service's pod port to the controller's pods. harbor's hand-written all-pods intent is gone. It went through the role registry first and came back out: `findRoleProvider` refuses two providers of a role, and two ingress controllers in one cluster is a shape this package already supports, so the edge is written from the `ingressNginx` dep the caller already holds. Verified on stage2 with cilium audit mode turned off for the backend endpoint: 200 through the Ingress, 504 with the derived policy deleted, 200 again when it is put back. Gateway API is not covered — see the note in HANDBOOK §16.5.

- [x] **Commands see one Kix cluster's objects** (2026-09-28, `v2_discussions/archive/150_scope_managed_sweep_to_one_cluster.md`). `inventory::sweep_managed` takes a `SweepScope` (`Cluster`, `Records`, `All`) and attributes each object through the Activation record hashes in its `kix.run/activations`, split by the records' `kix.run/cluster` label (`tenancy::Tenancy`, `inventory::attribute`). `kix diff`, `status`, `health`, `snapshot save`, `gc --hard` and the operator's reconcile read only the named cluster's objects and print how many they skipped per other cluster; `kix deploy`'s rebuild-from-live reads only the Active, Failed and kept-orphan records' closures; `kix drift` takes `--cluster` and otherwise names each object's clusters. With one Kix cluster the output is unchanged. When another cluster has records, an object naming no record is "unattributed": left out of read views and judged by `gc --hard` only with `--include-unattributed`. An orphan that another Kix cluster's current build still contains is kept by deploy, rollback, soft and hard gc, the operator's reconcile and its finalizer: plans list it as kept (`inventory::split_shared_orphans`), and every prune deletes through `prune_guard::PruneGuard`, which reads the object, then the records, and deletes with the read's uid and resourceVersion as preconditions. Every sweep lists the records after the objects, so a Kix cluster whose first deploy lands mid-sweep is never mistaken for this one. Breaking: `kix snapshot save <CLUSTER> <DIR>`. ### Break glass — emergency escape hatches
- [ ] Strip dependency context — remove a resource from the DAG without deleting it (e.g. `builtins.unsafeDiscardStringContext` on a specific dep reference) to unlink a broken dependency and allow the rest of the graph to deploy
- [ ] Force-override a single resource — bypass the content-addressed pipeline for one resource (pin its manifest directly) when the DSL can't express what you need right now
- [ ] Skip a package from the cluster build — `exclude = [ "package-name" ];` at the cluster level to drop a package entirely without editing its definition
- [ ] Partial deploy — deploy a subset of the graph (e.g. only one wave or one namespace) when a broken package blocks the full rollout
- [ ] Escape-hatch annotations — mark resources with `kix.run/unmanaged: "true"` so kix-diff ignores them, allowing manual hotfixes to coexist temporarily
- [ ] Audit trail for escape hatches — any break-glass action should be visible in the build output / diff summary so it doesn't silently become permanent

## Open design questions (still-to-get-right)

- [ ] **One source for package ownership when the build is absent** (2026-11-05). gc, health, and migrate should read which package owns an object from the record's `status.packageIndex`, as `kix diff` and `kix plan` now do, so the per-object `kix.run/package` stamp stops being a decision input. Release 0.6 carries build facts in two places, per-object annotations (#293) and the record (#294); a later release should pick one.
- [ ] **`kix plan`, what doc 157 left open** (from `v2_discussions/archive/157_kix_plan_primary_preview.md`) (2026-10-03). (1) Saved plans: answered in #185 (see the saved-plans item above). A `resourceVersion` precondition on applies that revert drift, and deploying a reviewed store path from a binary cache, wait for the in-cluster doc. (2) Cost on large clusters: unchanged objects already skip the dry run, as the engine skips them; is one request per changed object acceptable on every `kix deploy`, or should `--yes` in CI be able to skip it? (3) The deployed build for three-way labels when its store path is gone and the live reconstruction is itself drifted: today nothing is labelled; a fetch from a binary cache would label it. (4) Running plans inside the cluster so callers never hold credentials needs its own doc (how a build reaches the cluster, who may request a plan, how results return). (5) A plan's `drift` covers the objects the deploy applies; drift on the objects it skips is in `kix diff` and `kix drift`, not in the plan.
- [ ] **Contested shelf names, what the refusal left open** (from `v2_discussions/archive/151_ambiguous_alias_providers.md` §4, 2026-09-28; the refusal shipped in kixpkgs#156). (2) `kube-prometheus-stack` answers `prometheusOperator` without `mkAlertmanager` and `mkPrometheus`, so an explicit kps instance next to a native alertmanager still fails on a missing attribute: drop the alias, add the builders, or wait for doc 120's `out` typing. (3) `effectiveAliases` replaces `defaultAliases` with instance aliases, while `peekPackageAliases` adds shelf-entry aliases to them; making the shelf replace too would allow `availablePackages.<n>.aliases = [ ]` as a third way to choose. (4) Sugar for choosing a provider (doc 151 option B): no until choosing becomes repetitive across real clusters.
- [ ] **Two Kix clusters that render one shared object differently** (2026-09-28, from kixpkgs#161, `v2_discussions/archive/150_scope_managed_sweep_to_one_cluster.md`). When the two builds render it differently, each deploy overwrites the other's version and nothing warns. The workload builders could stamp one from the content hashes (`out.contentHash`) of the Kix-built ConfigMaps and Secrets the pod spec references, which string context already tracks. - [ ] **The resolver never binds an instance to itself** (from the mayastor rework, 2026-10). A dependency named like one of the instance's own aliases (`storageClasses` on an instance aliased `storageClasses`) resolves to the instance itself unless wired explicitly.

Mayastor's ingress to etcd, api-rest, and agent-core (all three unauthenticated) is open to all pods because its host-network peers arrive as the host or a remote node; a narrower source would admit only them.

## Key risks & design principles

- **Nix adoption barrier** — nix has clear advantages but hasn't taken over the world; we need to actively study *why* people who know about nix's benefits still choose not to use it — not just build features. The intro tutorial and DX must be approachable for a non-nix user. Positioning: nix scales; helm and friends do not.
- **Adoption is the #1 killer of platforms** — not features. The experience for a non-infra developer must be so easy a novice could use it. Datadog vs Prometheus is the cautionary tale (user acquisition beats technical correctness).
- **"Not simple, but intuitive"** — the goal isn't to reduce the interface, but to distill inherent complexity into intuitive form. If the tool is "too smart", the user has to think about the tool rather than their work (mental overhead as a design constraint).
- **Eval times** — content-addressing could lead to long eval times; unclear if path caching helps.
- **Abstraction balance** — narrow interface ≠ less cognitive load; making things simpler than they are creates a dangerous illusion. Don't abstract away physical properties (cost, latency, SLA) — they're leaky abstractions people care about.
- **"Composability and cohesion over capability and completeness"** — the platform will grow by itself, but composability and cohesion must be actively protected.
- **Show value in weeks** — don't over-engineer. Find immediate MVPs and GTM opportunities. The demo must be compelling quickly, not after all features are built.
- **IaC as readable, long-lived intent** — "express ideas in a language you can re-read a year ago". This is a core reason to use nix over YAML/templating: the configuration is human-readable code, not opaque generated output.
