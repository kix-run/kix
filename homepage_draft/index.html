Whole-cluster automation follows from the artifact model.

Because Kix evaluates the cluster as one artifact, it can derive work teams usually maintain by hand: network policy, RBAC, monitoring wiring, ingress, ordering, repeated platform rules, and environment-specific variation.

Prevention first

Move failures out of production.

Kix does not merely scan what is already running. It prevents non-compliant or inconsistent changes from being included in the artifact you deploy.

Typical Kubernetes stack

  • -Helm, Kustomize, Argo, and Flux remain useful tools for packaging and delivery.
  • -They usually operate on rendered pieces of the cluster, not one shared cluster model.
  • -Policy and scanning often happen after the configuration has already been produced.
  • -Catalogs, runbooks, and diagrams can drift from the real deployed system.

Kix

  • +Evaluates the whole cluster definition before deployment.
  • +Emits standard Kubernetes resources into existing delivery flows.
  • +Catches wiring and policy failures in local checks, pre-commit, or CI.
  • +Derives dependency, ownership, diff, and evidence from the artifact.
Workflow

Change Kubernetes with a compiler loop.

The important shift is not that Kubernetes resources disappear. The shift is that every change goes through the same evaluate, inspect, and apply loop before it can affect production.

1

Define the change

Use package relationships instead of copying names, selectors, ports, and policy fragments between files. 

# Add Acme Co.'s internal app with platform-provided Postgres.
{
  kix.instances = {
    postgres = {
      package = pkgs.cloudnative-pg-cluster;
      namespace = "data";
    };

    acmeApp = {
      package = acmePackages.internalApp;
      namespace = "acme-prod";
      config.expose.host = "acme.internal.example.com";
      deps.database = ref "postgres";
    };
  };
}
2

Evaluate locally or in CI

Kix resolves dependencies, runs schema and scorecard checks, and emits diagnostics while the change is still in review. 

$ kix check prod-eu --sarif > scorecard.sarif

OK selectors, RBAC, routes, scorecard
WARN apps/api: backup window overlaps maintenance freeze
3

Review the artifact

Inspect what will change, what depends on it, and which evidence was produced before the deploy step is allowed to run. 

$ kix diff prod-eu --output markdown
$ kix graph prod-eu --format tree
$ kix compliance audit prod-eu --out ./evidence
4

Deploy or hand off

Apply in dependency order with Kix, or export standard Kubernetes resources for your existing delivery process. 

$ kix deploy prod-eu --dry-run
$ kix deploy prod-eu
$ kix export prod-eu --out ./manifests
5

Operate the result

The same artifact model supports drift checks, image inventory, rollback history, and recovery after a bad change. 

$ kix health prod-eu
$ kix images prod-eu --sources
$ kix rollback prod-eu --list
Adoption
